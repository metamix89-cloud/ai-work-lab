- **A 의 1/9 는 대부분 계약(경로) 탓이다.** 셋 다 `/api/cart/{id}`(단수)에 장바구니 ID 를 화면이 만들었다(발급 API 없음). 그래서 규칙을 점수로는 못 잰다 — **코드를 읽어** 규칙을 비교했다.
- **A 셋 다 할인을 옵션 추가금에도 걸었다** (A1 `sale_price(price + extra, pct)`, A2 · A3 `round((price + extra) * (100 - rate) / 100 / 10) * 10`). PRD R3 은 "할인가 + 추가금, 할인은 추가금에 적용하지 않는다". 고추장 1kg(정가 9,000 · 할인가 7,500 · 추가금 6,000)이면 PRD 13,500원, 할인율 17% 를 합에 걸면 12,450원 — **한 줄에 1,050원**. 어느 쪽이 옳다가 아니라 **정해야 하는 것**이다.
- **A 셋 다 '상품 단위 한도' 와 '1회 한도' 가 없다.** 재고를 옵션마다 따로 세고(같은 상품 다른 옵션을 합치지 않음), 상한은 코드 상수 99 · 20 · 10. PRD R4 는 `min(stock, max_per_order)`, 상품 단위로 합친다.
- **배송비 경계는 A 셋 다 맞았다** — 셋 다 '이상' 이면 무료, 빈 장바구니는 0. 기준 금액은 3만 · 5만 · 3만(A2 는 5만). 경계 감각은 있다, 금액은 회사가 정할 것.
- A2 · A3 은 "담아 둔 뒤 품절된 줄은 경고하고 합계에서 뺀다" 를 스스로 정했다(PRD 에 없음 — 이 PRD 는 서버 시작마다 DB 를 새로 만들어 해당 없음). A 셋 다 수량 범위 밖은 FastAPI 기본 422(PRD 는 400).
- **R7 의 틈 — 400 이 두 종류였다.** R7 은 "400(입력 오류) → 404 → 409" 이고 "옵션 아님은 400" 인데, 옵션이 맞는지는 **상품을 찾아야** 안다. "없는 장바구니 + 옵션 틀림" 을 보내면(`probe_cases.py` · `probe_r7.json`) **B1 · B3 · C1 · C3 은 404, B2 · C2 는 400** — 4 대 2 로 갈렸다(우리 정답 앱도 404). 테스트 T8 은 '수량 400 → 404' 만 물어서 점수는 같다. **보고한 건 C1 하나** — "옵션이 맞는지 보려면 상품이 있어야 해서, 옵션 오류는 상품 확인 뒤에 판정합니다". 고칠 문장: "본문만 보고 아는 오류(수량) 400 → 없는 장바구니 · 상품 · 줄 404 → 상품을 찾아야 아는 오류(옵션) 400 → 409".
- B 셋 다 "화면(T9)과 tests 는 확인하지 못했다" 고 정직하게 적었다. B1 은 PRD 7 의 `PORT` 환경 변수를 안 따랐다고 스스로 적었다(채점은 `--port` 로 해서 영향 없음).
- C 의 보고: C1 R7 판정 순서 · 품절 + 옵션 오류는 400 먼저, C2 PRD 에 없는 거부 문구를 직접 정함, C3 화면의 수량 칸 · 빼기 버튼에 `data-testid` 없음. 세 편 연속 '추가한 API 없음' 을 명시.

## 채점기 버그 — 첫 C1 빌더가 찾았다 (세 번째 사례)

- 첫 시도의 C1 빌더가 "서버 출력 파이프가 안 읽히면 서버가 멈출 수 있다" 며 접속 로그를 끄고 9/9 를 냈다. 맞는 지적이다 — 테스트의 `Server` 가 uvicorn 출력을 `PIPE` 로 받고 끝날 때까지 읽지 않아, 요청이 많으면 버퍼가 차서 서버가 멈출 수 있었다. **고쳤다**: 출력을 임시 파일로 받는다. 채점과 C 의 재실행은 고친 테스트로 했다(A · B 빌드는 테스트를 받지 않으므로 영향 없음).
- 그 빌더는 자기가 띄운 서버를 치우려고 `taskkill /F /IM python.exe` 를 했고, python.exe 로 돌던 **우리 빌드 스크립트까지 같이 죽었다**(rc=1, 트레이스백 없음 — 3편 B1 과 같은 증상). 결과(build.json)가 안 남아 C 를 다시 돌렸다. 두 번째 시도의 C1 도 같은 식으로 스크립트가 죽어(고아로 남은 빌더는 정리) 세 번째에 `pythonw.exe` 로 빌드 스크립트를 돌려 해결 — 이름이 달라 `taskkill /IM python.exe` 에 안 걸린다.
- 4편(C2 · 채점기의 모호함) · 9편(C3 · 정리 단계 경쟁 조건) · 10편(C1 · 출력 파이프) — **채점기를 고치게 만든 AI 보고가 세 번째**. 이번 건 보고 칸이 아니라 빌더의 작업 기록에서 찾았다(그 시도는 보고까지 가지 못했다).

## 숫자의 뜻

- 돈이 걸린 화면의 PRD 는 **계산 순서를 식으로** 적는다. "할인가 + 추가금(할인은 추가금에 안 걸림)" 을 안 적으면 AI 는 합에 할인율을 건다(3/3).
- 한도는 **무엇의 한도인지** 까지 — 재고인지 1회 한도인지, 옵션별인지 상품별인지. 안 적으면 옵션별 재고 + 코드 상수(3/3).
- 거부 순서는 **'무엇을 찾아야 알 수 있나'** 로 적는다. 같은 400 이라도 본문만 보면 아는 것과 상품을 찾아야 아는 것은 자리가 다르다 — 안 그러면 4 대 2 로 갈린다.
