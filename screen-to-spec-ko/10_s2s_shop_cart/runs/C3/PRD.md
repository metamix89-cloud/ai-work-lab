# PRD — 가나다식품 「소호 쇼핑몰 상품 목록 · 장바구니」

> 「이 화면, PRD 로는 이렇게」 10편. 회사 · 상품 · 가격은 모두 교육용 가상 데이터. 결제는 없다(장바구니까지).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 가나다식품은 소규모 직영 쇼핑몰을 연다. 지난 시범 운영에서 품절 상품이 장바구니에 담기고, 재고보다 많이 주문되고, 할인가와 정가가 섞여 합계가 틀렸다는 문의가 이어졌다.
- **목적:** 손님이 상품을 보고 **옵션과 수량을 골라 담으면**, 품절 · 수량 한도 · 옵션 누락은 **서버가 막고**, 합계와 배송비는 **한 가지 규칙으로** 계산된다.
- **성공 기준:** 품절 · 재고 초과 주문 0건. 합계 문의 0건.

## 2. 사용자

- **손님 1유형.** 로그인 없이 연다. 장바구니는 서버가 발급한 `cart_id` 로 구분한다(화면은 처음 열 때 하나 발급받아 쓴다).

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 상품 목록: 이름 · 가격(할인가가 있으면 정가에 취소선 + 할인가) · 품절 표시 · 옵션 선택 · 수량 · 담기 | Must | 1 |
| F2 | 장바구니: 줄마다 상품 · 옵션 · 단가 · 수량 · 줄 합계, 수량 바꾸기(0 이면 빼기) | Must | 1 |
| F3 | 합계: 상품 합계 · 배송비 · 총액 | Must | 1 |
| F4 | API: `GET /api/products` · `POST /api/carts` · `GET /api/carts/{cart_id}` · `POST /api/carts/{cart_id}/items` · `PUT /api/carts/{cart_id}/items/{item_id}` | Must | 1 |

## 4. 화면

한 페이지(`/`). 왼쪽 상품, 오른쪽 장바구니.

- **상품 카드:** `data-testid="product"` + `data-id`(product_id) + `data-soldout="1|0"`. 카드 안: 이름, 할인가가 있으면 정가(`data-testid="list-price"`, 취소선)와 할인가(`data-testid="sale-price"`), 없으면 가격(`data-testid="sale-price"` 하나), 옵션이 있으면 옵션 선택(`data-testid="option"`), 수량(`data-testid="qty"`, 기본 1), 담기(`data-testid="add-btn"`). **품절 카드에는 담기 버튼이 없거나 비활성**이고 `품절` 표시.
- **장바구니:** 줄마다 `data-testid="cart-item"` + `data-item`(item_id). 합계 `data-testid="subtotal"` · `shipping` · `total` — 숫자는 천 단위 쉼표 허용, 배송비 0 은 `무료` 로 써도 된다.
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 2개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`shop.db`)를 **새로** 만든다. 장바구니는 DB 에 쓴다(서버가 도는 동안 유지).

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/products.csv` | `product_id, name, price, sale_price, stock, max_per_order` | `product_id` 문자열 `P01` · `price` 정가 원 단위 정수 `9000` · `sale_price` 할인가 정수 또는 빈칸 · `stock` 재고 0 이상 정수(0 = 품절) · `max_per_order` 한 장바구니에 담을 수 있는 최대 수량 정수 |
| `seed/options.csv` | `option_id, product_id, label, extra` | `option_id` 문자열 `P02-1K` · `label` `1kg` · `extra` 추가금 0 이상 정수 |

- **테이블:** 접두어 `sh_` — `sh_products` · `sh_options` · `sh_carts(cart_id)` · `sh_cart_items(item_id, cart_id, product_id, option_id, qty)`.
- **가상 데이터:** 상품 5개(품절 1 · 할인 2 · 옵션 있는 상품 1). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API** — 금액은 원 단위 정수.
  - `GET /api/products` → `[{"product_id","name","price","sale_price"(정수 또는 null),"stock","max_per_order","sold_out","options":[{"option_id","label","extra"}]}]`
  - `POST /api/carts` → 201 `{"cart_id":"문자열"}`
  - `GET /api/carts/{cart_id}` → `{"cart_id","items":[{"item_id","product_id","option_id"(또는 null),"name","label"(또는 null),"unit_price","qty","line_total"}],"subtotal","shipping","total"}`
  - `POST /api/carts/{cart_id}/items` 본문 `{"product_id":"P02","option_id":"P02-1K","qty":2}` → 201 과 장바구니 전체
  - `PUT /api/carts/{cart_id}/items/{item_id}` 본문 `{"qty":3}` → 200 과 장바구니 전체 (`qty` 0 이면 그 줄을 뺀다)
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **품절은 담을 수 없다.** `stock` 0 인 상품을 담으면 409 `품절된 상품입니다`. |
| R2 | **옵션.** 옵션이 있는 상품은 `option_id` 가 그 상품의 옵션이어야 한다. 옵션이 없는 상품에 `option_id` 를 주거나, 있는 상품에 안 주면 400 `옵션을 확인하세요`. |
| R3 | **단가** = (할인가가 있으면 할인가, 없으면 정가) + 옵션 추가금. 할인은 옵션 추가금에는 적용하지 않는다. |
| R4 | **수량 한도** = `min(stock, max_per_order)` — **상품 단위**(옵션이 달라도 같은 상품이면 합친다). 담기 · 바꾸기 결과 그 상품의 장바구니 수량 합이 한도를 넘으면 409 `최대 N개까지 담을 수 있습니다`. 같은 상품 · 같은 옵션을 또 담으면 한 줄로 합친다. |
| R5 | **합계.** 상품 합계 = 줄 합계(단가 × 수량)의 합. **배송비 = 상품 합계 30,000원 이상이면 0, 미만이면 3,000원(장바구니가 비면 0).** 총액 = 상품 합계 + 배송비. **30,000원은 무료다.** |
| R6 | **입력.** `qty` 는 담기에서 1 이상 정수, 바꾸기에서 0 이상 정수. 아니면 400 `수량을 확인하세요`. |
| R7 | **거부가 둘 이상 해당하면** 400(입력 오류) → 404(없는 장바구니 · 상품 · 줄 · 옵션 아님은 400) → 409(품절 · 한도) 순서로 먼저 걸리는 것 하나만. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 금액은 정수 연산.
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 장바구니에 담는다고 **재고를 줄이지 않는다**(재고 차감은 11편 주문의 일).
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원, 결제 · 주문 확정, 쿠폰 · 적립금, 상품 검색 · 정렬 · 카테고리, 상품 상세 페이지, 리뷰 · 찜, **상품 · 재고 편집 화면(데이터 편집 화면)**, 재고 차감, 이미지 업로드, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 5개와 규칙 R1~R7, `/` 화면(상품 · 장바구니 · 합계 · 메시지 · 오류).
2. 그 외 없음.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '장바구니' 가 보인다.
- [ ] T2 상품 5개, 품절 상품은 `sold_out: true`, 할인 없는 상품의 `sale_price` 는 null, 옵션 있는 상품의 옵션 2개.
- [ ] T3 품절 상품을 담으면 409, 장바구니가 그대로다 (R1).
- [ ] T4 옵션 빠짐 · 옵션 없는 상품에 옵션은 400. 할인 상품 + 옵션의 단가 = 할인가 + 추가금 (R2 · R3).
- [ ] T5 재고(3)가 1회 한도(5)보다 적으면 4개는 409 · 3개는 201. 한도 2 상품을 2개 담은 뒤 1개 더 담으면 409. 같은 상품 다른 옵션도 합쳐서 센다 (R4).
- [ ] T6 상품 합계 28,500 → 배송비 3,000, 수량을 바꿔 30,000 → 배송비 0 (R5).
- [ ] T7 수량 0 으로 바꾸면 줄이 빠지고, 한도를 넘게 바꾸면 409, 없는 줄은 404 (R4 · R6).
- [ ] T8 없는 장바구니 + 잘못된 수량은 400, 없는 장바구니 + 올바른 본문은 404, 없는 상품은 404 (R7).
- [ ] T9 화면: 품절 카드의 담기가 막혀 있고, 할인 카드에 정가 · 할인가가 따로 보이며, 1,500원 상품을 담으면 총액 4,500(배송비 포함)이 보인다.
