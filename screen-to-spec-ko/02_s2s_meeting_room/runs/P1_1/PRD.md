# 회의실 예약 웹앱 PRD

- 조직: 다온소프트 (사내용)
- 문서 상태: 초안 v0.1
- 기술: Python FastAPI + 순수 HTML/JS + SQLite
- 데이터: 가상 데이터만 사용 (실제 직원·개인정보 없음)

---

## 1. 개요

### 1.1 배경
회의실 예약을 메신저·구두로 하다 보니 같은 시간에 겹치거나, 누가 쓰는지 알기 어렵다. 한 화면에서 회의실 상태를 보고 바로 예약·취소할 수 있는 간단한 사내 웹앱을 만든다.

### 1.2 목표
- 회의실 3개의 하루 시간표(09:00~18:00, 30분 단위)를 한 화면에서 본다.
- 시간표의 빈 칸을 눌러 예약한다.
- 내가 한 예약은 내가 취소할 수 있다.

### 1.3 성공 기준 (요약)
- 같은 회의실·같은 시간에 중복 예약이 생기지 않는다.
- 조회 → 예약 → 취소까지 화면 이동 없이 한 화면에서 끝난다.
- 상세 기준은 10장 참고.

### 1.4 범위 원칙
- **Phase 1에는 Must 기능만 넣는다.** Should/Could는 이후 Phase로 미룬다.
- 가장 작은 형태로 먼저 만든다. 인증, 알림, 관리자 기능은 만들지 않는다.

## 2. 사용자

| 구분 | 설명 | 주요 행동 |
|---|---|---|
| 직원 (일반 사용자) | 다온소프트 사내 직원. 유일한 사용자 유형 | 시간표 조회, 예약, 본인 예약 취소 |

- 로그인은 없다. 화면에서 가상 직원 목록 중 "나"를 선택해 본인을 구분한다. (보안 인증이 아니라 단순 구분이며, 사내 소규모 사용 전제)
- 관리자 역할은 두지 않는다.

## 3. 기능 요구사항

MoSCoW: M = Must, S = Should, C = Could

| F-번호 | 기능 | 설명 | MoSCoW | Phase |
|---|---|---|---|---|
| F-01 | 하루 시간표 보기 | 회의실 3개 × 09:00~18:00 30분 칸(18칸)을 표로 표시. 예약된 칸에는 예약자 이름 표시 | M | 1 |
| F-02 | 사용자 선택 | 가상 직원 목록에서 "나"를 선택. 선택값은 브라우저에 기억 | M | 1 |
| F-03 | 빈 칸 클릭 예약 | 빈 칸 클릭 → 확인 창 → 확인 시 해당 30분 예약 | M | 1 |
| F-04 | 내 예약 취소 | 내 예약 칸 클릭 → 확인 창 → 확인 시 취소 | M | 1 |
| F-05 | 중복 예약 방지 | 서버에서 같은 방·같은 시간 중복을 거부하고 사용자에게 메시지 표시 | M | 1 |
| F-06 | 가상 시드 데이터 | 회의실 3개와 가상 직원 목록을 최초 실행 시 자동 생성 | M | 1 |
| F-07 | 날짜 이동 | 이전/다음 날, 오늘 버튼으로 다른 날짜 시간표 조회·예약 | S | 2 |
| F-08 | 연속 시간 예약 | 시작 칸 클릭 후 종료 시간을 골라 30분 초과 예약을 한 번에 생성 | S | 2 |
| F-09 | 회의 제목 입력 | 예약 시 제목(선택)을 입력하고 칸에 표시 | S | 2 |
| F-10 | 내 예약 목록 | 오늘 이후 내 예약을 목록으로 모아 보기 | C | 3 |
| F-11 | 자동 새로고침 | 일정 간격으로 시간표를 갱신해 다른 사람 예약을 반영 | C | 3 |

> Phase 1은 F-01 ~ F-06 (모두 Must)만 포함한다. Phase 1의 시간표는 **오늘 하루**만 다룬다.

## 4. 화면 구성

화면은 단일 페이지 1개다.

### 4.1 레이아웃
```
┌─────────────────────────────────────────────┐
│ 회의실 예약          오늘: 2026-10-30   [나: ▼ 김가온 ] │  ← 상단 바 (F-02)
├──────┬────────────┬────────────┬────────────┤
│ 시간 │ 회의실 A   │ 회의실 B   │ 회의실 C   │
├──────┼────────────┼────────────┼────────────┤
│ 09:00│ (빈 칸)    │ 이서연     │ (빈 칸)    │
│ 09:30│ (빈 칸)    │ 이서연     │ (빈 칸)    │
│  ... │            │            │            │
│ 17:30│ (빈 칸)    │ (빈 칸)    │ 박도윤     │
└──────┴────────────┴────────────┴────────────┘
```
- 행: 09:00 ~ 17:30 시작 칸 18개 (마지막 칸은 17:30~18:00)
- 열: 회의실 3개

### 4.2 칸 상태

| 상태 | 표시 | 클릭 동작 |
|---|---|---|
| 빈 칸 | 흰색 | 예약 확인 창 열기 |
| 내 예약 | 강조색 + 내 이름 | 취소 확인 창 열기 |
| 남의 예약 | 회색 + 예약자 이름 | 동작 없음 |
| 지난 시간 | 흐리게 | 동작 없음 |

### 4.3 확인 창
- 예약: "회의실 A, 10:00~10:30 예약할까요?" [예약] [닫기]
- 취소: "회의실 A, 10:00~10:30 예약을 취소할까요?" [예약 취소] [닫기]
- 실패 시(중복 등) 창 또는 상단에 오류 메시지를 보여주고 시간표를 다시 불러온다.

## 5. 데이터 구조

SQLite 사용. 모든 표 이름은 `mr_` 로 시작한다. (mr = meeting room)

### 5.1 mr_rooms — 회의실

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | 회의실 번호 |
| name | TEXT NOT NULL UNIQUE | 회의실 이름 (A / B / C) |

### 5.2 mr_users — 가상 직원

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | 직원 번호 |
| name | TEXT NOT NULL UNIQUE | 가상 이름 |

### 5.3 mr_reservations — 예약

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | 예약 번호 |
| room_id | INTEGER NOT NULL | → mr_rooms.id |
| user_id | INTEGER NOT NULL | → mr_users.id (예약자) |
| rsv_date | TEXT NOT NULL | 예약 날짜 `YYYY-MM-DD` |
| slot_start | TEXT NOT NULL | 시작 시각 `HH:MM` (09:00 ~ 17:30, 30분 단위) |
| status | TEXT NOT NULL | `active` / `cancelled` |
| created_at | TEXT NOT NULL | 생성 일시 |
| cancelled_at | TEXT | 취소 일시 (취소 시에만) |

- 제약: `(room_id, rsv_date, slot_start)` 조합은 `status = 'active'` 인 행에서 유일해야 한다. (부분 유니크 인덱스) — 중복 방지의 최종 방어선.
- 한 행 = 30분 한 칸. Phase 2의 연속 예약(F-08)은 여러 행을 만들어 처리하므로 구조 변경이 필요 없다.
- `rsv_date` 는 Phase 1에서 항상 오늘이지만, Phase 2 날짜 이동을 위해 미리 둔다.

### 5.4 가상 시드 데이터
- 회의실: A, B, C
- 직원: 가상 이름 8명 내외 (예: 김가온, 이서연, 박도윤 … 실존 인물과 무관)
- 예약: 시드는 직원·회의실만 생성. 예약은 사용자가 만든다. (보여주기용 예약이 필요하면 가상 예약 몇 건을 선택적으로 추가)

## 6. 업무 규칙

| R-번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00~18:00. 30분 단위 칸만 예약할 수 있다. (시작 시각 09:00 ~ 17:30) |
| R-02 | 한 예약은 한 회의실의 한 칸(30분)이다. (Phase 1) |
| R-03 | 같은 회의실·같은 날짜·같은 시간에 활성 예약은 1건만 가능하다. |
| R-04 | 이미 지난 시간 칸은 예약할 수 없다. 현재 시각 이전에 시작한 칸은 지난 칸으로 본다. |
| R-05 | 예약은 예약한 본인만 취소할 수 있다. 서버에서도 예약자와 요청자를 대조한다. |
| R-06 | 이미 시작했거나 지난 예약은 취소할 수 없다. (이용 기록 보존) |
| R-07 | 취소는 행을 지우지 않고 `status = 'cancelled'` 로 바꾼다. 취소된 칸은 다시 예약 가능하다. |
| R-08 | 한 사람이 여러 회의실의 같은 시간을 동시에 예약하는 것도 막지 않는다. (Phase 1 단순화) |
| R-09 | 예약 개수 제한은 두지 않는다. |
| R-10 | 시간 기준은 서버 시각(한국 표준시)이다. |

## 7. 제약 조건

- **기술 스택**: 백엔드 Python FastAPI, 프런트 순수 HTML + JavaScript(프레임워크·빌드 도구 없음), DB는 SQLite 파일 1개.
- **구성**: FastAPI가 정적 HTML/JS와 JSON API를 함께 제공하는 단일 서버. 로컬(사내 PC) 실행 기준.
- **데이터**: 가상 데이터만 사용한다. 실제 직원 이름·계정·연락처를 넣지 않는다.
- **인증**: 없음. 사용자 선택 방식은 본인 확인이 아니므로 외부 공개 환경에서 쓰지 않는다.
- **동시성**: 두 사람이 같은 칸을 동시에 누르면 DB 유니크 제약으로 한 명만 성공하고, 다른 한 명은 오류 메시지를 받는다.
- **브라우저**: 최신 Chrome/Edge 데스크톱 기준. 모바일 최적화는 하지 않는다.
- **규모**: 회의실 3개·직원 수십 명 이하의 소규모 사용을 가정한다.

## 8. 범위 밖

Phase 1뿐 아니라 이 PRD 전체에서 다루지 않는 것:

- 로그인, 비밀번호, SSO 등 실제 인증·권한 관리
- 관리자 화면 (회의실 추가·삭제, 타인 예약 강제 취소)
- 반복 예약, 예약 수정(시간 변경)
- 이메일·메신저 알림, 캘린더(Outlook/Google) 연동
- 회의실 정원·장비 정보, 승인 절차, 사용 통계
- 모바일 앱 및 모바일 전용 화면
- 실제 직원 데이터 연동

(날짜 이동, 연속 시간 예약, 회의 제목, 내 예약 목록, 자동 새로고침은 범위 밖이 아니라 **Phase 2~3** 이다.)

## 9. 개발 단계

| Phase | 포함 기능 | 목표 |
|---|---|---|
| 1 | F-01, F-02, F-03, F-04, F-05, F-06 (Must 전부) | 오늘 하루 시간표 조회 · 예약 · 본인 예약 취소가 동작하는 최소 제품 |
| 2 | F-07, F-08, F-09 (Should) | 날짜 이동, 연속 시간 예약, 회의 제목으로 실사용성 향상 |
| 3 | F-10, F-11 (Could) | 편의 기능 |

- 각 Phase는 앞 Phase의 완료 기준(10장)을 모두 통과한 뒤 시작한다.
- Should/Could 기능은 Phase 1에 앞당겨 넣지 않는다.

## 10. 완료 기준

### Phase 1 (모두 통과해야 완료)

**화면·조회**
- [ ] T-01 첫 접속 시 회의실 3개 열과 09:00~17:30 18개 행의 시간표가 표시된다. (F-01)
- [ ] T-02 예약된 칸에 예약자 이름이 표시되고, 내 예약·남의 예약·빈 칸·지난 칸이 시각적으로 구분된다. (F-01)
- [ ] T-03 최초 실행 시 회의실 3개와 가상 직원이 자동 생성되고, 사용자 선택 목록에 직원이 나타난다. (F-06, F-02)
- [ ] T-04 선택한 "나"가 새로고침 후에도 유지된다. (F-02)

**예약**
- [ ] T-05 빈 칸을 클릭하고 확인하면 예약이 생기고, 칸에 내 이름이 즉시 표시된다. (F-03)
- [ ] T-06 확인 창에서 닫기를 누르면 예약이 생기지 않는다. (F-03)
- [ ] T-07 지난 시간 칸은 클릭해도 예약되지 않는다. 서버에 직접 요청해도 거부된다. (R-04)
- [ ] T-08 같은 회의실·같은 시간에 두 번째 예약 요청은 거부되고 오류 메시지가 보인다. (F-05, R-03)
- [ ] T-09 두 브라우저에서 같은 칸을 거의 동시에 예약하면 한 쪽만 성공한다. (F-05)

**취소**
- [ ] T-10 내 예약 칸을 클릭하고 확인하면 예약이 취소되고 칸이 빈 칸으로 돌아간다. (F-04)
- [ ] T-11 남의 예약 칸은 클릭해도 취소 창이 열리지 않는다. 다른 사용자 이름으로 서버에 취소 요청해도 거부된다. (R-05)
- [ ] T-12 이미 시작했거나 지난 예약은 취소할 수 없다. (R-06)
- [ ] T-13 취소된 칸은 다시 예약할 수 있고, DB에는 `status = 'cancelled'` 행으로 남는다. (R-07)

**데이터·제약**
- [ ] T-14 모든 DB 표 이름이 `mr_` 로 시작한다. (5장)
- [ ] T-15 시드·테스트 데이터에 실제 인물 정보가 없다. (7장)
- [ ] T-16 Phase 1 화면에 날짜 이동·제목 입력·연속 예약 등 Should/Could 기능이 없다. (9장)

### Phase 2

- [ ] T-17 이전/다음/오늘 버튼으로 날짜를 이동하면 해당 날짜 시간표가 표시된다. (F-07)
- [ ] T-18 종료 시간을 골라 연속 구간을 예약하면 해당 칸이 모두 예약되고, 하나라도 겹치면 전부 거부된다. (F-08)
- [ ] T-19 예약 시 입력한 제목이 칸에 표시된다. 제목을 비워도 예약된다. (F-09)

### Phase 3

- [ ] T-20 내 예약 목록에 오늘 이후 내 예약이 시간순으로 나타나고 여기서 취소할 수 있다. (F-10)
- [ ] T-21 다른 브라우저에서 만든 예약이 일정 시간 안에 새로고침 없이 반영된다. (F-11)
