# 회의실 예약 웹앱 PRD

- 조직: 다온소프트 (사내용)
- 문서 버전: 0.1 (초안)
- 작성일: 2026-10-30

## 1. 개요

### 1.1 배경
회의실 예약 현황을 한눈에 확인하고 바로 예약·취소할 수 있는 사내 웹앱이 필요하다.

### 1.2 목표
- 회의실 3개의 하루 시간표(09:00~18:00, 30분 단위)를 한 화면에 보여준다.
- 빈 칸을 눌러 예약한다.
- 내 예약은 직접 취소할 수 있다.

### 1.3 기술 스택
| 영역 | 선택 |
|---|---|
| 백엔드 | Python FastAPI |
| 프론트엔드 | 순수 HTML + JavaScript (프레임워크·빌드 도구 없음) |
| 저장소 | SQLite (단일 파일) |

### 1.4 데이터 원칙
모든 데이터(사용자, 회의실, 예약)는 가상 데이터만 사용한다. 실제 직원 정보는 넣지 않는다.

## 2. 사용자

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원 | 다온소프트 사내 구성원 (가상 사용자) | 시간표 조회, 예약, 본인 예약 취소 |

- 관리자 역할은 두지 않는다. (8. 범위 밖)
- 로그인 대신 화면 상단에서 "나"를 가상 사용자 목록 중에서 고른다. 이 선택이 "내 예약"의 기준이다. 인증이 아니라 식별용이다.

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could, W=Won't(이번 범위 밖). Phase 1에는 Must만 포함한다.

| F-번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F-01 | 가상 사용자 선택 ("나" 지정) | M | 1 |
| F-02 | 회의실 3개 × 09:00~18:00(30분 단위 18칸) 하루 시간표 표시 (기본 오늘) | M | 1 |
| F-03 | 칸 상태 구분 표시: 빈 칸 / 내 예약 / 타인 예약 / 지난 시간 | M | 1 |
| F-04 | 빈 칸 클릭 → 예약 입력(종료 시각, 제목) → 예약 확정 | M | 1 |
| F-05 | 내 예약 클릭 → 취소 확인 → 취소 | M | 1 |
| F-06 | 규칙 위반 시 사유 메시지 표시 (중복, 지난 시간 등) | M | 1 |
| F-07 | 가상 초기 데이터(사용자·회의실·예약 예시) 적재 | M | 1 |
| F-08 | 날짜 이동 (이전/다음 날, 날짜 선택) | S | 2 |
| F-09 | 내 예약 목록 화면 | S | 2 |
| F-10 | 예약 제목·시간 수정 | C | 3 |
| F-11 | 반복 예약 | C | 3 |
| F-12 | 알림(메일·메신저) | W | - |

## 4. 화면 구성

Phase 1은 한 화면(시간표)과 두 개의 대화상자로 구성한다.

### 4.1 시간표 화면
- 상단: 제목, 날짜(오늘 고정 표시), "나" 선택 드롭다운(F-01)
- 본문: 세로축은 시간(09:00~17:30 시작 칸 18개), 가로축은 회의실 3개(F-02)
- 칸 표현(F-03, 색뿐 아니라 글자로도 구분)
  - 빈 칸: 흰색, 클릭 가능
  - 내 예약: 강조색, 제목 표시, 클릭 시 취소 대화상자
  - 타인 예약: 회색, 예약자 이름·제목 표시, 클릭 불가
  - 지난 시간: 흐리게, 클릭 불가

### 4.2 예약 대화상자 (F-04)
- 표시: 회의실, 날짜, 시작 시각(칸에서 자동 입력, 수정 불가)
- 입력: 종료 시각(30분 단위 선택), 제목(필수)
- 버튼: 예약 / 닫기

### 4.3 취소 확인 대화상자 (F-05)
- 표시: 회의실, 시간, 제목
- 버튼: 예약 취소 / 닫기

### 4.4 오류 표시 (F-06)
- 대화상자 안에 사유를 한 줄로 표시한다. 예약·취소 성공 시 시간표를 다시 불러온다.

## 5. 데이터 구조

표 이름 접두어는 `mr_` (meeting room)이다.

### 5.1 mr_users (가상 사용자)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| user_id | INTEGER PK | 사용자 ID |
| name | TEXT NOT NULL | 가상 이름 |

### 5.2 mr_rooms (회의실)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| room_id | INTEGER PK | 회의실 ID |
| name | TEXT NOT NULL UNIQUE | 예: 회의실 A, B, C |

### 5.3 mr_reservations (예약)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| reservation_id | INTEGER PK | 예약 ID |
| room_id | INTEGER NOT NULL | mr_rooms 참조 |
| user_id | INTEGER NOT NULL | mr_users 참조 (예약자) |
| rsv_date | TEXT NOT NULL | 예약 날짜 (YYYY-MM-DD) |
| start_time | TEXT NOT NULL | 시작 (HH:MM) |
| end_time | TEXT NOT NULL | 종료 (HH:MM, 시작보다 뒤) |
| title | TEXT NOT NULL | 예약 제목 |
| created_at | TEXT NOT NULL | 생성 시각 |

- 취소는 행을 삭제하는 방식으로 처리한다. (취소 이력은 Phase 1에서 보관하지 않음)
- 중복 방지를 위해 (room_id, rsv_date) 인덱스를 둔다.

## 6. 업무 규칙

| R-번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00~18:00이며, 시작·종료 시각은 30분 단위다. |
| R-02 | 같은 회의실·같은 날짜에서 시간 구간이 겹치는 예약은 만들 수 없다. 맞닿는 것(앞 예약 종료 = 뒤 예약 시작)은 허용한다. |
| R-03 | 이미 지난 시간(현재 시각 이전에 시작하는 칸)은 새로 예약할 수 없다. |
| R-04 | 한 번의 예약은 최소 30분, 최대 2시간으로 한다. (가정: 확정 필요) |
| R-05 | 제목은 필수이며 공백만으로는 안 된다. 최대 50자. (가정: 확정 필요) |
| R-06 | 예약자 본인만 해당 예약을 취소할 수 있다. 타인 예약은 취소할 수 없다. |
| R-07 | 이미 종료된 예약은 취소할 수 없다. 진행 중이거나 시작 전인 예약만 취소 가능하다. (가정: 확정 필요) |
| R-08 | 동시에 같은 칸을 예약하려 하면 먼저 처리된 한 건만 성공하고, 나머지는 R-02 위반으로 거절한다. 검사와 저장은 하나의 트랜잭션에서 수행한다. |
| R-09 | 규칙 검사는 서버에서 수행한다. 화면의 클릭 제한은 편의 기능일 뿐 규칙의 근거가 아니다. |

## 7. 제약 조건

- 기술: Python FastAPI + 순수 HTML/JS + SQLite. 외부 프레임워크·빌드 도구·별도 DB 서버를 쓰지 않는다.
- 데이터: 가상 데이터만 사용한다. 실제 개인정보를 저장하지 않는다.
- 인증: 로그인이 없다. "나" 선택은 보안 수단이 아니므로, 사내 망·시연 용도로만 쓴다. R-06은 이 선택을 신뢰하는 전제의 규칙이다.
- 규모: 회의실 3개, 동시 사용자 수십 명 이하. 단일 서버·단일 SQLite 파일.
- 시간대: 서버 로컬 시간(KST) 기준 하나만 사용한다.
- 브라우저: 최신 데스크톱 브라우저 (Chrome, Edge). 모바일 최적화는 하지 않는다.
- Phase 1에는 Must 기능만 넣는다.

## 8. 범위 밖

- 로그인·권한 관리·관리자 기능
- 날짜 이동(F-08), 내 예약 목록(F-09)은 Phase 1 범위 밖 (Phase 2)
- 예약 수정(F-10), 반복 예약(F-11) (Phase 3)
- 알림 발송 (F-12)
- 회의실 추가·삭제·정보 관리 화면
- 외부 캘린더(Outlook, Google 등) 연동
- 참석자 지정, 장비·좌석 예약, 승인 절차
- 취소 이력·통계·리포트
- 모바일 전용 화면

## 9. 개발 단계

| Phase | 목표 | 포함 기능 | 비고 |
|---|---|---|---|
| 1 | 오늘 하루 시간표에서 조회·예약·취소가 되는 최소 제품 | F-01 ~ F-07 (전부 Must) | 이 단계만 완료되면 요청 사항이 충족된다 |
| 2 | 사용 편의 | F-08, F-09 (Should) | Phase 1 완료 후 착수 |
| 3 | 부가 기능 | F-10, F-11 (Could) | 필요 시 |

Phase 1 내부 순서: 데이터 구조·초기 데이터(F-07) → 시간표 조회(F-02, F-03) → 예약(F-04, F-06) → 취소(F-05) → 사용자 선택(F-01) 연결.

## 10. 완료 기준

Phase 1 완료 기준이다. 모두 체크되면 Phase 1이 끝난다.

- [ ] T-01: 서버를 처음 실행하면 `mr_users`, `mr_rooms`, `mr_reservations` 표가 만들어지고 가상 데이터(회의실 3개, 사용자 여러 명, 예약 몇 건)가 들어간다. (F-07)
- [ ] T-02: 시간표에 회의실 3개와 09:00~18:00의 30분 칸 18개가 모두 보인다. (F-02)
- [ ] T-03: 빈 칸, 내 예약, 타인 예약, 지난 시간이 서로 구분되어 보인다. (F-03)
- [ ] T-04: "나"를 바꾸면 내 예약과 타인 예약의 표시가 바뀐다. (F-01, F-03)
- [ ] T-05: 빈 칸을 눌러 종료 시각과 제목을 입력하면 예약이 저장되고 시간표에 즉시 반영된다. (F-04)
- [ ] T-06: 이미 예약된 시간과 겹치게 예약하면 거절되고 사유가 표시된다. 맞닿는 예약은 성공한다. (R-02, F-06)
- [ ] T-07: 지난 시간 칸은 예약할 수 없다. 서버에 직접 요청해도 거절된다. (R-03, R-09)
- [ ] T-08: 제목이 비어 있거나, 예약 길이가 30분 미만 또는 2시간 초과이면 거절된다. (R-04, R-05)
- [ ] T-09: 내 예약을 누르고 확인하면 취소되고 해당 칸이 빈 칸으로 돌아온다. (F-05)
- [ ] T-10: 타인 예약은 화면에서 취소할 수 없고, 서버에 직접 취소 요청을 보내도 거절된다. (R-06, R-09)
- [ ] T-11: 이미 종료된 예약은 취소할 수 없다. (R-07)
- [ ] T-12: 같은 칸에 대한 두 요청이 거의 동시에 들어오면 한 건만 저장된다. (R-08)
- [ ] T-13: 서버를 껐다 켜도 예약 내용이 유지된다. (SQLite 영속성)
- [ ] T-14: 실제 개인정보 없이 가상 데이터만 들어 있다. (7. 제약 조건)

## 확정이 필요한 가정

요청에 없어서 임의로 정한 항목이다. 바꿀 수 있다.
- R-04: 최대 2시간 (제한 없음으로 바꿀 수 있음)
- R-05: 제목 최대 50자
- R-07: 종료된 예약은 취소 불가
- Phase 1은 "오늘"만 표시한다. 날짜 이동은 Phase 2 (F-08)로 미뤘다.
