# 회의실 예약 웹앱 PRD

다온소프트 사내 '회의실 예약' 웹앱 · 문서 버전 0.1 · 작성일 2026-10-30

## 1. 개요

- **목적**: 회의실 3개의 하루 시간표를 한 화면에서 보고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있게 한다.
- **배경**: 회의실 사용 현황을 한눈에 볼 수 없어 중복 사용과 확인 전화가 생긴다. 이를 줄이는 가장 작은 도구를 만든다.
- **핵심 범위(Phase 1)**: 시간표 조회 · 빈 칸 클릭 예약 · 내 예약 취소. 그 밖의 기능은 Phase 2 이후로 미룬다.
- **기술**: Python FastAPI(백엔드), 순수 HTML/JS(프런트, 프레임워크 없음), SQLite(저장).
- **데이터**: 가상 데이터만 사용한다. 실제 직원 정보나 사내 데이터는 넣지 않는다.

## 2. 사용자

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원 | 다온소프트 사내 구성원(가상 사용자 5명) | 시간표 조회, 예약, 본인 예약 취소 |

- 관리자 역할은 두지 않는다(8장 참고).
- 인증은 두지 않는다. 화면에서 가상 사용자 한 명을 고르면 그 사람으로 동작한다(F-04).

## 3. 기능 요구사항

| 번호 | 기능 | 설명 | MoSCoW | Phase |
|---|---|---|---|---|
| F-01 | 하루 시간표 보기 | 회의실 3개 × 9:00~18:00, 30분 단위 칸(18칸)을 표로 표시. 칸마다 빈 칸/예약됨 구분, 예약된 칸에는 예약자와 제목 표시 | Must | 1 |
| F-02 | 빈 칸 클릭 예약 | 빈 칸을 누르면 예약 창이 열림. 제목 입력과 종료 시각 선택(기본 30분) 후 확정하면 저장되고 시간표에 즉시 반영 | Must | 1 |
| F-03 | 내 예약 취소 | 본인 예약 칸을 누르면 취소 버튼 표시. 확인 후 취소하면 칸이 빈 칸으로 돌아감 | Must | 1 |
| F-04 | 사용자 선택 | 화면 상단에서 가상 사용자 중 한 명을 선택. "내 예약"의 기준이 됨 | Must | 1 |
| F-05 | 날짜 이동 | 이전/다음 날 버튼으로 다른 날짜의 시간표 조회 및 예약 | Should | 2 |
| F-06 | 내 예약 목록 | 오늘 이후 내 예약을 목록으로 모아 보고 거기서 취소 | Should | 2 |
| F-07 | 예약 수정 | 기존 예약의 제목/시간 변경 | Could | 3 |
| F-08 | 반복 예약 | 매주 같은 시간 예약 | Could | 3 |
| F-09 | 알림 | 회의 시작 전 알림 | Could | 3 |

Phase 1에는 Must만 넣는다(F-01~F-04).

## 4. 화면 구성

단일 페이지 1개(`index.html`)로 구성한다.

1. **상단 바**: 앱 제목, 오늘 날짜, 사용자 선택 드롭다운(F-04)
2. **시간표 영역**(F-01)
   - 가로: 회의실 3개(열), 세로: 09:00~17:30 시작 칸 18개(행)
   - 빈 칸: 흰색, 마우스를 올리면 강조
   - 남의 예약: 회색, 예약자·제목 표시, 클릭해도 취소 불가
   - 내 예약: 강조색, 클릭하면 취소 창
   - 지난 시간 칸: 비활성(클릭 불가)
3. **예약 창**(F-02): 회의실·시작 시각(읽기 전용), 종료 시각 선택, 제목 입력, [예약] [닫기]
4. **취소 확인 창**(F-03): 예약 내용 표시, [예약 취소] [닫기]
5. **메시지 영역**: 성공·실패 안내(예: "이미 예약된 시간입니다")

## 5. 데이터 구조

SQLite 사용. 표 이름은 모두 `rsv_` 로 시작한다.

### rsv_user (가상 사용자)

| 열 | 타입 | 설명 |
|---|---|---|
| user_id | INTEGER PK | 사용자 번호 |
| name | TEXT NOT NULL | 가상 이름 (예: 사용자A~E) |

### rsv_room (회의실)

| 열 | 타입 | 설명 |
|---|---|---|
| room_id | INTEGER PK | 회의실 번호 |
| name | TEXT NOT NULL | 회의실 이름 (예: 회의실 1~3) |

### rsv_booking (예약)

| 열 | 타입 | 설명 |
|---|---|---|
| booking_id | INTEGER PK | 예약 번호 |
| room_id | INTEGER NOT NULL | rsv_room 참조 |
| user_id | INTEGER NOT NULL | rsv_user 참조 (예약자) |
| book_date | TEXT NOT NULL | 예약 날짜 `YYYY-MM-DD` |
| start_slot | INTEGER NOT NULL | 시작 칸 번호 0~17 (0 = 09:00) |
| end_slot | INTEGER NOT NULL | 끝 칸 번호(미포함) 1~18. 종료 시각 = 9:00 + end_slot × 30분 |
| title | TEXT NOT NULL | 회의 제목 |
| status | TEXT NOT NULL | `ACTIVE` 또는 `CANCELED` |
| created_at | TEXT NOT NULL | 생성 시각 |

- 초기 데이터: 회의실 3개, 사용자 5명, 예시 예약 몇 건(전부 가상).
- 취소는 행을 지우지 않고 status를 `CANCELED`로 바꾼다.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00~18:00, 30분 단위 칸이다. 이 범위를 벗어난 요청은 거부한다. |
| R-02 | 같은 회의실·같은 날짜에서 `ACTIVE` 예약끼리 시간이 겹치면 안 된다. 서버가 저장 직전에 검사한다. |
| R-03 | 예약 길이는 최소 30분(1칸), 최대 4시간(8칸)이다. |
| R-04 | 이미 지난 시간 칸에는 예약할 수 없다. |
| R-05 | 예약 제목은 필수이며 1~30자다. |
| R-06 | 취소는 예약자 본인만 할 수 있다. 서버가 요청자와 예약자를 비교해 확인한다. |
| R-07 | 이미 시작했거나 지난 예약은 취소할 수 없다. |
| R-08 | 취소된 예약은 시간표에서 빈 칸으로 보이며, 같은 시간에 다시 예약할 수 있다. |
| R-09 | 한 사람이 같은 시간에 여러 회의실을 예약하는 것은 막지 않는다(Phase 1). |

## 7. 제약 조건

- 백엔드는 Python FastAPI, 프런트는 순수 HTML/JS(빌드 도구·프레임워크 없음), 저장소는 SQLite 파일 1개.
- 모든 데이터는 가상이다. 실제 이름·이메일·사내 정보를 넣지 않는다.
- 로컬/사내 PC 1대에서 실행하는 소규모 사용(동시 사용자 수십 명 이하)을 전제로 한다.
- 시간대는 한국 표준시(KST) 하나로 고정한다.
- 지원 브라우저: 최신 Chrome, Edge.
- 중복 방지는 화면이 아닌 서버에서 보장한다(R-02).

## 8. 범위 밖

- 로그인·비밀번호·권한 관리(사용자 선택은 흉내일 뿐 보안 기능이 아님)
- 관리자 기능, 회의실 추가·삭제·수정
- 승인 절차, 외부 캘린더(Outlook·Google) 연동
- 이메일·메신저 알림 (F-09는 Phase 3 후보일 뿐 현재 범위 밖)
- 모바일 전용 화면, 다국어
- 회의 참석자 관리, 장비·좌석 예약
- 사용 통계·리포트

## 9. 개발 단계

| Phase | 목표 | 포함 기능 |
|---|---|---|
| 1 | 최소 동작 버전: 보고·예약하고·취소 | F-01, F-02, F-03, F-04 (Must만) |
| 2 | 편의 기능 | F-05 날짜 이동, F-06 내 예약 목록 (Should) |
| 3 | 선택 기능 | F-07 예약 수정, F-08 반복 예약, F-09 알림 (Could) |

Phase 1 작업 순서: ① DB 표 생성과 가상 초기 데이터 → ② 시간표 조회·예약·취소 API → ③ 시간표 화면 → ④ 예약/취소 창과 사용자 선택 연결 → ⑤ 완료 기준 점검.

## 10. 완료 기준

Phase 1 완료 기준은 아래 항목을 모두 통과하는 것이다.

### Phase 1

- [ ] T-01 첫 화면에 회의실 3개 × 18칸(9:00~18:00) 시간표가 표시된다. (F-01)
- [ ] T-02 초기 예시 예약이 해당 칸에 예약자·제목과 함께 표시된다. (F-01)
- [ ] T-03 화면 상단에서 가상 사용자를 바꿀 수 있고, 바꾸면 "내 예약" 표시가 그에 맞게 바뀐다. (F-04)
- [ ] T-04 빈 칸을 누르면 예약 창이 열리고, 제목 입력 후 예약하면 칸이 즉시 예약됨으로 바뀐다. (F-02)
- [ ] T-05 종료 시각을 늘려(예: 1시간) 예약하면 해당 칸 여러 개가 함께 채워진다. (F-02, R-03)
- [ ] T-06 겹치는 시간에 예약하면 거부되고 안내 메시지가 나온다. 서버 API를 직접 호출해도 거부된다. (R-02)
- [ ] T-07 제목이 비었거나 30자를 넘으면 예약되지 않는다. (R-05)
- [ ] T-08 지난 시간 칸은 클릭해도 예약 창이 열리지 않고, API로 요청해도 거부된다. (R-04)
- [ ] T-09 내 예약을 누르면 취소 창이 열리고, 취소하면 칸이 빈 칸으로 돌아가 다시 예약할 수 있다. (F-03, R-08)
- [ ] T-10 남의 예약에는 취소 버튼이 없고, API로 취소를 요청해도 거부된다. (R-06)
- [ ] T-11 이미 시작했거나 지난 내 예약은 취소할 수 없다. (R-07)
- [ ] T-12 서버를 껐다 켜도 예약과 취소 내용이 유지된다. (5장)
- [ ] T-13 DB의 모든 표 이름이 `rsv_` 로 시작하고, 데이터에 실제 개인정보가 없다. (5장, 7장)
- [ ] T-14 Phase 1 화면과 API에 Must 외 기능(날짜 이동, 내 예약 목록 등)이 들어 있지 않다. (3장)

### Phase 2 (착수 시 점검)

- [ ] T-15 이전/다음 날 버튼으로 날짜를 바꾸면 그날의 시간표가 표시되고 예약·취소가 동작한다. (F-05)
- [ ] T-16 내 예약 목록에 오늘 이후 내 예약만 나오고, 목록에서 취소할 수 있다. (F-06)
