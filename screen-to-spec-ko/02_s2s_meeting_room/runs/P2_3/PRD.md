# PRD — 다온소프트 회의실 예약 웹앱

## 1. 개요

- **목적**: 다온소프트 사내 회의실 3개의 하루 시간표를 한 화면에서 보고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있게 한다.
- **핵심 요청 3가지**
  1. 회의실 3개의 하루 시간표(09:00~18:00, 30분 단위)를 보여 준다.
  2. 빈 칸을 누르면 예약된다.
  3. 내 예약은 취소할 수 있다.
- **기술**: Python FastAPI(백엔드) + 순수 HTML/JS(프론트, 프레임워크·빌드 도구 없음) + SQLite(저장소).
- **데이터**: 가상 데이터만 사용한다. 실제 직원 정보·계정은 넣지 않는다.
- **산출물 원칙**: Must 가 아닌 기능은 Phase 1 에 넣지 않는다.

## 2. 사용자와 권한

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원(예약자) | 다온소프트 사내 구성원(가상 사용자 5명) | 시간표 조회, 빈 칸 예약, 본인 예약 취소 |

- 관리자 역할은 두지 않는다(8장 범위 밖).
- 로그인 대신 화면 상단에서 "나"를 가상 사용자 목록 중에서 고른다(F-04). 비밀번호·인증은 없다.

### 2.1 권한 표 (누가 누구의 것을 만들고 지울 수 있나)

| 동작 | 본인 예약 | 남의 예약 | 서버 검사 |
|---|---|---|---|
| 조회 | 가능 | 가능(예약자 이름 표시) | 없음 |
| 예약 생성 | 요청한 사용자 본인 이름으로만 생성 | 남의 이름으로 대신 생성 불가 | 요청의 `user_id` 가 `rr_user` 에 있는지 확인. 없으면 거절(4.2장 E-07) |
| 예약 취소 | 시작 전인 것만 가능 | 불가 | 예약의 `user_id` 와 요청의 `user_id` 가 다르면 403 (R-04). 화면에서 막는 것과 별개로 **서버가 항상 검사**한다 |
| 예약 삭제(행 삭제) | 불가 | 불가 | 취소는 `status='cancelled'` 기록뿐이며 행을 지우는 API 는 없다(R-06) |

- 인증이 없으므로 서버는 요청에 실린 `user_id` 를 신뢰한다. 이는 보안 수단이 아니라 "실수로 남의 예약을 지우지 않게" 하는 수준의 방어다(7장).

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could. Phase 1 에는 M 만 넣는다.

| ID | 기능 | MoSCoW | Phase | 설명 |
|---|---|---|---|---|
| F-01 | 하루 시간표 조회 | M | 1 | 회의실 3개 × 18칸(09:00~17:30 시작, 30분 단위) 격자를 보여 준다. 칸마다 빈 칸/예약됨/내 예약/지난 시간을 구분해 표시한다. Phase 1 은 오늘 날짜만 보여 준다. |
| F-02 | 빈 칸 클릭 예약 | M | 1 | 빈 칸을 누르면 그 칸(30분) 1개가 현재 사용자 이름으로 예약된다. 여러 칸이 필요하면 칸마다 누른다. 확인창은 띄우지 않는다. |
| F-03 | 내 예약 취소 | M | 1 | 내 예약 칸을 누르면 취소 확인 후 취소되고 빈 칸으로 돌아간다. 남의 예약 칸은 취소할 수 없다. |
| F-04 | 사용자 선택(간이 식별) | M | 1 | "내 예약" 판단을 위해 가상 사용자 중 한 명을 고른다. 선택값은 브라우저(localStorage)에 저장한다. 처음 접속해 저장값이 없으면 목록의 첫 번째 사용자를 선택해 둔다. |
| F-05 | 날짜 이동(이전/다음 날) | S | 2 | 오늘 외의 날짜 시간표를 보고 예약한다. |
| F-06 | 내 예약 목록 | S | 2 | 내가 잡은 예약을 날짜순으로 모아 보고 거기서 취소한다. |
| F-07 | 연속 칸 한 번에 예약 | S | 2 | 칸을 드래그하거나 시작·끝을 골라 여러 칸을 한 번에 예약한다. |
| F-08 | 예약 제목 입력 | C | 3 | 예약 시 회의 제목(선택)을 입력하고 시간표에 표시한다. |

## 4. 화면 구성

단일 페이지(`index.html`) 하나로 구성한다.

```
┌──────────────────────────────────────────────┐
│ 다온소프트 회의실 예약     오늘: 2026-10-30   나: [김다온 ▼] │  ← 헤더
├──────────────────────────────────────────────┤
│ (안내 메시지 한 줄 — 평소에는 비어 있음)                   │
├──────┬───────────┬───────────┬───────────┤
│ 시간  │ 회의실 A   │ 회의실 B   │ 회의실 C   │  ← 열 머리글
├──────┼───────────┼───────────┼───────────┤
│09:00 │  (빈 칸)   │  박예약    │  (빈 칸)   │
│09:30 │  (빈 칸)   │  박예약    │  (빈 칸)   │
│ ...  │           │           │           │
│17:30 │  (빈 칸)   │  (빈 칸)   │  내 예약   │
└──────┴───────────┴───────────┴───────────┘
범례: □ 빈 칸   ■ 다른 사람 예약   ■ 내 예약   ▒ 지난 시간
```

| 영역 | 내용 | 관련 기능 |
|---|---|---|
| 헤더 | 서비스명, 오늘 날짜(`YYYY-MM-DD`), 사용자 선택 드롭다운 | F-01, F-04 |
| 안내 메시지 | 격자 바로 위 한 줄. 성공·실패 문구를 표시한다(4.2장). 다음 동작(클릭·새로고침·사용자 변경)이 있으면 지우거나 새 문구로 바꾼다 | R-01~R-09 |
| 시간표 격자 | 행 18개(30분) × 열 3개(회의실). 칸 색으로 상태 구분, 예약된 칸에는 예약자 이름 표시 | F-01 |
| 빈 칸 클릭 | 즉시 예약 후 격자 갱신 | F-02 |
| 내 예약 칸 클릭 | "예약을 취소할까요?" 확인창 → 확인 시 취소 후 격자 갱신, 취소(닫기) 시 아무 일도 없음 | F-03 |
| 범례 | 칸 색상 설명 | F-01 |

- 지난 시간 칸, 남의 예약 칸은 누르면 서버 요청을 보내지 않는다. 지난 시간 칸을 누르면 "지난 시간은 예약할 수 없습니다", 남의 예약 칸을 누르면 "다른 사람의 예약은 취소할 수 없습니다"를 안내 메시지에 표시한다.
- 화면 갱신: 페이지를 열 때, 예약·취소 요청이 끝날 때(성공이든 실패든), 사용자 드롭다운을 바꿀 때 시간표를 다시 불러온다. 자동 새로고침(주기 조회)은 하지 않는다.
- Phase 2 이후 화면 요소(날짜 이동 버튼, 내 예약 목록, 제목 입력)는 Phase 1 화면에 두지 않는다.

### 4.1 빈 상태

| 상황 | 화면 |
|---|---|
| 오늘 예약이 한 건도 없음 | 정상 응답(200)이며 18행 × 3열 격자를 전부 "빈 칸"으로 그린다. 별도 "없음" 문구는 넣지 않는다 |
| 오늘 모든 칸이 이미 지난 시간(18:00 이후 접속) | 격자는 전부 "지난 시간"으로 표시한다. 안내 메시지에 "오늘 예약 가능한 시간이 끝났습니다"를 표시한다 |
| 사용자 목록이 비어 있음(시드 실패 등) | 드롭다운 자리에 "사용자 없음"을 표시하고 예약·취소를 막는다. 안내 메시지: "사용자 정보를 불러오지 못했습니다" |

### 4.2 오류 상태 — 서버 응답과 화면 문구

모든 오류 응답은 JSON `{"detail": "<아래 문구 그대로>"}` 형식이며, 화면은 `detail` 문구를 안내 메시지에 그대로 표시한다.

| ID | 상황 | 상태 코드 | 문구 | 화면 처리 |
|---|---|---|---|---|
| E-01 | 이미 활성 예약이 있는 칸을 예약(R-01, R-08 의 패배한 요청 포함) | 409 | 이미 예약된 시간입니다 | 메시지 표시 후 시간표 다시 불러옴(그 칸이 남의 예약으로 바뀜) |
| E-02 | 범위 밖·30분 단위가 아닌 `slot_start`(R-02), 존재하지 않는 `room_id` | 422 | 예약할 수 없는 시간입니다 (09:00~17:30, 30분 단위) / 존재하지 않는 회의실입니다 | 메시지 표시 |
| E-03 | 이미 시작된 칸 예약(R-03) | 422 | 지난 시간은 예약할 수 없습니다 | 메시지 표시 후 시간표 다시 불러옴 |
| E-04 | 남의 예약 취소(R-04) | 403 | 본인의 예약만 취소할 수 있습니다 | 메시지 표시 |
| E-05 | 이미 시작된 칸의 내 예약 취소(R-05) | 422 | 이미 시작된 예약은 취소할 수 없습니다 | 메시지 표시 |
| E-06 | 없는 예약 번호 취소 / 이미 취소된 예약 취소 | 404 / 409 | 존재하지 않는 예약입니다 / 이미 취소된 예약입니다 | 메시지 표시 후 시간표 다시 불러옴 |
| E-07 | 요청의 `user_id` 가 없거나 `rr_user` 에 없음 | 422 | 사용자를 확인할 수 없습니다 | 메시지 표시 |
| E-08 | 같은 사용자가 같은 시각에 다른 회의실을 이미 예약함(R-09) | 409 | 같은 시간에 다른 회의실을 이미 예약했습니다 | 메시지 표시 |
| E-09 | `date` 가 오늘이 아님(Phase 1) | 422 | 오늘 날짜만 조회할 수 있습니다 | 메시지 표시 |
| E-10 | 서버 내부 오류 | 500 | 서버 오류가 발생했습니다. 잠시 후 다시 시도하세요 | 메시지 표시. 격자는 마지막으로 그린 상태 유지 |
| E-11 | 서버에 연결 불가(네트워크 오류) | (응답 없음) | 서버에 연결할 수 없습니다 | 메시지 표시. 격자는 마지막으로 그린 상태 유지, 예약·취소 반영 안 함 |

- 성공 문구: 예약 성공 "예약되었습니다", 취소 성공 "예약이 취소되었습니다". 성공 시 상태 코드는 예약 201, 취소 200.
- 오류가 나도 격자를 빈 화면으로 비우지 않는다.

## 5. 데이터 구조

표 이름 접두어는 `rr_`(room reservation)로 한다. 시각은 모두 한국 시간(KST) 기준 문자열이다.

### 5.1 rr_user — 가상 사용자

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| user_id | INTEGER | PK | 사용자 번호 |
| name | TEXT | NOT NULL | 표시 이름(가상, 예: 김다온) |

### 5.2 rr_room — 회의실

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| room_id | INTEGER | PK | 회의실 번호 |
| name | TEXT | NOT NULL, UNIQUE | 회의실 A / B / C |

### 5.3 rr_reservation — 예약

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| reservation_id | INTEGER | PK | 예약 번호 |
| room_id | INTEGER | NOT NULL, FK → rr_room | 회의실 |
| user_id | INTEGER | NOT NULL, FK → rr_user | 예약자 |
| rsv_date | TEXT | NOT NULL | 예약 날짜 `YYYY-MM-DD` |
| slot_start | TEXT | NOT NULL | 칸 시작 시각 `HH:MM` 24시간제 (09:00~17:30, 30분 단위) |
| status | TEXT | NOT NULL, 기본 `active` | `active` / `cancelled` |
| created_at | TEXT | NOT NULL | 생성 시각 `YYYY-MM-DD HH:MM:SS` (KST) |
| cancelled_at | TEXT | NULL | 취소 시각 `YYYY-MM-DD HH:MM:SS` (KST) |

- **부분 유니크 인덱스**: `(room_id, rsv_date, slot_start) WHERE status='active'` — 같은 칸 중복 예약을 DB 차원에서 막는다(R-01). 취소된 행은 이력으로 남고 같은 칸을 다시 예약할 수 있다.

### 5.4 API 개요 (Phase 1)

| 메서드·경로 | 용도 | 기능 | 성공 응답 |
|---|---|---|---|
| `GET /api/users` | 사용자 목록 | F-04 | 200, `[{user_id, name}]` |
| `GET /api/timetable?date=YYYY-MM-DD` | 3개 회의실의 하루 칸 상태. `date` 생략 시 오늘. Phase 1 은 오늘만 허용(E-09) | F-01 | 200, 회의실별 활성 예약 목록(`reservation_id`, `room_id`, `slot_start`, `user_id`, 예약자 `name`) |
| `POST /api/reservations` | 칸 1개 예약. 본문: `room_id`, `slot_start`, `user_id`. 날짜는 서버가 오늘로 정함 | F-02 | 201, 생성된 예약 |
| `DELETE /api/reservations/{id}` | 예약 취소. 본문 또는 쿼리로 `user_id` 포함 | F-03 | 200, 취소된 예약 |

- 오류 응답은 4.2장의 상태 코드·문구를 따른다.
- 시간표 응답에 "지난 시간" 판정은 서버 현재 시각(KST) 기준이며, 화면은 서버가 준 현재 시각(`now`)으로 지난 칸을 그린다(브라우저 시계와 어긋나도 R-03·R-05 판정과 일치하게 하기 위함).

### 5.5 가상 시드 데이터

- rr_user 5명(예: 김다온, 이소프트, 박예약, 최회의, 정시간), rr_room 3개(회의실 A·B·C), 데모용 예약 몇 건. 서버 시작 시 세 표가 비어 있으면 넣는다. 이미 데이터가 있으면 다시 넣지 않는다.
- 데모용 예약은 접속 시각에 따라 이미 지난 칸이 될 수 있다. 이는 오류가 아니다.

## 6. 업무 규칙

### 6.1 시간·수량 단위와 한도

| 항목 | 값 |
|---|---|
| 예약 단위 | 1건 = 칸 1개 = 30분 |
| 운영 시간 | 09:00 ~ 18:00 (칸 시작은 09:00 ~ 17:30) |
| 하루 칸 수 | 회의실 1개당 18칸, 3개 합계 54칸 |
| 시각 표기 | 24시간제 `HH:MM`, 날짜 `YYYY-MM-DD`, 시간대 KST |
| 사용자 1명의 하루 예약 한도 | 한도 없음(단, 같은 시각 다른 회의실 중복은 R-09 로 거절). 최대 18칸 |
| 한 번에 예약하는 칸 수 | 1칸(Phase 1) |
| 동시 접속 | 사용자 5명 이하 기준 |
| 응답 속도 | 시간표 조회 1초 이내(체감 기준), 예약·취소 1초 이내 |

### 6.2 규칙

"시작된 칸"의 경계: 칸의 `slot_start` 가 서버 현재 시각 **이하**이면 시작된 칸이다. 예) 지금이 10:00:00 이면 10:00 칸은 시작된 칸(예약·취소 불가), 10:30 칸은 가능. 10:29:59 에는 10:00 칸도 이미 시작된 칸이고 10:30 칸이 가능하다.

| ID | 규칙 |
|---|---|
| R-01 | 같은 회의실·같은 날짜·같은 칸에는 활성 예약이 1건만 존재한다. 이미 예약된 칸을 예약하면 409 로 거절하고 "이미 예약된 시간입니다"를 알린다. 서로 다른 칸이 시간상 맞닿는 것(예: 09:00 칸 예약과 09:30 칸 예약, 한 칸의 종료 = 다음 칸의 시작)은 충돌이 아니다. 같은 칸을 취소한 뒤 다시 예약하는 것도 충돌이 아니다. |
| R-02 | 예약 가능한 칸은 09:00~17:30 시작 30분 단위 18칸뿐이다(마지막 칸은 18:00 종료). 시작 시각이 17:30 이면 허용, 18:00 이면 거절한다. 08:30·09:15 처럼 범위 밖이거나 30분 단위가 아닌 값은 거절한다. |
| R-03 | 이미 시작된 칸(`slot_start` ≤ 현재 시각)은 예약할 수 없다. 경계는 위 6.2 설명과 같다. |
| R-04 | 예약 취소는 예약한 본인만 할 수 있다. 다른 사용자의 예약 취소 요청은 403 으로 거절한다(서버에서 검사). |
| R-05 | 이미 시작된 칸(`slot_start` ≤ 현재 시각)의 예약은 취소할 수 없다(지난 이력 보존). 시작 전인 내 예약만 취소 가능. |
| R-06 | 취소는 행을 삭제하지 않고 `status='cancelled'`, `cancelled_at` 을 기록한다. 시간표에는 활성 예약만 표시한다. |
| R-07 | 예약 1건 = 칸 1개(30분)이다. 연속 칸이 필요하면 칸마다 예약한다(Phase 1). |
| R-08 | 동시에 두 사람이 같은 칸을 눌러도 먼저 처리된 한 건만 성공하고 나머지는 R-01 과 같이 409 로 거절된다(DB 유니크 인덱스로 보장). |
| R-09 | 같은 사용자는 같은 날짜·같은 칸에 서로 다른 회의실을 동시에 예약할 수 없다. 두 번째 요청은 409 로 거절한다. 같은 사용자가 서로 다른 칸(맞닿는 칸 포함)을 다른 회의실에 잡는 것은 허용한다. |

## 7. 제약 조건

- **기술**: FastAPI + 순수 HTML/JS + SQLite 로 한정한다. 프론트 프레임워크·번들러·외부 CDN 의존을 두지 않는다.
- **배포**: 사내 PC 한 대에서 `uvicorn` 으로 실행하는 단일 프로세스. SQLite 파일 1개.
- **데이터**: 가상 데이터만 사용한다. 실제 이름·이메일·사번 등 개인정보를 저장하지 않는다.
- **인증**: 없음. 사용자 선택은 편의 식별일 뿐 보안 수단이 아니다. 사내망 데모 전제이며, 서버 측 R-04 검사는 요청에 실린 사용자 ID 를 신뢰하는 수준이다(ID 를 위조하면 남의 예약을 취소할 수 있음을 알고 수용한다).
- **시간대**: 서버·화면 모두 KST. 서버 시각 기준으로 R-03, R-05 를 판정한다.
- **브라우저**: 최신 Chrome/Edge 데스크톱. 모바일 최적화는 하지 않는다.
- **규모**: 회의실 3개, 사용자 5명. 성능 목표는 6.1장의 1초 이내 체감 기준 하나만 둔다.

## 8. 범위 밖

이번(Phase 1)에 만들지 않는 것이다. Phase 2·3 항목(F-05~F-08)도 Phase 1 에서는 만들지 않는다.

- 실제 로그인·SSO·권한 관리, 관리자 기능(남의 예약 강제 취소, 회의실 추가·수정)
- 반복(정기) 예약, 예약 변경(시간 이동), 승인 절차
- 알림(이메일·메신저), 캘린더(Outlook/Google) 연동
- 회의실 정보(수용 인원, 장비), 참석자 지정
- 09:00~18:00 외 시간, 주말·휴일 처리, 30분 외 단위
- 오늘 외 날짜 조회·예약(F-05), 내 예약 목록·취소 이력 조회(F-06), 연속 칸 일괄 예약(F-07), 예약 제목(F-08)
- 사용자별 하루 예약 횟수 제한, 대기 목록
- 실시간 화면 동기화(자동 새로고침·푸시). 다른 사람의 변경은 새로고침하거나 동작할 때 반영된다
- 모바일 앱·반응형 디자인, 다국어
- 실제 직원 데이터 연동

## 9. 개발 단계

| Phase | 목표 | 포함 기능 | 비고 |
|---|---|---|---|
| 1 (MVP) | 오늘 시간표 보기·예약·내 예약 취소 | F-01, F-02, F-03, F-04 (전부 Must) | 규칙 R-01~R-09 전부 적용 |
| 2 | 사용 편의 확대 | F-05, F-06, F-07 (Should) | Phase 1 완료 기준 통과 후 착수 |
| 3 | 부가 기능 | F-08 (Could) | 필요 시 |

Phase 1 작업 순서: ① DB 스키마·시드 → ② 조회 API → ③ 예약·취소 API(R-01~R-09, E-01~E-10) → ④ 시간표 화면 → ⑤ 예약·취소 클릭 연결 및 안내 메시지 → ⑥ 완료 기준 점검.

## 10. 완료 기준

Phase 1 이 아래를 모두 통과하면 완료로 본다.

### 조회 (F-01)
- [ ] T-01 첫 화면에 회의실 3개 열 × 09:00~17:30 18행 격자가 보인다.
- [ ] T-02 예약된 칸은 예약자 이름이 보이고, 내 예약은 다른 색으로 구분된다.
- [ ] T-03 현재 시각 이전에 시작한 칸은 "지난 시간"으로 구분되어 눌러도 서버 요청이 나가지 않는다.
- [ ] T-18 예약이 0건인 날 격자 54칸이 전부 빈 칸으로 보이고 오류 문구가 없다(4.1장).
- [ ] T-19 `date` 에 오늘이 아닌 날짜를 주고 시간표를 조회하면 422 와 "오늘 날짜만 조회할 수 있습니다"가 온다(E-09).

### 예약 (F-02)
- [ ] T-04 빈 칸을 누르면 격자에 즉시 내 예약으로 표시되고(201, "예약되었습니다"), 새로고침해도 유지된다.
- [ ] T-05 이미 예약된 칸을 API 로 다시 예약하면 409 와 "이미 예약된 시간입니다"가 오고 화면에 안내 메시지가 나온다(R-01).
- [ ] T-06 범위 밖·단위 위반 시각(08:30, 18:00, 09:15)으로 예약 요청하면 422 로 거절되고, 17:30 은 성공한다(R-02).
- [ ] T-07 시작된 칸 예약 요청은 422 로 거절된다. 현재 시각과 정확히 같은 `slot_start` 칸도 거절되고, 다음 칸은 성공한다(R-03).
- [ ] T-08 같은 칸에 동시 요청 두 건을 보내면 한 건(201)만 성공하고 나머지는 409 이다(R-08).
- [ ] T-20 09:00 칸을 예약한 뒤 같은 회의실 09:30 칸을 예약하면 둘 다 성공한다(맞닿는 칸은 충돌 아님, R-01).
- [ ] T-21 같은 사용자가 같은 시각에 다른 회의실을 예약하면 409 와 "같은 시간에 다른 회의실을 이미 예약했습니다"가 온다(R-09).
- [ ] T-22 존재하지 않는 `user_id` 로 예약·취소를 요청하면 422 와 "사용자를 확인할 수 없습니다"가 온다(E-07).

### 취소 (F-03)
- [ ] T-09 내 예약 칸을 누르고 확인하면 빈 칸으로 돌아오고(200, "예약이 취소되었습니다"), 새로고침해도 유지된다. 확인창에서 닫으면 아무 변화가 없다.
- [ ] T-10 다른 사용자의 예약을 취소하는 요청은 403 과 "본인의 예약만 취소할 수 있습니다"로 거절된다(R-04). 화면 우회 없이 API 직접 호출로도 확인한다.
- [ ] T-11 이미 시작된 칸의 내 예약 취소는 422 로 거절된다(R-05).
- [ ] T-12 취소한 칸은 DB 에 `cancelled` 로 남고, 같은 칸을 다시 예약할 수 있다(R-06).
- [ ] T-23 이미 취소된 예약을 다시 취소하면 409, 없는 번호를 취소하면 404 이다(E-06).

### 사용자 선택 (F-04)
- [ ] T-13 사용자 드롭다운을 바꾸면 "내 예약" 표시가 바뀐 사용자 기준으로 갱신된다.
- [ ] T-14 선택한 사용자가 새로고침 후에도 유지된다. 저장값이 없으면 첫 번째 사용자가 선택된다.

### 오류 표시
- [ ] T-24 서버를 끈 상태에서 칸을 누르면 "서버에 연결할 수 없습니다"가 안내 메시지에 나오고 격자는 비워지지 않는다(E-11).
