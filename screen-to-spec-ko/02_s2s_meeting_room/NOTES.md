- **A 가 떨어진 이유는 '틀려서' 가 아니라 '부를 수 없어서'.** 보고문대로라면 셋 다 겹침 거부 · 30분 단위 · 본인만 취소를 구현했다. 그런데 API 가 셋 다 다르다 — `room_id` 가 숫자(A1 · A2, 422), 필드가 `day · start_min`(A1 · A2) 또는 `user_id · start_slot · slots`(A3), 경로가 `/api/bookings`(A3). 테스트가 PRD 의 몸체로 부르면 422 · 404. **계약이 없으면 규칙을 지켰는지 확인할 방법이 없다.**
- **A 가 스스로 정한 것 (셋 다):** 회의 제목을 **필수**로(서버가 400 "회의 제목을 입력하세요"), 지난 시간 예약 막기, 다음 예약 직전까지만 길이 선택(A1 · A2) / 최대 4시간(A3; PRD 는 2시간). 시간표 칸 수도 다르다 — A1 62(rowspan 으로 합침), A2 36, A3 54.
- **B 와 C 는 DoD 가 같다.** 여섯 번 모두 PRD 에 없는 `GET /api/users` 를 추가했다 — **PRD 가 사용자 선택 상자의 데이터 출처를 빠뜨렸기 때문**(우리 실수, PRD.md 5 에 메모). 차이는 그걸 어디에 적었나:
  - C 셋 다 4줄 보고의 'PRD 와 다르게 한 것' 칸에 `/api/users` 와 직접 정한 거부 문구(C1 2개 · C3 2개)를 적었다.
  - B 는 보고문 중간 문단에. B2 는 자기 테스트를 새로 쓰고 **"PRD 가 말하는 9개 완료 기준 테스트는 아직 돌려 보지 못했습니다"** 라고 솔직히 적음. B3 는 `httpx` 를 PC 에 설치(TestClient 용).
- 시간: 회당 60~111초. 비용은 API 정가 기준(구독 포함).

## 실수 · 주의

- A3 빌더가 확인용 uvicorn 을 끄지 않아 작업 폴더 이동(`shutil.move`)이 `server.log` 잠김으로 실패 → `run_build.py` 를 복사 + 서버 정리(`kill_servers`) + 지울 수 있는 만큼 삭제로 바꿈. 남은 서버는 `tools/kill_servers.py`.
- `grade_run.py` 의 허용 라우트와 `results_table.py` 의 범위 밖 패턴이 1편 전용이었다 → 편마다 `grading.json`(allowed_routes · extra_patterns). 패턴 `title` · `week|month` 는 `<title>` 과 날짜 계산에 오탐 → 좁힘. 범위 밖 판단은 코드 패턴 + 사람이 보고문으로 확인.
- `run_build.py` 수정 중 `def prepare` 머리 한 줄이 지워져 B · C 재실행이 바로 죽음(NameError) → 수정. 빌드 스크립트를 고치면 `python -c` 말고 작은 구문 검사 도구로 확인할 것.

## 숫자의 뜻

- 1편(3/9)보다 더 낮은 1/9 — 화면이 아니라 **동작(API)** 을 검사하는 편이라서. 한 줄 요청의 앱은 겉으로는 다 된다(겹치면 막고, 남의 것은 못 지운다). 그러나 어떤 이름으로 어떤 값을 보내면 어떤 코드로 거부하는지가 없으니, 테스트도 다른 시스템도 그 앱을 부를 수 없다.
- PRD 의 빈틈은 AI 가 메운다 — 여섯 번 다 같은 자리(`/api/users`). 메운 것을 **정해진 칸에 적게** 하는 것이 CLAUDE.md 의 값.
