# 회의실 예약 웹앱 PRD

- 조직: 다온소프트 (사내용)
- 문서 버전: 0.2 (점검 반영 초안)
- 작성일: 2026-10-30

## 1. 개요

### 1.1 배경
회의실 예약 현황을 한눈에 확인하고 바로 예약·취소할 수 있는 사내 웹앱이 필요하다.

### 1.2 목표
- 회의실 3개의 하루 시간표(09:00~18:00, 30분 단위)를 한 화면에 보여준다.
- 빈 칸을 눌러 예약한다.
- 내 예약은 직접 취소할 수 있다.

### 1.3 기술 스택
| 영역 | 선택 |
|---|---|
| 백엔드 | Python FastAPI |
| 프론트엔드 | 순수 HTML + JavaScript (프레임워크·빌드 도구 없음) |
| 저장소 | SQLite (단일 파일) |

### 1.4 데이터 원칙
모든 데이터(사용자, 회의실, 예약)는 가상 데이터만 사용한다. 실제 직원 정보는 넣지 않는다.

## 2. 사용자

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원 | 다온소프트 사내 구성원 (가상 사용자) | 시간표 조회, 본인 명의로 예약, 본인 예약 취소 |

- 관리자 역할은 두지 않는다. (8. 범위 밖)
- 로그인 대신 화면 상단에서 "나"를 가상 사용자 목록 중에서 고른다. 이 선택이 "내 예약"의 기준이다. 인증이 아니라 식별용이다.
- 예약·취소 요청에는 "나"의 user_id를 함께 보낸다. 서버는 이 값을 "요청자"로 보고 6.2의 권한 규칙을 검사한다.

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could, W=Won't(이번 범위 밖). Phase 1에는 Must만 포함한다.

| F-번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F-01 | 가상 사용자 선택 ("나" 지정) | M | 1 |
| F-02 | 회의실 3개 × 09:00~18:00(30분 단위 18칸) 하루 시간표 표시 (기본 오늘) | M | 1 |
| F-03 | 칸 상태 구분 표시: 빈 칸 / 내 예약 / 타인 예약 / 지난 시간 | M | 1 |
| F-04 | 빈 칸 클릭 → 예약 입력(종료 시각, 제목) → 예약 확정 | M | 1 |
| F-05 | 내 예약 클릭 → 취소 확인 → 취소 | M | 1 |
| F-06 | 규칙 위반 시 사유 메시지 표시 (중복, 지난 시간 등) | M | 1 |
| F-07 | 가상 초기 데이터(사용자·회의실·예약 예시) 적재 | M | 1 |
| F-08 | 날짜 이동 (이전/다음 날, 날짜 선택) | S | 2 |
| F-09 | 내 예약 목록 화면 | S | 2 |
| F-10 | 예약 제목·시간 수정 | C | 3 |
| F-11 | 반복 예약 | C | 3 |
| F-12 | 알림(메일·메신저) | W | - |

## 4. 화면 구성

Phase 1은 한 화면(시간표)과 두 개의 대화상자로 구성한다.

### 4.1 시간표 화면
- 상단: 제목, 날짜(오늘 고정 표시), "나" 선택 드롭다운(F-01)
- 본문: 세로축은 시간(09:00~17:30 시작 칸 18개), 가로축은 회의실 3개(F-02)
- 칸 표현(F-03, 색뿐 아니라 글자로도 구분)
  - 빈 칸: 흰색, 클릭 가능
  - 내 예약: 강조색, 제목 표시, 클릭 시 취소 대화상자
  - 타인 예약: 회색, 예약자 이름·제목 표시, 클릭 불가
  - 지난 시간: 흐리게, "지난 시간" 글자 표시, 클릭 불가
- 칸 상태 우선순위: 예약이 있으면 예약 상태(내/타인)가 우선이고, 예약이 없는 칸만 지난 시간 여부를 따진다. 이미 끝난 내 예약 칸도 "내 예약"으로 보이되 취소는 R-07로 거절된다.
- 지난 시간 판정은 R-03과 같은 기준(6.1)을 쓴다.

### 4.2 예약 대화상자 (F-04)
- 표시: 회의실, 날짜, 시작 시각(칸에서 자동 입력, 수정 불가)
- 입력: 종료 시각(30분 단위 선택, 시작+30분 ~ min(시작+2시간, 18:00) 범위만 선택지로 제공), 제목(필수, 최대 50자, 입력창에서 50자 초과 입력 차단)
- 버튼: 예약 / 닫기

### 4.3 취소 확인 대화상자 (F-05)
- 표시: 회의실, 시간, 제목
- 버튼: 예약 취소 / 닫기

### 4.4 오류 표시 (F-06)
- 대화상자 안에 사유를 한 줄로 표시한다. 문구는 6.3의 표 그대로 쓴다.
- 오류가 나면 대화상자는 닫히지 않고 입력값을 유지한다. 사용자가 고쳐서 다시 시도하거나 "닫기"를 누른다.
- 예약·취소 성공 시 대화상자를 닫고 시간표를 다시 불러온다.
- 겹침(409)·종료됨(409)·찾을 수 없음(404) 오류는 다른 사람이 먼저 바꾼 상태이므로, 오류 문구를 보여 준 뒤 뒤쪽 시간표도 함께 다시 불러와 최신 상태로 맞춘다.

### 4.5 빈 상태 · 불러오기 실패 (시간표 화면)
| 상황 | 화면 표시 |
|---|---|
| 오늘 예약이 0건 | 오류가 아니다. 54칸(3실 × 18칸) 전부 빈 칸(또는 지난 시간)으로 보인다. 별도 안내 문구는 두지 않는다. |
| 회의실이 0개 또는 사용자가 0명 (초기 데이터 적재 실패) | 시간표 대신 "회의실 또는 사용자 데이터가 없습니다. 서버 초기 데이터를 확인하세요." 한 줄을 표시한다. |
| 시간표 불러오기 실패 (서버 응답 없음·5xx) | 시간표 자리에 "시간표를 불러오지 못했습니다. 잠시 후 다시 시도하세요." 한 줄과 [다시 불러오기] 버튼을 표시한다. 예약 입력은 막는다. |
| 하루의 모든 칸이 지난 시간 (18:00 이후 접속) | 오류가 아니다. 모든 빈 칸이 "지난 시간"으로 보이고, 기존 예약만 표시된다. |

## 5. 데이터 구조

표 이름 접두어는 `mr_` (meeting room)이다.

### 5.1 mr_users (가상 사용자)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| user_id | INTEGER PK | 사용자 ID |
| name | TEXT NOT NULL | 가상 이름 |

### 5.2 mr_rooms (회의실)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| room_id | INTEGER PK | 회의실 ID |
| name | TEXT NOT NULL UNIQUE | 예: 회의실 A, B, C |

### 5.3 mr_reservations (예약)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| reservation_id | INTEGER PK | 예약 ID |
| room_id | INTEGER NOT NULL | mr_rooms 참조 |
| user_id | INTEGER NOT NULL | mr_users 참조 (예약자) |
| rsv_date | TEXT NOT NULL | 예약 날짜 (YYYY-MM-DD) |
| start_time | TEXT NOT NULL | 시작 (24시간제 HH:MM, 예 09:30) |
| end_time | TEXT NOT NULL | 종료 (24시간제 HH:MM, 시작보다 뒤. 마지막 칸의 종료는 18:00) |
| title | TEXT NOT NULL | 예약 제목 (앞뒤 공백 제거 후 저장, 1~50자) |
| created_at | TEXT NOT NULL | 생성 시각 (KST, YYYY-MM-DD HH:MM:SS) |

- 취소는 행을 삭제하는 방식으로 처리한다. (취소 이력은 Phase 1에서 보관하지 않음)
- (room_id, rsv_date) 인덱스는 조회 속도용이다. 중복 방지는 인덱스가 아니라 R-08의 트랜잭션 검사로 보장한다.

## 6. 업무 규칙

### 6.1 규칙 목록

| R-번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00~18:00이며, 시작·종료 시각은 30분 단위(:00 또는 :30)다. 시작은 09:00~17:30, 종료는 09:30~18:00이다. 종료가 18:00인 예약은 허용하고, 18:00을 넘는 것은 거절한다. |
| R-02 | 같은 회의실·같은 날짜에서 시간 구간이 겹치는 예약은 만들 수 없다. 구간은 [시작, 종료)로 본다. 따라서 앞 예약 종료 = 뒤 예약 시작인 맞닿음은 허용하고, 1분이라도 겹치면 거절한다. 다른 회의실, 다른 날짜의 예약끼리는 겹침으로 보지 않는다. 같은 사람이 같은 시간에 서로 다른 회의실을 잡는 것은 허용한다. |
| R-03 | 현재 시각(KST, 분 단위로 내림)보다 시작 시각이 이전인 칸은 새로 예약할 수 없다. 시작 시각이 현재 시각과 같으면 허용한다. 예: 지금이 10:10이면 10:00 시작은 거절(이미 시작함), 10:30 시작은 허용. 같은 기준으로 화면의 "지난 시간"을 정한다. |
| R-04 | 한 번의 예약은 최소 30분, 최대 2시간(120분)이다. 정확히 30분, 정확히 120분은 허용하고 그 밖은 거절한다. (가정: 확정 필요) |
| R-05 | 제목은 앞뒤 공백을 제거한 뒤 1자 이상 50자 이하(글자 수 기준, 한글·영문 모두 1자)다. 공백만 있으면 거절한다. (가정: 확정 필요) |
| R-06 | 예약자 본인만 해당 예약을 취소할 수 있다. 요청자 user_id가 예약의 user_id와 다르면 서버가 거절한다. |
| R-07 | 종료 시각이 현재 시각(분 단위로 내림)보다 뒤인 예약만 취소할 수 있다. 진행 중이거나 시작 전이면 취소 가능하고, 종료 시각이 현재 시각과 같거나 이전이면(이미 끝남) 거절한다. (가정: 확정 필요) |
| R-08 | 동시에 같은 칸을 예약하려 하면 먼저 처리된 한 건만 성공하고, 나머지는 R-02 위반으로 거절한다. 검사와 저장은 하나의 트랜잭션에서 수행한다. |
| R-09 | 모든 규칙 검사는 서버에서 수행한다. 화면의 클릭 제한은 편의 기능일 뿐 규칙의 근거가 아니다. |
| R-10 | Phase 1의 예약 날짜는 오늘만 허용한다. 오늘이 아닌 날짜를 보내면 거절한다. (Phase 2의 F-08에서 완화) |
| R-11 | 예약은 요청자 본인 명의로만 만들 수 있다. 서버는 요청자 user_id가 mr_users에 있는지, room_id가 mr_rooms에 있는지 확인하고, 없으면 거절한다. |
| R-12 | 같은 규칙에 여러 건이 걸리면 아래 순서로 검사하고 처음 걸린 것 하나만 알린다. 예약: R-11(사용자·회의실) → R-10(날짜) → R-01(단위·범위) → R-04(길이) → R-05(제목) → R-03(지난 시간) → R-02(겹침). 취소: 예약 존재 → R-06(권한) → R-07(종료 여부). |

### 6.2 권한 (누가 무엇을 할 수 있나)

| 동작 | 누가 | 서버 검사 | 거절 시 |
|---|---|---|---|
| 시간표 조회 | 모든 직원 | 없음 | - |
| 예약 만들기 | 직원 본인 명의로만 | 요청자 user_id가 존재하는 사용자인지 (R-11). 요청 본문으로 다른 사람 명의 예약자를 지정할 수 없다. 예약자는 항상 요청자다. | 422 |
| 예약 취소 | 예약자 본인만 | 요청자 user_id = 예약의 user_id (R-06) | 403 |
| 타인 예약 취소 | 아무도 불가 (관리자 없음) | 위와 같음 | 403 |

- 화면이 타인 예약을 클릭 불가로 막더라도 서버가 같은 검사를 다시 한다. (R-09)
- "나" 선택은 인증이 아니므로 user_id를 바꿔 보내면 남의 예약도 취소할 수 있다. 이는 알려진 한계이며 7. 제약 조건과 8. 범위 밖에 적는다.

### 6.3 거절 응답 (상태 코드 · 문구)

응답 본문은 `{"detail": "<문구>"}` 형식이고, 화면은 이 문구를 대화상자에 그대로 보여 준다.

| 상황 | 규칙 | 상태 코드 | 문구 |
|---|---|---|---|
| 사용자 미선택 · 존재하지 않는 사용자 | R-11 | 422 | 사용자를 선택해 주세요. |
| 존재하지 않는 회의실 | R-11 | 422 | 존재하지 않는 회의실입니다. |
| 오늘이 아닌 날짜 · 날짜 형식 오류 | R-10 | 422 | 오늘 날짜만 예약할 수 있습니다. |
| 시각 형식 오류 · 30분 단위 아님 · 09:00~18:00 밖 · 종료가 시작과 같거나 앞 | R-01 | 422 | 예약은 09:00~18:00 사이 30분 단위로만 가능합니다. |
| 30분 미만 또는 2시간 초과 | R-04 | 422 | 예약 시간은 30분 이상 2시간 이하여야 합니다. |
| 제목이 비었거나 공백뿐 | R-05 | 422 | 제목을 입력해 주세요. |
| 제목이 50자 초과 | R-05 | 422 | 제목은 50자 이하로 입력해 주세요. |
| 이미 시작한 시간 | R-03 | 422 | 이미 지난 시간은 예약할 수 없습니다. |
| 다른 예약과 겹침 (동시 요청에서 늦게 처리된 건 포함) | R-02, R-08 | 409 | 이미 예약된 시간과 겹칩니다. |
| 취소할 예약이 없음 (이미 취소됨 포함) | - | 404 | 예약을 찾을 수 없습니다. 이미 취소되었을 수 있습니다. |
| 타인 예약 취소 | R-06 | 403 | 본인의 예약만 취소할 수 있습니다. |
| 이미 종료된 예약 취소 | R-07 | 409 | 이미 종료된 예약은 취소할 수 없습니다. |
| 서버 내부 오류 · 저장소 오류 | - | 500 | 처리 중 오류가 발생했습니다. 잠시 후 다시 시도하세요. |

- 성공 응답: 예약 생성 201(생성된 예약 내용 포함), 취소 200, 시간표 조회 200.
- 시간표 조회 결과가 비어도(예약 0건) 200과 빈 목록을 돌려준다. 404를 쓰지 않는다.
- 거절된 요청은 데이터를 바꾸지 않는다. (부분 저장 없음)

## 7. 제약 조건

- 기술: Python FastAPI + 순수 HTML/JS + SQLite. 외부 프레임워크·빌드 도구·별도 DB 서버를 쓰지 않는다.
- 데이터: 가상 데이터만 사용한다. 실제 개인정보를 저장하지 않는다.
- 인증: 로그인이 없다. "나" 선택은 보안 수단이 아니므로, 사내 망·시연 용도로만 쓴다. R-06은 이 선택을 신뢰하는 전제의 규칙이다. 요청 user_id를 위조하면 서버가 막을 수 없다는 점을 알고 쓴다.
- 규모: 회의실 3개, 동시 사용자 수십 명(50명) 이하. 하루 최대 54칸(3실 × 18칸). 단일 서버·단일 SQLite 파일.
- 시간대: 서버 로컬 시간(KST) 기준 하나만 사용한다. "현재 시각"은 서버 시계로, 분 단위로 내림해 비교한다. 브라우저 시계는 쓰지 않는다.
- 응답 시간: 시간표 조회와 예약·취소는 각각 1초 이내에 응답하는 것을 목표로 한다.
- 초기 데이터 규모: 회의실 3개, 사용자 5명, 예약 5건 안팎(오늘 날짜 기준, 겹침 없음).
- 브라우저: 최신 데스크톱 브라우저 (Chrome, Edge). 모바일 최적화는 하지 않는다.
- Phase 1에는 Must 기능만 넣는다.

## 8. 범위 밖

- 로그인·권한 관리·관리자 기능 (타인 예약 강제 취소 포함)
- user_id 위조를 막는 보안 장치(토큰, 세션, 비밀번호)
- 날짜 이동(F-08), 내 예약 목록(F-09)은 Phase 1 범위 밖 (Phase 2). Phase 1은 오늘 외 날짜 예약도 하지 않는다. (R-10)
- 예약 수정(F-10), 반복 예약(F-11) (Phase 3)
- 알림 발송 (F-12)
- 회의실 추가·삭제·정보 관리 화면, 사용자 추가·삭제 화면
- 외부 캘린더(Outlook, Google 등) 연동
- 참석자 지정, 장비·좌석 예약, 승인 절차
- 여러 회의실·여러 칸을 한 번에 묶어 예약하기, 하룻밤을 넘기는 예약
- 같은 사용자의 동시간 중복 예약 제한 (다른 회의실이면 허용)
- 취소 이력·통계·리포트
- 모바일 전용 화면, 다국어, 시간대 선택
- 서버 이중화·백업·장애 복구

## 10. 완료 기준

Phase 1 완료 기준이다. 모두 체크되면 Phase 1이 끝난다.

- [ ] T-01: 서버를 처음 실행하면 `mr_users`, `mr_rooms`, `mr_reservations` 표가 만들어지고 가상 데이터(회의실 3개, 사용자 5명, 예약 5건 안팎)가 들어간다. 서버를 다시 실행해도 초기 데이터가 중복 적재되지 않는다. (F-07)
- [ ] T-02: 시간표에 회의실 3개와 09:00~18:00의 30분 칸 18개가 모두 보인다. (F-02)
- [ ] T-03: 빈 칸, 내 예약, 타인 예약, 지난 시간이 서로 구분되어 보인다. (F-03)
- [ ] T-04: "나"를 바꾸면 내 예약과 타인 예약의 표시가 바뀐다. (F-01, F-03)
- [ ] T-05: 빈 칸을 눌러 종료 시각과 제목을 입력하면 예약이 저장되고(201) 시간표에 즉시 반영된다. (F-04)
- [ ] T-06: 이미 예약된 시간과 겹치게 예약하면 409와 "이미 예약된 시간과 겹칩니다."가 대화상자에 표시된다. 맞닿는 예약(앞 종료 = 뒤 시작)은 성공한다. (R-02, F-06)
- [ ] T-07: 지난 시간 칸은 예약할 수 없다. 서버에 직접 요청해도 422로 거절된다. 시작 시각이 현재 시각과 같은 칸은 예약된다. (R-03, R-09)
- [ ] T-08: 제목이 비었거나 공백뿐이거나 51자 이상이면, 예약 길이가 30분 미만 또는 2시간 초과이면, 18:00을 넘기면 422로 거절된다. 제목 50자·길이 30분·길이 2시간은 성공한다. (R-01, R-04, R-05)
- [ ] T-09: 내 예약을 누르고 확인하면 취소되고(200) 해당 칸이 빈 칸으로 돌아온다. (F-05)
- [ ] T-10: 타인 예약은 화면에서 취소할 수 없고, 서버에 직접 취소 요청을 보내도 403으로 거절된다. (R-06, R-09)
- [ ] T-11: 종료 시각이 지난 예약을 취소하면 409로 거절된다. 진행 중인 예약은 취소된다. (R-07)
- [ ] T-12: 같은 칸에 대한 두 요청이 거의 동시에 들어오면 한 건만 저장되고 나머지는 409를 받는다. (R-08)
- [ ] T-13: 서버를 껐다 켜도 예약 내용이 유지된다. (SQLite 영속성)
- [ ] T-14: 실제 개인정보 없이 가상 데이터만 들어 있다. (7. 제약 조건)
- [ ] T-15: 이미 취소된(없는) 예약을 취소하면 404와 "예약을 찾을 수 없습니다. 이미 취소되었을 수 있습니다."가 표시되고 시간표가 최신으로 다시 불러와진다. (6.3, 4.4)
- [ ] T-16: 오늘이 아닌 날짜, 존재하지 않는 회의실·사용자로 예약 요청을 보내면 422로 거절되고 데이터가 바뀌지 않는다. (R-10, R-11)
- [ ] T-17: 오늘 예약이 0건이어도 시간표가 오류 없이 표시된다. 서버를 멈춘 채 화면을 열면 "시간표를 불러오지 못했습니다. 잠시 후 다시 시도하세요."와 [다시 불러오기] 버튼이 나온다. (4.5)
