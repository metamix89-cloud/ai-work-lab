# 다온소프트 회의실 예약 웹앱 PRD

- 문서 상태: 초안 v0.1 (2026-10-30)
- 표 이름 접두어: `mr_` (meeting room)

## 1. 개요

### 1.1 배경과 목적
다온소프트 사내 회의실 3개를 구두·메신저로 잡다 보니 중복 예약과 "지금 어디 비었나" 확인 비용이 생긴다. 하루 시간표를 한 화면에 보여 주고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있는 최소한의 웹앱을 만든다.

### 1.2 한 줄 요약
회의실 3개 × 09:00~18:00(30분 단위) 시간표를 보고, 빈 칸을 눌러 예약하고, 내 예약을 취소한다.

### 1.3 성공 기준
- 시간표를 열고 10초 안에 예약을 끝낼 수 있다.
- 같은 회의실·같은 시간에 예약이 둘 이상 생기지 않는다.
- 남의 예약은 취소할 수 없다.

### 1.4 기술 스택
| 영역 | 선택 |
|---|---|
| 백엔드 | Python FastAPI |
| 프런트엔드 | 순수 HTML / CSS / JavaScript (프레임워크·빌드 도구 없음) |
| 데이터베이스 | SQLite (단일 파일) |
| 데이터 | 가상 데이터만 사용 (실제 직원·실제 회의 정보 금지) |

## 2. 사용자

| 구분 | 설명 | 주요 행동 |
|---|---|---|
| 직원 (유일한 역할) | 다온소프트 사내 구성원. 모두 같은 권한 | 시간표 조회, 예약 생성, 본인 예약 취소 |

- 관리자 역할은 두지 않는다 (8장 참고).
- 가정: 사용자는 PC 브라우저(최신 Chrome/Edge)로 사용한다.
- 가정: 로그인 대신 화면 상단에서 "내 이름"을 고른다 (7장 제약 참고).

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could, W=Won't(이번 범위 밖). **Phase 1에는 Must만 포함한다.**

| 번호 | 기능 | 설명 | MoSCoW | Phase |
|---|---|---|---|---|
| F-01 | 오늘 시간표 조회 | 회의실 3개를 열, 09:00~18:00을 30분 단위 행(18칸)으로 보여 준다 | M | 1 |
| F-02 | 예약 현황 표시 | 예약된 칸에 제목·예약자 이름을 표시하고, 빈 칸/예약됨/내 예약을 색으로 구분한다 | M | 1 |
| F-03 | 사용자 선택 | 가상 직원 목록에서 "나"를 고른다. 선택은 브라우저에 기억된다 | M | 1 |
| F-04 | 빈 칸 클릭 예약 | 빈 칸을 누르면 예약 창이 뜨고, 제목과 종료 시각을 정해 예약한다 | M | 1 |
| F-05 | 중복 예약 방지 | 겹치는 시간의 예약은 서버가 거절하고 이유를 알려 준다 | M | 1 |
| F-06 | 내 예약 취소 | 내 예약 칸을 누르면 취소 확인 후 취소한다. 남의 예약은 취소 불가 | M | 1 |
| F-07 | 날짜 이동 | 이전/다음 날, 오늘로 돌아가기 | S | 2 |
| F-08 | 내 예약 목록 | 오늘 이후 내 예약을 한 목록으로 모아 본다 | S | 2 |
| F-09 | 예약 수정 | 제목·시간 변경 (Phase 1에서는 취소 후 재예약으로 대체) | C | 3 |
| F-10 | 자동 새로고침 | 일정 간격으로 시간표를 다시 불러온다 | C | 3 |
| F-11 | 반복 예약 | 매주 같은 시간 등 | W | - |
| F-12 | 알림 | 메일·메신저 알림 | W | - |

## 4. 화면 구성

단일 페이지 1개로 구성한다.

### 4.1 상단 바
- 앱 제목 "회의실 예약", 오늘 날짜 표시
- 사용자 선택 드롭다운 (F-03). 미선택 상태에서는 예약/취소 동작이 막히고 안내 문구를 보여 준다

### 4.2 시간표 (F-01, F-02)
```
        | 회의실 A | 회의실 B | 회의실 C |
 09:00  |  (빈)    | 주간회의 |  (빈)    |
 09:30  |  (빈)    | 김가온   |  (빈)    |
  ...
 17:30  |  (빈)    |  (빈)    |  (빈)    |
```
- 행 18개(09:00~17:30 시작), 열 3개. 시간 라벨은 왼쪽, 회의실 이름은 위쪽에 고정
- 칸 상태: **빈 칸**(클릭 가능) / **예약됨**(남의 예약, 제목+이름 표시) / **내 예약**(강조색) / **지난 시간**(회색, 클릭 불가)
- 긴 예약은 시작 칸에 제목을 쓰고 이어지는 칸은 같은 색으로 잇는다

### 4.3 예약 창 (F-04)
- 입력: 회의실(자동), 시작 시각(자동, 수정 불가), 종료 시각(선택, 30분 단위), 제목(필수)
- 버튼: 예약 / 닫기
- 오류(겹침, 입력 오류)는 창 안에 빨간 문구로 표시

### 4.4 취소 확인 창 (F-06)
- 내용: 회의실·시간·제목 표시 + "이 예약을 취소할까요?"
- 버튼: 예약 취소 / 닫기
- 남의 예약 칸을 누르면 상세만 보여 주고 취소 버튼은 숨긴다

## 5. 데이터 구조

SQLite, 표 이름은 모두 `mr_` 로 시작한다. 날짜는 `YYYY-MM-DD`, 시각은 `HH:MM` 문자열(24시간제)로 저장한다.

### 5.1 mr_users (가상 직원)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| name | TEXT NOT NULL | 가상 이름 (예: 김가온) |
| dept | TEXT | 가상 부서명 |

### 5.2 mr_rooms (회의실)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| name | TEXT NOT NULL UNIQUE | 회의실 A / B / C |
| capacity | INTEGER | 정원 (표시용) |

### 5.3 mr_reservations (예약)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| room_id | INTEGER NOT NULL | → mr_rooms.id |
| user_id | INTEGER NOT NULL | → mr_users.id (예약자) |
| rsv_date | TEXT NOT NULL | 예약 날짜 |
| start_time | TEXT NOT NULL | 시작 (포함) |
| end_time | TEXT NOT NULL | 종료 (미포함) |
| title | TEXT NOT NULL | 회의 제목 |
| status | TEXT NOT NULL | `active` / `cancelled` |
| created_at | TEXT NOT NULL | 생성 시각 |
| cancelled_at | TEXT | 취소 시각 |

- 취소는 행을 지우지 않고 `status='cancelled'` 로 바꾼다 (이력 보존). 겹침 검사는 `active` 만 대상으로 한다.
- 인덱스: `(room_id, rsv_date, status)`.

### 5.4 초기(가상) 데이터
- mr_users 5명, mr_rooms 3개, mr_reservations 오늘 날짜로 몇 건. 모두 실존하지 않는 가상 값.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00 이상 18:00 이하이며, 시작·종료는 모두 정각 또는 30분 단위여야 한다 |
| R-02 | 종료 시각은 시작 시각보다 늦어야 한다 (최소 30분) |
| R-03 | 같은 회의실에서 `active` 예약끼리 시간이 겹치면 안 된다. 겹침 기준은 `새 시작 < 기존 종료` 그리고 `새 종료 > 기존 시작`이며, 끝과 시작이 맞닿는 것(예: 10:00 종료 / 10:00 시작)은 허용한다 |
| R-04 | 이미 지난 시간(현재 시각 이전에 시작하는 칸)은 예약할 수 없다 |
| R-05 | 제목은 필수이며 공백 제외 1자 이상 30자 이하이다 |
| R-06 | 예약자 본인만 자기 예약을 취소할 수 있다. 판정은 서버가 한다 |
| R-07 | 이미 지난 예약(종료 시각이 현재 이전)은 취소할 수 없다 |
| R-08 | 한 번에 예약할 수 있는 최대 길이는 2시간이다 (가정: 독점 방지용. 사용자 확인 필요) |
| R-09 | 겹침 검사와 저장은 한 트랜잭션에서 처리해, 동시에 눌러도 중복이 생기지 않게 한다 |

## 7. 제약 조건

- **스택 고정**: FastAPI + 순수 HTML/JS + SQLite. 프런트 프레임워크·번들러·외부 CDN 의존 없음.
- **가상 데이터만**: 실제 직원 이름·이메일·회의 내용을 넣지 않는다.
- **인증 없음(알려진 한계)**: 로그인 대신 이름 선택 방식이므로 다른 사람인 척하는 것을 기술적으로 막지 못한다. R-06은 "요청에 담긴 user_id" 기준으로 판정하며, 실사용 전에는 사내 로그인 연동이 필요하다. 가상 데이터 데모 범위에서는 허용한다.
- **서버 시각 기준**: "지난 시간" 판정은 서버 시계로 한다 (사용자 PC 시계 조작 방지).
- **단일 서버·단일 SQLite 파일**: 동시 사용자 수십 명 이하를 가정한다.
- **API 개요** (구현 시 확정):
  - `GET /api/users`, `GET /api/rooms`
  - `GET /api/reservations?date=YYYY-MM-DD`
  - `POST /api/reservations`
  - `POST /api/reservations/{id}/cancel`
  - 오류는 HTTP 4xx와 한국어 사유 메시지로 돌려준다 (겹침 409, 입력 오류 422, 권한 403).

## 9. 개발 단계

| Phase | 목표 | 포함 기능 | 비고 |
|---|---|---|---|
| 1 | 핵심 흐름 완성: 보기 → 예약 → 취소 | F-01 ~ F-06 (**Must만**) | 오늘 날짜만 다룬다 |
| 2 | 편의 | F-07 날짜 이동, F-08 내 예약 목록 | Should |
| 3 | 다듬기 | F-09 예약 수정, F-10 자동 새로고침 | Could |

Phase 1 안에서의 작업 순서: DB 표·초기 데이터 → 조회 API → 예약/취소 API(규칙 R-01~R-09) → 시간표 화면 → 예약/취소 창 → 검증.
