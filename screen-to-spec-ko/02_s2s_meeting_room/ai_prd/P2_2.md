# 회의실 예약 웹앱 PRD

다온소프트 사내 '회의실 예약' 웹앱 · 문서 버전 0.2 · 작성일 2026-10-30

## 1. 개요

- **목적**: 회의실 3개의 하루 시간표를 한 화면에서 보고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있게 한다.
- **배경**: 회의실 사용 현황을 한눈에 볼 수 없어 중복 사용과 확인 전화가 생긴다. 이를 줄이는 가장 작은 도구를 만든다.
- **핵심 범위(Phase 1)**: 시간표 조회 · 빈 칸 클릭 예약 · 내 예약 취소. 그 밖의 기능은 Phase 2 이후로 미룬다.
- **기술**: Python FastAPI(백엔드), 순수 HTML/JS(프런트, 프레임워크 없음), SQLite(저장).
- **데이터**: 가상 데이터만 사용한다. 실제 직원 정보나 사내 데이터는 넣지 않는다.

## 2. 사용자와 권한

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원 | 다온소프트 사내 구성원(가상 사용자 5명) | 시간표 조회(전원 것), 예약 생성(본인 명의로만), 취소(본인 예약만) |

- 관리자 역할은 두지 않는다(8장 참고). 따라서 남의 예약을 지우거나 대신 예약해 주는 사람은 없다.
- 인증은 두지 않는다. 화면에서 가상 사용자 한 명을 고르면 그 사람으로 동작한다(F-04).
- **권한 규칙(화면과 서버 모두 적용)**

| 동작 | 누가 | 화면 | 서버 |
|---|---|---|---|
| 시간표 조회 | 누구나 | 전원의 예약자·제목 표시 | 제한 없음 |
| 예약 생성 | 선택된 사용자 본인 명의로만 | 예약자는 선택된 사용자로 고정, 입력 칸 없음 | 요청자 번호를 예약자로 저장. 요청 본문에 다른 예약자를 넣을 수 없음 |
| 예약 취소 | 예약자 본인만 | 남의 예약은 취소 버튼 없음 | 요청자 번호 ≠ 예약자 번호이면 403으로 거부(R-06) |

- **요청자 확인 방식**: 화면이 모든 예약·취소 요청에 선택된 사용자 번호를 `X-User-Id` 헤더로 보낸다. 서버는 이 번호가 `rsv_user`에 있는지 확인하고, 없거나 빠졌으면 400으로 거부한다.
- **한계(의도된 것)**: 번호는 클라이언트가 스스로 밝히는 값이라 보안이 아니다. 서버가 막는 것은 "화면을 거치지 않고 API로 남의 예약 취소를 시도하는 실수·장난"까지이며, 번호를 위조하는 공격은 막지 않는다(8장).

## 3. 기능 요구사항

| 번호 | 기능 | 설명 | MoSCoW | Phase |
|---|---|---|---|---|
| F-01 | 하루 시간표 보기 | 회의실 3개 × 9:00~18:00, 30분 단위 칸(18칸)을 표로 표시. 칸마다 빈 칸/예약됨 구분, 예약된 칸에는 예약자와 제목 표시. Phase 1은 오늘 날짜만 표시 | Must | 1 |
| F-02 | 빈 칸 클릭 예약 | 빈 칸을 누르면 예약 창이 열림. 제목 입력과 종료 시각 선택(기본 30분, 최대 4시간) 후 확정하면 저장되고 시간표에 즉시 반영 | Must | 1 |
| F-03 | 내 예약 취소 | 본인 예약 칸을 누르면 취소 버튼 표시. 확인 후 취소하면 칸이 빈 칸으로 돌아감 | Must | 1 |
| F-04 | 사용자 선택 | 화면 상단에서 가상 사용자 중 한 명을 선택. "내 예약"의 기준이 됨. 첫 화면의 기본 선택은 `user_id` 가 가장 작은 사용자 | Must | 1 |
| F-05 | 날짜 이동 | 이전/다음 날 버튼으로 다른 날짜의 시간표 조회 및 예약 | Should | 2 |
| F-06 | 내 예약 목록 | 오늘 이후 내 예약을 목록으로 모아 보고 거기서 취소 | Should | 2 |
| F-07 | 예약 수정 | 기존 예약의 제목/시간 변경 | Could | 3 |
| F-08 | 반복 예약 | 매주 같은 시간 예약 | Could | 3 |
| F-09 | 알림 | 회의 시작 전 알림 | Could | 3 |

Phase 1에는 Must만 넣는다(F-01~F-04).

## 4. 화면 구성

단일 페이지 1개(`index.html`)로 구성한다.

1. **상단 바**: 앱 제목, 오늘 날짜(KST, `YYYY-MM-DD`), 사용자 선택 드롭다운(F-04)
2. **시간표 영역**(F-01)
   - 가로: 회의실 3개(열), 세로: 09:00~17:30 시작 칸 18개(행)
   - 빈 칸: 흰색, 마우스를 올리면 강조
   - 남의 예약: 회색, 예약자·제목 표시, 클릭해도 취소 불가(클릭 시 아무 일도 없음)
   - 내 예약: 강조색, 클릭하면 취소 창
   - 지난 시간 칸: 비활성(클릭 불가). 지난 시간의 예약 칸은 예약자·제목만 보이고 클릭해도 창이 열리지 않음
   - 여러 칸짜리 예약은 칸마다 같은 예약자·제목을 표시하고 한 덩어리로 보이게 한다
3. **예약 창**(F-02): 회의실·시작 시각(읽기 전용), 종료 시각 선택, 제목 입력, [예약] [닫기]
   - 종료 시각 목록은 시작 + 30분부터 최대 시작 + 4시간까지, 18:00을 넘지 않는 값만 보여 준다. 그 사이에 다른 예약이 있으면 그 예약의 시작 시각까지만 보여 준다.
   - 제목 입력 칸은 30자를 넘겨 입력할 수 없고, 현재 글자 수(예: 7/30)를 보여 준다.
4. **취소 확인 창**(F-03): 예약 내용(회의실·시간·제목) 표시, [예약 취소] [닫기]
5. **메시지 영역**: 성공·실패 안내. 문구는 6.2장의 표를 그대로 쓴다. 성공 메시지는 5초 뒤 사라지고, 실패 메시지는 다른 동작을 하거나 닫기를 누를 때까지 남는다.

### 4.1 빈 상태 · 오류 상태 화면

| 상황 | 화면에 나오는 것 |
|---|---|
| 오늘 예약이 한 건도 없음 | 시간표 18칸 × 3열이 모두 빈 칸으로 표시됨. 별도 오류 아님. 시간표 위에 "오늘 예약이 없습니다. 빈 칸을 눌러 예약하세요." 한 줄 표시 |
| 시간표를 불러오지 못함(서버 응답 없음·5xx) | 시간표 자리에 "시간표를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요." 와 [다시 불러오기] 버튼. 칸은 클릭 불가 |
| 사용자 목록을 불러오지 못함 / 사용자가 0명 | 드롭다운은 비활성, 예약·취소 불가. "사용자 정보를 불러오지 못했습니다." 표시 |
| 예약·취소 요청이 실패함 | 창은 닫지 않고 메시지 영역에 사유 표시. 입력한 제목은 유지. 409(겹침)·404 때는 시간표를 자동으로 다시 불러와 최신 상태로 맞춤 |
| 예약·취소 요청 중 | 해당 창의 [예약]·[예약 취소] 버튼을 비활성화해 이중 클릭을 막음 |

## 5. 데이터 구조

SQLite 사용. 표 이름은 모두 `rsv_` 로 시작한다.

### rsv_user (가상 사용자)

| 열 | 타입 | 설명 |
|---|---|---|
| user_id | INTEGER PK | 사용자 번호 |
| name | TEXT NOT NULL | 가상 이름 (예: 사용자A~E) |

### rsv_room (회의실)

| 열 | 타입 | 설명 |
|---|---|---|
| room_id | INTEGER PK | 회의실 번호 |
| name | TEXT NOT NULL | 회의실 이름 (예: 회의실 1~3) |

### rsv_booking (예약)

| 열 | 타입 | 설명 |
|---|---|---|
| booking_id | INTEGER PK | 예약 번호 |
| room_id | INTEGER NOT NULL | rsv_room 참조 |
| user_id | INTEGER NOT NULL | rsv_user 참조 (예약자) |
| book_date | TEXT NOT NULL | 예약 날짜 `YYYY-MM-DD` (KST) |
| start_slot | INTEGER NOT NULL | 시작 칸 번호 0~17 (0 = 09:00). 시작 시각 = 9:00 + start_slot × 30분 |
| end_slot | INTEGER NOT NULL | 끝 칸 번호(미포함) 1~18. 종료 시각 = 9:00 + end_slot × 30분. 항상 start_slot < end_slot |
| title | TEXT NOT NULL | 회의 제목 (앞뒤 공백 제거 후 1~30자) |
| status | TEXT NOT NULL | `ACTIVE` 또는 `CANCELED` |
| created_at | TEXT NOT NULL | 생성 시각 `YYYY-MM-DD HH:MM:SS` (KST) |

- 초기 데이터: 회의실 3개, 사용자 5명, 예시 예약 3~5건(전부 가상, 서로 겹치지 않고 오늘 날짜 기준으로 만든다. 지난 시간 예약과 앞으로의 예약이 둘 다 한 건 이상 포함).
- 취소는 행을 지우지 않고 status를 `CANCELED`로 바꾼다. 어떤 API도 행을 삭제하지 않는다.

## 6. 업무 규칙

### 6.1 규칙 목록

**용어(경계 판단 기준)**
- 시간 구간은 **시작 포함 · 끝 미포함**(`[start_slot, end_slot)`)으로 본다. 10:00~10:30 예약은 칸 하나(10:00 칸)만 차지한다.
- **현재 시각**은 서버의 KST 시계다. 브라우저 시계는 쓰지 않는다.
- 칸의 **시작 시각이 현재 시각보다 이르거나 같으면** 그 칸은 "지난(또는 이미 시작한) 칸"이다. 예: 10:00 칸은 10:00:00부터 지난 칸이다.

| 번호 | 규칙 |
|---|---|
| R-01 | 예약 가능 시간은 09:00~18:00, 30분 단위 칸이다. `start_slot`은 0~17, `end_slot`은 1~18, `start_slot < end_slot`이어야 한다. 이 범위를 벗어나거나 정수가 아닌 값은 거부한다(400). 17:30~18:00 칸(끝 18:00)은 허용, 18:00을 넘는 끝은 거부. |
| R-02 | 같은 회의실·같은 날짜에서 `ACTIVE` 예약끼리 시간이 겹치면 거부한다(409). 겹침 조건: `새.start_slot < 기존.end_slot` **그리고** `기존.start_slot < 새.end_slot`. 따라서 **딱 붙는 경우는 허용**한다(기존 10:00~10:30 뒤에 10:30~11:00 예약 가능, 기존 시작과 새 끝이 같은 경우도 허용). `CANCELED` 예약은 검사에서 제외한다. 서버가 검사와 저장을 한 번에(같은 트랜잭션에서) 처리해, 동시에 같은 칸을 누른 두 요청 중 하나만 성공한다. |
| R-03 | 예약 길이는 최소 30분(1칸), 최대 4시간(8칸)이다. `end_slot − start_slot`이 1~8이어야 하며 벗어나면 거부한다(400). 정확히 8칸(4시간)은 허용, 9칸은 거부. |
| R-04 | 예약 시작 칸이 지난 칸(위 용어)이면 예약할 수 없다(400). 현재 10:10이면 10:00 칸은 불가, 10:30 칸은 가능. Phase 1은 오늘 날짜만 받으며 `book_date`가 오늘이 아니면 거부한다(400). |
| R-05 | 예약 제목은 필수이며 앞뒤 공백을 지운 뒤 1~30자(글자 수 기준, 한글·영문 모두 1자)다. 공백만 있거나 31자 이상이면 거부한다(400). 30자 정확히는 허용. |
| R-06 | 취소는 예약자 본인만 할 수 있다. 서버가 `X-User-Id`의 요청자와 예약의 `user_id`를 비교해, 다르면 403으로 거부한다. 화면에서 버튼을 숨기는 것만으로는 충분하지 않다. 예약 생성도 요청자 본인 명의로만 저장한다(2장). |
| R-07 | 이미 시작했거나 지난 예약은 취소할 수 없다(409). 기준은 예약의 `start_slot` 시각이 현재 시각보다 이르거나 같은지다(R-04와 같은 기준). 여러 칸짜리 예약도 시작 시각으로만 판단한다. |
| R-08 | 취소된 예약은 시간표에서 빈 칸으로 보이며, 같은 시간에 다시 예약할 수 있다(R-02에서 제외되므로). 이미 `CANCELED`인 예약을 다시 취소하면 409로 거부한다. |
| R-09 | 한 사람이 같은 시간에 여러 회의실을 예약하는 것은 막지 않는다(Phase 1). 한 사람의 하루 예약 건수·총 시간에도 한도를 두지 않는다. |

**규칙이 동시에 걸릴 때의 검사 순서**(첫 번째로 걸린 오류만 돌려준다): 요청자 확인(400) → 존재 확인(404) → 권한(403, 취소만) → 형식·범위·길이·제목(400) → 지난 시간(400 예약 / 409 취소) → 겹침·이미 취소(409).

### 6.2 API 오류·응답 규약

모든 오류 응답은 JSON `{"message": "<아래 문구>"}` 형태이며, 화면은 이 문구를 메시지 영역에 그대로 보여 준다.

| 요청 | 성공 응답 | 비고 |
|---|---|---|
| 시간표 조회 (오늘) | 200, 회의실 3개와 `ACTIVE` 예약 목록. 예약이 없으면 `예약 목록: []`(빈 배열)이며 오류가 아님 | 예약자 이름·제목 포함 |
| 사용자 목록 조회 | 200, 사용자 배열 | |
| 예약 생성 | 201, 만들어진 예약 | |
| 예약 취소 | 200, 취소된 예약(`status = CANCELED`) | 행은 삭제되지 않음 |

| 상태 코드 | 상황 | 문구(`message`) |
|---|---|---|
| 400 | `X-User-Id` 없음 / 없는 사용자 | 사용자를 확인할 수 없습니다. |
| 400 | 시간 범위 밖·칸 번호 오류(R-01), 날짜가 오늘이 아님(R-04) | 예약할 수 없는 시간입니다. (09:00~18:00, 30분 단위, 오늘만 가능) |
| 400 | 길이가 30분 미만 / 4시간 초과(R-03) | 예약은 30분 이상 4시간 이하로 해 주세요. |
| 400 | 제목 비었음 / 30자 초과(R-05) | 제목은 1~30자로 입력해 주세요. |
| 400 | 지난 시간에 예약(R-04) | 이미 지난 시간에는 예약할 수 없습니다. |
| 400 | 없는 회의실 | 존재하지 않는 회의실입니다. |
| 403 | 남의 예약 취소(R-06) | 본인이 만든 예약만 취소할 수 있습니다. |
| 404 | 없는 예약 번호로 취소 | 예약을 찾을 수 없습니다. |
| 409 | 시간 겹침(R-02) | 이미 예약된 시간입니다. |
| 409 | 이미 시작했거나 지난 예약 취소(R-07) | 이미 시작했거나 지난 예약은 취소할 수 없습니다. |
| 409 | 이미 취소된 예약을 다시 취소(R-08) | 이미 취소된 예약입니다. |
| 500 / 응답 없음 | 서버 오류 | 처리 중 문제가 생겼습니다. 잠시 후 다시 시도해 주세요. (화면에서 표시. 세부 오류 내용은 화면에 노출하지 않음) |

성공 시 화면 문구: 예약 → "예약되었습니다.", 취소 → "예약이 취소되었습니다."

## 7. 제약 조건

- 백엔드는 Python FastAPI, 프런트는 순수 HTML/JS(빌드 도구·프레임워크 없음), 저장소는 SQLite 파일 1개.
- 모든 데이터는 가상이다. 실제 이름·이메일·사내 정보를 넣지 않는다.
- 로컬/사내 PC 1대에서 실행하는 소규모 사용(동시 사용자 수십 명 이하, 가상 사용자는 5명)을 전제로 한다.
- 시간대는 한국 표준시(KST) 하나로 고정한다. 모든 시각 판단(지난 칸, 취소 가능 여부, "오늘")은 서버 KST 시계 기준이다.
- 시간 단위는 30분 칸 하나로 통일한다. 예약 가능 시간 09:00~18:00(하루 18칸), 예약 길이 1~8칸(30분~4시간), 제목 1~30자.
- 지원 브라우저: 최신 Chrome, Edge.
- 중복 방지와 본인 예약만 취소는 화면이 아닌 서버에서 보장한다(R-02, R-06).
- 시간표는 다시 불러올 때만 갱신한다(자동 새로고침 없음). 예약·취소·[다시 불러오기] 후, 그리고 페이지를 열 때 갱신한다.

## 8. 범위 밖

이번(Phase 1)에 만들지 않는 것이다.

- 로그인·비밀번호·사용자 위조 방지(`X-User-Id`는 자기 신고일 뿐 보안 기능이 아님), 역할·권한 관리
- 관리자 기능, 회의실 추가·삭제·수정, 남의 예약을 대신 취소하는 기능
- 승인 절차, 외부 캘린더(Outlook·Google) 연동
- 이메일·메신저 알림 (F-09는 Phase 3 후보일 뿐 현재 범위 밖)
- 모바일 전용 화면, 다국어
- 회의 참석자 관리, 장비·좌석 예약
- 사용 통계·리포트
- 날짜 이동·다른 날짜 조회 및 예약(F-05, Phase 2), 내 예약 목록(F-06, Phase 2)
- 예약 수정(F-07), 반복 예약(F-08) (Phase 3)
- 취소된 예약의 이력 조회 화면, 취소 사유 입력, 행 삭제(데이터는 `CANCELED`로만 남김)
- 한 사람의 예약 건수·시간 한도, 같은 시간 여러 회의실 예약 차단(R-09)
- 화면 자동 새로고침·실시간 동기화(다른 사람의 예약은 다시 불러와야 보임)
- 30분이 아닌 단위(15분·1시간 등), 09:00~18:00 밖의 시간대, 4시간을 넘는 예약

## 9. 개발 단계

| Phase | 목표 | 포함 기능 |
|---|---|---|
| 1 | 최소 동작 버전: 보고·예약하고·취소 | F-01, F-02, F-03, F-04 (Must만) |
| 2 | 편의 기능 | F-05 날짜 이동, F-06 내 예약 목록 (Should) |
| 3 | 선택 기능 | F-07 예약 수정, F-08 반복 예약, F-09 알림 (Could) |

Phase 1 작업 순서: ① DB 표 생성과 가상 초기 데이터 → ② 시간표 조회·예약·취소 API(6.2장 오류 규약 포함) → ③ 시간표 화면(빈·오류 상태 포함) → ④ 예약/취소 창과 사용자 선택 연결 → ⑤ 완료 기준 점검.

## 10. 완료 기준

Phase 1 완료 기준은 아래 항목을 모두 통과하는 것이다.

### Phase 1

- [ ] T-01 첫 화면에 회의실 3개 × 18칸(9:00~18:00) 시간표가 표시된다. (F-01)
- [ ] T-02 초기 예시 예약이 해당 칸에 예약자·제목과 함께 표시된다. (F-01)
- [ ] T-03 화면 상단에서 가상 사용자를 바꿀 수 있고, 바꾸면 "내 예약" 표시가 그에 맞게 바뀐다. (F-04)
- [ ] T-04 빈 칸을 누르면 예약 창이 열리고, 제목 입력 후 예약하면 칸이 즉시 예약됨으로 바뀌며 "예약되었습니다."가 표시된다(API는 201). (F-02)
- [ ] T-05 종료 시각을 늘려(예: 1시간) 예약하면 해당 칸 여러 개가 함께 채워진다. 4시간(8칸)은 되고 4시간 30분(9칸)은 400으로 거부된다. (F-02, R-03)
- [ ] T-06 겹치는 시간에 예약하면 409와 "이미 예약된 시간입니다."가 나오고 시간표가 최신으로 갱신된다. 서버 API를 직접 호출해도 거부된다. (R-02)
- [ ] T-06a 딱 붙는 예약은 성공한다: 10:00~10:30 예약 바로 뒤의 10:30~11:00, 바로 앞의 09:30~10:00. 칸이 하나라도 겹치면(예: 10:00~11:00) 거부된다. (R-02)
- [ ] T-06b 같은 칸에 두 요청을 동시에 보내면 하나만 201, 나머지는 409다. 취소된 예약 자리에는 다시 예약된다. (R-02, R-08)
- [ ] T-07 제목이 비었거나(공백만 포함) 31자 이상이면 400과 "제목은 1~30자로 입력해 주세요."가 나온다. 정확히 30자는 예약된다. (R-05)
- [ ] T-07a 17:30~18:00 예약은 성공하고, 18:00을 넘는 끝(end_slot 19)·start_slot 18 이상·start_slot ≥ end_slot은 400이다. (R-01)
- [ ] T-08 지난 시간 칸은 클릭해도 예약 창이 열리지 않고, API로 요청해도 400으로 거부된다. 시작 시각이 현재와 같은 칸도 거부, 다음 칸은 허용된다. (R-04)
- [ ] T-09 내 예약을 누르면 취소 창이 열리고, 취소하면 칸이 빈 칸으로 돌아가 "예약이 취소되었습니다."가 표시되며 다시 예약할 수 있다. (F-03, R-08)
- [ ] T-10 남의 예약에는 취소 버튼이 없고, API로 취소를 요청하면 403과 "본인이 만든 예약만 취소할 수 있습니다."가 나온다. 없는 예약 번호는 404, `X-User-Id` 없음은 400이다. (R-06)
- [ ] T-11 이미 시작했거나 지난 내 예약은 취소할 수 없다(409). 이미 취소된 예약을 다시 취소해도 409다. (R-07, R-08)
- [ ] T-12 서버를 껐다 켜도 예약과 취소 내용이 유지된다. (5장)
- [ ] T-13 DB의 모든 표 이름이 `rsv_` 로 시작하고, 데이터에 실제 개인정보가 없다. (5장, 7장)
- [ ] T-14 Phase 1 화면과 API에 Must 외 기능(날짜 이동, 내 예약 목록 등)이 들어 있지 않다. (3장, 8장)
- [ ] T-14a 예약이 하나도 없는 날(DB의 예약을 비운 상태)에도 빈 시간표 18칸 × 3열과 안내 문구가 나오고 오류가 아니다. 서버를 끈 상태에서 열면 "시간표를 불러오지 못했습니다." 와 [다시 불러오기]가 나온다. (4.1장)

### Phase 2 (착수 시 점검)
