# 다온소프트 회의실 예약 웹앱 PRD

- 문서 상태: 초안 v0.2 (2026-10-30) — 점검표 5문항(충돌 · 단위 · 권한 · 빈/오류 상태 · 범위 밖) 반영
- 표 이름 접두어: `mr_` (meeting room)

## 1. 개요

### 1.1 배경과 목적
다온소프트 사내 회의실 3개를 구두·메신저로 잡다 보니 중복 예약과 "지금 어디 비었나" 확인 비용이 생긴다. 하루 시간표를 한 화면에 보여 주고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있는 최소한의 웹앱을 만든다.

### 1.2 한 줄 요약
회의실 3개 × 09:00~18:00(30분 단위) 시간표를 보고, 빈 칸을 눌러 예약하고, 내 예약을 취소한다.

### 1.3 성공 기준
- 시간표를 열고 10초 안에 예약을 끝낼 수 있다 (클릭 3번 이내: 빈 칸 → 제목 입력 → 예약).
- 같은 회의실·같은 시간에 `active` 예약이 둘 이상 생기지 않는다.
- 남의 예약은 취소할 수 없다 (화면에서도, 서버에서도).

### 1.4 기술 스택
| 영역 | 선택 |
|---|---|
| 백엔드 | Python FastAPI |
| 프런트엔드 | 순수 HTML / CSS / JavaScript (프레임워크·빌드 도구 없음) |
| 데이터베이스 | SQLite (단일 파일) |
| 데이터 | 가상 데이터만 사용 (실제 직원·실제 회의 정보 금지) |

## 2. 사용자

| 구분 | 설명 | 주요 행동 |
|---|---|---|
| 직원 (유일한 역할) | 다온소프트 사내 구성원. 모두 같은 권한 | 시간표 조회, 예약 생성, 본인 예약 취소 |

- 관리자 역할은 두지 않는다 (8장 참고).
- 가정: 사용자는 PC 브라우저(최신 Chrome/Edge)로 사용한다.
- 가정: 로그인 대신 화면 상단에서 "내 이름"을 고른다 (7장 제약 참고).

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could, W=Won't(이번 범위 밖). **Phase 1에는 Must만 포함한다.**

| 번호 | 기능 | 설명 | MoSCoW | Phase |
|---|---|---|---|---|
| F-01 | 오늘 시간표 조회 | 회의실 3개를 열, 09:00~18:00을 30분 단위 행(18칸)으로 보여 준다 | M | 1 |
| F-02 | 예약 현황 표시 | 예약된 칸에 제목·예약자 이름을 표시하고, 빈 칸/예약됨/내 예약/지난 시간을 색으로 구분한다 | M | 1 |
| F-03 | 사용자 선택 | 가상 직원 목록에서 "나"를 고른다. 선택은 브라우저(localStorage)에 기억된다 | M | 1 |
| F-04 | 빈 칸 클릭 예약 | 빈 칸을 누르면 예약 창이 뜨고, 제목과 종료 시각을 정해 예약한다 | M | 1 |
| F-05 | 중복 예약 방지 | 겹치는 시간의 예약은 서버가 거절하고 이유를 알려 준다 | M | 1 |
| F-06 | 내 예약 취소 | 내 예약 칸을 누르면 취소 확인 후 취소한다. 남의 예약은 취소 불가 | M | 1 |
| F-07 | 날짜 이동 | 이전/다음 날, 오늘로 돌아가기. 이때부터 오늘 이후 날짜 예약을 허용한다 | S | 2 |
| F-08 | 내 예약 목록 | 오늘 이후 내 예약을 한 목록으로 모아 본다 | S | 2 |
| F-09 | 예약 수정 | 제목·시간 변경 (Phase 1에서는 취소 후 재예약으로 대체) | C | 3 |
| F-10 | 자동 새로고침 | 30초 간격으로 시간표를 다시 불러온다 (Phase 3 가정값) | C | 3 |
| F-11 | 반복 예약 | 매주 같은 시간 등 | W | - |
| F-12 | 알림 | 메일·메신저 알림 | W | - |

## 4. 화면 구성

단일 페이지 1개로 구성한다.

### 4.1 상단 바
- 앱 제목 "회의실 예약", 오늘 날짜 표시 (`YYYY-MM-DD`, 한국 표준시)
- 사용자 선택 드롭다운 (F-03).
  - 미선택 상태: 드롭다운 기본 문구 "이름을 선택하세요", 상단에 안내 띠 "이름을 먼저 선택해야 예약·취소할 수 있습니다." 표시. 빈 칸과 내 예약 칸을 눌러도 예약 창·취소 창이 열리지 않는다 (남의 예약 상세 보기는 가능).
  - 저장된 사용자가 목록에 더 이상 없으면 선택을 비우고 미선택 상태로 처리한다.

### 4.2 시간표 (F-01, F-02)
```
        | 회의실 A | 회의실 B | 회의실 C |
 09:00  |  (빈)    | 주간회의 |  (빈)    |
 09:30  |  (빈)    | 김가온   |  (빈)    |
  ...
 17:30  |  (빈)    |  (빈)    |  (빈)    |
```
- 행 18개(09:00~17:30 시작, 각 칸 30분), 열 3개. 시간 라벨은 왼쪽, 회의실 이름은 위쪽에 고정
- 칸 상태: **빈 칸**(클릭 가능) / **예약됨**(남의 예약, 제목+이름 표시) / **내 예약**(강조색) / **지난 시간**(회색, 클릭 불가)
- 긴 예약은 시작 칸에 제목을 쓰고 이어지는 칸은 같은 색으로 잇는다
- 지난 시간 칸 안의 예약은 지난 시간 칸이어도 제목·이름을 그대로 보여 주고 회색 톤만 더한다 (이력 확인용).
- **빈 상태**
  - 오늘 예약이 0건이면: 18행 × 3열이 모두 빈 칸으로 정상 표시되고, 시간표 위에 "오늘 예약이 없습니다. 빈 칸을 눌러 예약하세요." 한 줄을 보여 준다.
  - 현재 시각이 18:00 이후(또는 모든 칸이 지난 시간)이면: 시간표는 전부 회색이고 "오늘 예약 가능한 시간이 끝났습니다." 를 보여 준다.
  - 회의실 목록이 0개이거나 불러오기에 실패하면: 시간표 자리에 "회의실 정보를 불러오지 못했습니다." + [다시 시도] 버튼.
- **불러오는 중**: 시간표 자리에 "불러오는 중…" 문구. 3초 안에 응답이 없으면 같은 문구를 유지하고, 실패 응답/네트워크 끊김이면 위 오류 문구 + [다시 시도]로 바꾼다.

### 4.3 예약 창 (F-04)
- 입력: 회의실(자동), 시작 시각(자동, 수정 불가), 종료 시각(선택, 30분 단위), 제목(필수)
- 종료 시각 드롭다운은 시작+30분부터 `min(시작+120분, 18:00)` 까지만 보여 준다. 기본값은 시작+30분.
- 제목 입력란은 최대 30자까지만 입력되고, "n/30" 글자 수를 보여 준다.
- 버튼: 예약 / 닫기
- 오류(겹침, 입력 오류, 서버 오류)는 창 안 하단에 빨간 문구로 표시한다. 오류가 나도 창은 닫히지 않고 입력값을 유지한다. 409(겹침)이면 시간표를 즉시 다시 불러와 최신 상태로 맞춘다.
- 예약 성공 시 창을 닫고 시간표를 다시 불러온다.

### 4.4 취소 확인 창 (F-06)
- 내용: 회의실·시간·제목 표시 + "이 예약을 취소할까요?"
- 버튼: 예약 취소 / 닫기
- 남의 예약 칸을 누르면 상세(회의실·시간·제목·예약자)만 보여 주고 취소 버튼은 숨긴다.
- 이미 끝난 내 예약을 누르면 상세만 보여 주고 취소 버튼은 숨긴다 (R-07).
- 취소 실패 시 창 안에 빨간 문구를 보여 주고, 403/404/409이면 시간표를 다시 불러온다.

## 5. 데이터 구조

SQLite, 표 이름은 모두 `mr_` 로 시작한다. 날짜는 `YYYY-MM-DD`, 시각은 `HH:MM` 문자열(24시간제)로 저장한다. 모든 시각의 기준은 한국 표준시(Asia/Seoul)이며, `created_at`/`cancelled_at` 은 `YYYY-MM-DD HH:MM:SS` 형식이다.

### 5.1 mr_users (가상 직원)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| name | TEXT NOT NULL | 가상 이름 (예: 김가온) |
| dept | TEXT | 가상 부서명 |

### 5.2 mr_rooms (회의실)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| name | TEXT NOT NULL UNIQUE | 회의실 A / B / C |
| capacity | INTEGER | 정원 (명, 표시용) |

### 5.3 mr_reservations (예약)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| room_id | INTEGER NOT NULL | → mr_rooms.id |
| user_id | INTEGER NOT NULL | → mr_users.id (예약자) |
| rsv_date | TEXT NOT NULL | 예약 날짜 |
| start_time | TEXT NOT NULL | 시작 (포함) |
| end_time | TEXT NOT NULL | 종료 (미포함) |
| title | TEXT NOT NULL | 회의 제목 (앞뒤 공백 제거 후 저장, 1~30자) |
| status | TEXT NOT NULL | `active` / `cancelled` |
| created_at | TEXT NOT NULL | 생성 시각 |
| cancelled_at | TEXT | 취소 시각 |

- 취소는 행을 지우지 않고 `status='cancelled'` 로 바꾼다 (이력 보존). 겹침 검사는 `active` 만 대상으로 한다. 따라서 취소된 시간은 즉시 다시 예약할 수 있다.
- 행을 실제로 삭제(DELETE)하는 API와 화면은 없다.
- 인덱스: `(room_id, rsv_date, status)`.

### 5.4 초기(가상) 데이터
- mr_users 5명, mr_rooms 3개(회의실 A/B/C), mr_reservations 오늘 날짜로 3~5건. 모두 실존하지 않는 가상 값.
- 초기 예약은 서버를 처음 띄운 시각과 무관하게 오늘 09:00~18:00 안에 들어가도록 만든다 (겹침 없음).

## 6. 업무 규칙

### 6.1 규칙 목록

| 번호 | 규칙 |
|---|---|
| R-01 | 시작 시각은 09:00~17:30, 종료 시각은 09:30~18:00 이며, 둘 다 `HH:00` 또는 `HH:30` 이어야 한다. 18:00 종료는 허용, 18:00 시작·18:00 초과 종료는 거절한다 |
| R-02 | 종료 시각은 시작 시각보다 늦어야 한다 (최소 30분). 시작 = 종료이거나 종료가 더 빠르면 거절한다 |
| R-03 | 같은 회의실·같은 날짜에서 `active` 예약끼리 시간이 겹치면 안 된다. 겹침 기준은 `새 시작 < 기존 종료` 그리고 `새 종료 > 기존 시작`이며, 끝과 시작이 맞닿는 것(예: 기존 10:00 종료 / 새 10:00 시작, 또는 새 10:00 종료 / 기존 10:00 시작)은 허용한다. 다른 회의실끼리는 겹쳐도 된다. 한 사람이 같은 시간에 서로 다른 회의실을 잡는 것도 막지 않는다 |
| R-04 | 예약의 시작 시각이 서버의 현재 시각보다 이전이면 거절한다 (시작 시각 = 현재 시각이면 허용). 예: 지금이 10:15이면 10:00 시작은 거절, 10:30 시작은 허용. 시간표에서는 시작 시각이 현재보다 이전인 칸을 "지난 시간"으로 칠한다 |
| R-05 | 제목은 필수이며, 앞뒤 공백을 제거한 뒤 1자 이상 30자 이하(글자 수 기준, 한글·영문 모두 1자)이다. 공백뿐인 제목은 빈 제목으로 본다 |
| R-06 | 예약자 본인만 자기 예약을 취소할 수 있다. 요청에 담긴 `user_id` 와 예약의 `user_id` 가 다르면 서버가 403으로 거절한다. 화면에서 버튼을 숨기는 것과 별개로 서버가 항상 판정한다 |
| R-07 | 이미 지난 예약(종료 시각 ≤ 서버 현재 시각)은 취소할 수 없다. 진행 중인 예약(시작 ≤ 현재 < 종료)은 취소할 수 있다 |
| R-08 | 한 번에 예약할 수 있는 최대 길이는 120분(4칸)이다. 120분은 허용, 121분 이상(30분 단위이므로 150분부터)은 거절한다 (가정: 독점 방지용. 사용자 확인 필요) |
| R-09 | 겹침 검사와 저장은 한 트랜잭션에서 처리해, 동시에 눌러도 중복이 생기지 않게 한다. 동시에 같은 칸을 요청하면 먼저 처리된 1건만 성공하고 나머지는 409를 받는다 |
| R-10 | Phase 1에서는 오늘 날짜(서버 기준) 예약만 만들 수 있다. 다른 날짜면 422로 거절한다. 날짜 이동(F-07)이 들어오는 Phase 2부터 오늘 이후 날짜를 허용한다 (과거 날짜는 계속 거절) |
| R-11 | 이미 `cancelled` 인 예약을 다시 취소하면 409로 거절한다 (같은 요청을 두 번 눌러도 상태는 변하지 않는다) |

### 6.2 검사 순서
한 요청이 여러 규칙을 동시에 어기면 아래 순서로 처음 걸린 오류 하나만 돌려준다.

- 예약 생성: ① 입력 형식·누락(422) → ② 사용자·회의실 존재 여부(403/404) → ③ R-10, R-05, R-01, R-02, R-08, R-04 (모두 422) → ④ R-03 겹침(409)
- 예약 취소: ① 예약 존재 여부(404) → ② R-06 소유자(403) → ③ R-11 이미 취소(409) → ④ R-07 이미 지남(409)

## 7. 제약 조건

- **스택 고정**: FastAPI + 순수 HTML/JS + SQLite. 프런트 프레임워크·번들러·외부 CDN 의존 없음.
- **가상 데이터만**: 실제 직원 이름·이메일·회의 내용을 넣지 않는다.
- **인증 없음(알려진 한계)**: 로그인 대신 이름 선택 방식이므로 다른 사람인 척하는 것을 기술적으로 막지 못한다. R-06은 "요청에 담긴 user_id" 기준으로 판정하며, 실사용 전에는 사내 로그인 연동이 필요하다. 가상 데이터 데모 범위에서는 허용한다.
- **서버 시각 기준**: "지난 시간" 판정(R-04, R-07, R-10)은 서버 시계(Asia/Seoul)로 한다 (사용자 PC 시계 조작 방지). 화면의 회색 표시는 시간표를 불러온 시점의 서버 시각을 기준으로 하며, 클릭 시점에는 서버가 다시 판정한다.
- **단일 서버·단일 SQLite 파일**: 동시 사용자 수 50명 이하, 하루 예약 최대 54건(3실 × 18칸)을 가정한다.
- **영업일 구분 없음**: 주말·공휴일도 평일과 같은 09:00~18:00으로 취급한다.

### 7.1 API 개요 (구현 시 확정)

| 메서드·경로 | 용도 | 요청 | 성공 응답 |
|---|---|---|---|
| `GET /api/users` | 직원 목록 | - | 200 + 배열 (0건이면 `[]`) |
| `GET /api/rooms` | 회의실 목록 | - | 200 + 배열 |
| `GET /api/reservations?date=YYYY-MM-DD` | 해당 날짜의 `active` 예약 | date 생략 시 오늘 | 200 + 배열 (0건이면 `[]`, 오류 아님) |
| `POST /api/reservations` | 예약 생성 | `user_id`, `room_id`, `rsv_date`, `start_time`, `end_time`, `title` | 201 + 만들어진 예약 |
| `POST /api/reservations/{id}/cancel` | 예약 취소 | `user_id` | 200 + 취소된 예약(`status='cancelled'`) |

- `user_id` 는 "이 요청을 하는 사람"이다. 예약 생성은 항상 요청한 본인 명의로만 만들어지며, 다른 사람 명의로 만드는 방법은 없다.
- 조회 API는 누구에게나 열려 있다 (예약자 이름·제목 포함, 직원 전원이 볼 수 있는 정보).
- 예약 수정·삭제 API는 만들지 않는다.

### 7.2 오류 응답 규약

본문은 `{"detail": "<한국어 사유>"}` 형식이다. 화면은 `detail` 문구를 그대로 보여 준다.

| 상황 | 상태 코드 | 사유 문구 (detail) | 화면 표시 |
|---|---|---|---|
| 필수값 누락·형식 오류(시각/날짜 형식, 숫자 아님) | 422 | "입력값을 확인해 주세요." | 예약 창 안 빨간 문구 |
| 제목 비었음(공백만 포함) | 422 | "제목을 입력해 주세요." | 예약 창 안 빨간 문구 |
| 제목 31자 이상 | 422 | "제목은 30자 이하로 입력해 주세요." | 예약 창 안 빨간 문구 |
| 30분 단위·운영 시간(09:00~18:00) 위반 | 422 | "예약은 09:00~18:00 사이, 30분 단위로만 가능합니다." | 예약 창 안 빨간 문구 |
| 종료가 시작보다 빠르거나 같음 | 422 | "종료 시각은 시작 시각보다 늦어야 합니다." | 예약 창 안 빨간 문구 |
| 120분 초과 | 422 | "한 번에 최대 2시간까지 예약할 수 있습니다." | 예약 창 안 빨간 문구 |
| 지난 시간 예약 | 422 | "이미 지난 시간은 예약할 수 없습니다." | 예약 창 안 빨간 문구 |
| 오늘이 아닌 날짜(Phase 1) | 422 | "오늘 날짜만 예약할 수 있습니다." | 예약 창 안 빨간 문구 |
| 시간 겹침 | 409 | "이미 예약된 시간입니다. 다른 시간을 선택해 주세요." | 예약 창 안 빨간 문구 + 시간표 새로고침 |
| `user_id` 가 없는 직원 | 403 | "사용자를 확인할 수 없습니다. 이름을 다시 선택해 주세요." | 안내 띠 + 사용자 선택 초기화 |
| 남의 예약 취소 | 403 | "본인의 예약만 취소할 수 있습니다." | 취소 창 안 빨간 문구 + 시간표 새로고침 |
| 없는 회의실 | 404 | "회의실을 찾을 수 없습니다." | 예약 창 안 빨간 문구 + 시간표 새로고침 |
| 없는 예약 | 404 | "예약을 찾을 수 없습니다." | 취소 창 안 빨간 문구 + 시간표 새로고침 |
| 이미 취소된 예약 | 409 | "이미 취소된 예약입니다." | 취소 창 안 빨간 문구 + 시간표 새로고침 |
| 이미 끝난 예약 취소 | 409 | "이미 끝난 예약은 취소할 수 없습니다." | 취소 창 안 빨간 문구 |
| 서버 내부 오류 | 500 | "일시적인 오류입니다. 잠시 후 다시 시도해 주세요." | 해당 창 안 빨간 문구 (입력값 유지) |
| 네트워크 끊김·서버 무응답 | (응답 없음) | (화면 자체 문구) "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요." | 해당 창 안 빨간 문구 / 시간표 조회면 [다시 시도] 버튼 |

- 거절된 요청은 DB에 아무것도 남기지 않는다 (부분 저장 금지).
- 같은 요청을 연속으로 두 번 보내도 예약이 두 건 생기지 않는다 (두 번째는 409).

## 8. 범위 밖

이번 버전(Phase 1)에서 만들지 않는 것이다.

- 로그인·비밀번호·권한 관리, 관리자 화면 (관리자가 남의 예약을 대신 취소하는 기능 포함)
- Phase 1에서 제외: 날짜 이동·내 예약 목록(Phase 2), 예약 수정·자동 새로고침(Phase 3). 즉 Phase 1은 오늘 하루만 다룬다
- 반복 예약, 승인 절차
- 이메일·메신저 알림, 캘린더(Outlook/Google) 연동
- 회의실 추가·삭제·정원 관리 화면 (3개는 초기 데이터로 고정), 직원 추가·삭제 화면
- 취소된 예약·지난 날짜의 이력 조회 화면 (DB에는 남기되 화면에는 보여 주지 않는다)
- 주말·공휴일·점심시간 등 운영일/휴게 시간 별도 설정
- 한 사람의 동시 중복 예약(다른 회의실 같은 시간) 제한, 하루 예약 횟수 제한
- 모바일 전용 UI, 다국어, 접근성 인증 수준의 대응
- 노쇼 처리, 통계·리포트, 장비 예약

## 9. 개발 단계

| Phase | 목표 | 포함 기능 | 비고 |
|---|---|---|---|
| 1 | 핵심 흐름 완성: 보기 → 예약 → 취소 | F-01 ~ F-06 (**Must만**) | 오늘 날짜만 다룬다 (R-10) |
| 2 | 편의 | F-07 날짜 이동, F-08 내 예약 목록 | Should |
| 3 | 다듬기 | F-09 예약 수정, F-10 자동 새로고침 | Could |

Phase 1 안에서의 작업 순서: DB 표·초기 데이터 → 조회 API → 예약/취소 API(규칙 R-01~R-11) → 시간표 화면 → 예약/취소 창 → 검증.
