# PRD — 다온소프트 회의실 예약 웹앱

## 1. 개요

- **목적**: 다온소프트 사내 회의실 3개의 하루 시간표를 한 화면에서 보고, 빈 칸을 눌러 바로 예약하고, 내 예약은 직접 취소할 수 있게 한다.
- **핵심 요청 3가지**
  1. 회의실 3개의 하루 시간표(09:00~18:00, 30분 단위)를 보여 준다.
  2. 빈 칸을 누르면 예약된다.
  3. 내 예약은 취소할 수 있다.
- **기술**: Python FastAPI(백엔드) + 순수 HTML/JS(프론트, 프레임워크·빌드 도구 없음) + SQLite(저장소).
- **데이터**: 가상 데이터만 사용한다. 실제 직원 정보·계정은 넣지 않는다.
- **산출물 원칙**: Must 가 아닌 기능은 Phase 1 에 넣지 않는다.

## 2. 사용자

| 구분 | 설명 | 할 수 있는 일 |
|---|---|---|
| 직원(예약자) | 다온소프트 사내 구성원(가상 사용자 5명) | 시간표 조회, 빈 칸 예약, 본인 예약 취소 |

- 관리자 역할은 두지 않는다(범위 밖 참고).
- 로그인 대신 화면 상단에서 "나"를 가상 사용자 목록 중에서 고른다(F-04). 비밀번호·인증은 없다.

## 3. 기능 요구사항

MoSCoW: M=Must, S=Should, C=Could. Phase 1 에는 M 만 넣는다.

| ID | 기능 | MoSCoW | Phase | 설명 |
|---|---|---|---|---|
| F-01 | 하루 시간표 조회 | M | 1 | 회의실 3개 × 18칸(09:00~17:30 시작, 30분 단위) 격자를 보여 준다. 칸마다 빈 칸/예약됨/내 예약을 구분해 표시한다. Phase 1 은 오늘 날짜만 보여 준다. |
| F-02 | 빈 칸 클릭 예약 | M | 1 | 빈 칸을 누르면 그 칸(30분) 1개가 현재 사용자 이름으로 예약된다. 여러 칸이 필요하면 칸마다 누른다. |
| F-03 | 내 예약 취소 | M | 1 | 내 예약 칸을 누르면 취소 확인 후 취소되고 빈 칸으로 돌아간다. 남의 예약 칸은 취소할 수 없다. |
| F-04 | 사용자 선택(간이 식별) | M | 1 | "내 예약" 판단을 위해 가상 사용자 중 한 명을 고른다. 선택값은 브라우저(localStorage)에 저장한다. |
| F-05 | 날짜 이동(이전/다음 날) | S | 2 | 오늘 외의 날짜 시간표를 보고 예약한다. |
| F-06 | 내 예약 목록 | S | 2 | 내가 잡은 예약을 날짜순으로 모아 보고 거기서 취소한다. |
| F-07 | 연속 칸 한 번에 예약 | S | 2 | 칸을 드래그하거나 시작·끝을 골라 여러 칸을 한 번에 예약한다. |
| F-08 | 예약 제목 입력 | C | 3 | 예약 시 회의 제목(선택)을 입력하고 시간표에 표시한다. |

## 4. 화면 구성

단일 페이지(`index.html`) 하나로 구성한다.

```
┌──────────────────────────────────────────────┐
│ 다온소프트 회의실 예약     오늘: 2026-10-30   나: [김다온 ▼] │  ← 헤더
├──────┬───────────┬───────────┬───────────┤
│ 시간  │ 회의실 A   │ 회의실 B   │ 회의실 C   │  ← 열 머리글
├──────┼───────────┼───────────┼───────────┤
│09:00 │  (빈 칸)   │  박예약    │  (빈 칸)   │
│09:30 │  (빈 칸)   │  박예약    │  (빈 칸)   │
│ ...  │           │           │           │
│17:30 │  (빈 칸)   │  (빈 칸)   │  내 예약   │
└──────┴───────────┴───────────┴───────────┘
범례: □ 빈 칸   ■ 다른 사람 예약   ■ 내 예약   ▒ 지난 시간
```

| 영역 | 내용 | 관련 기능 |
|---|---|---|
| 헤더 | 서비스명, 오늘 날짜, 사용자 선택 드롭다운 | F-01, F-04 |
| 시간표 격자 | 행 18개(30분) × 열 3개(회의실). 칸 색으로 상태 구분, 예약된 칸에는 예약자 이름 표시 | F-01 |
| 빈 칸 클릭 | 즉시 예약 후 격자 갱신 | F-02 |
| 내 예약 칸 클릭 | "예약을 취소할까요?" 확인창 → 취소 후 격자 갱신 | F-03 |
| 안내 메시지 | 실패 사유(이미 예약됨, 지난 시간 등)를 격자 위에 한 줄로 표시 | R-01~R-05 |
| 범례 | 칸 색상 설명 | F-01 |

- 지난 시간 칸, 남의 예약 칸은 누르면 반응하지 않는다(취소·예약 불가 표시만).
- Phase 2 이후 화면 요소(날짜 이동 버튼, 내 예약 목록, 제목 입력)는 Phase 1 화면에 두지 않는다.

## 5. 데이터 구조

표 이름 접두어는 `rr_`(room reservation)로 한다. 시각은 모두 한국 시간(KST) 기준 문자열이다.

### 5.1 rr_user — 가상 사용자

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| user_id | INTEGER | PK | 사용자 번호 |
| name | TEXT | NOT NULL | 표시 이름(가상, 예: 김다온) |

### 5.2 rr_room — 회의실

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| room_id | INTEGER | PK | 회의실 번호 |
| name | TEXT | NOT NULL, UNIQUE | 회의실 A / B / C |

### 5.3 rr_reservation — 예약

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| reservation_id | INTEGER | PK | 예약 번호 |
| room_id | INTEGER | NOT NULL, FK → rr_room | 회의실 |
| user_id | INTEGER | NOT NULL, FK → rr_user | 예약자 |
| rsv_date | TEXT | NOT NULL | 예약 날짜 `YYYY-MM-DD` |
| slot_start | TEXT | NOT NULL | 칸 시작 시각 `HH:MM` (09:00~17:30, 30분 단위) |
| status | TEXT | NOT NULL, 기본 `active` | `active` / `cancelled` |
| created_at | TEXT | NOT NULL | 생성 시각 |
| cancelled_at | TEXT | NULL | 취소 시각 |

- **부분 유니크 인덱스**: `(room_id, rsv_date, slot_start) WHERE status='active'` — 같은 칸 중복 예약을 DB 차원에서 막는다(R-01). 취소된 행은 이력으로 남고 같은 칸을 다시 예약할 수 있다.

### 5.4 API 개요 (Phase 1)

| 메서드·경로 | 용도 | 기능 |
|---|---|---|
| `GET /api/users` | 사용자 목록 | F-04 |
| `GET /api/timetable?date=오늘` | 3개 회의실의 하루 칸 상태 | F-01 |
| `POST /api/reservations` | 칸 1개 예약 (room_id, slot_start, 사용자) | F-02 |
| `DELETE /api/reservations/{id}` | 예약 취소 (요청 사용자 포함) | F-03 |

### 5.5 가상 시드 데이터

- rr_user 5명(예: 김다온, 이소프트, 박예약, 최회의, 정시간), rr_room 3개, 데모용 예약 몇 건. 서버 시작 시 비어 있으면 넣는다.

## 6. 업무 규칙

| ID | 규칙 |
|---|---|
| R-01 | 같은 회의실·같은 날짜·같은 칸에는 활성 예약이 1건만 존재한다. 이미 예약된 칸을 예약하면 거절하고 "이미 예약된 시간입니다"를 알린다. |
| R-02 | 예약 가능한 칸은 09:00~17:30 시작 30분 단위 18칸뿐이다(마지막 칸은 18:00 종료). 범위 밖 시각은 거절한다. |
| R-03 | 이미 시작된 칸(현재 시각 이전에 시작한 칸)은 예약할 수 없다. |
| R-04 | 예약 취소는 예약한 본인만 할 수 있다. 다른 사용자의 예약 취소 요청은 거절한다(서버에서 검사). |
| R-05 | 이미 시작된 칸의 예약은 취소할 수 없다(지난 이력 보존). 시작 전인 내 예약만 취소 가능. |
| R-06 | 취소는 행을 삭제하지 않고 `status='cancelled'`, `cancelled_at` 을 기록한다. 시간표에는 활성 예약만 표시한다. |
| R-07 | 예약 1건 = 칸 1개(30분)이다. 연속 칸이 필요하면 칸마다 예약한다(Phase 1). |
| R-08 | 동시에 두 사람이 같은 칸을 눌러도 먼저 처리된 한 건만 성공한다(DB 유니크 인덱스로 보장). |

## 7. 제약 조건

- **기술**: FastAPI + 순수 HTML/JS + SQLite 로 한정한다. 프론트 프레임워크·번들러·외부 CDN 의존을 두지 않는다.
- **배포**: 사내 PC 한 대에서 `uvicorn` 으로 실행하는 단일 프로세스. SQLite 파일 1개.
- **데이터**: 가상 데이터만 사용한다. 실제 이름·이메일·사번 등 개인정보를 저장하지 않는다.
- **인증**: 없음. 사용자 선택은 편의 식별일 뿐 보안 수단이 아니다. 사내망 데모 전제이며, 서버 측 R-04 검사는 선택된 사용자 ID 를 신뢰하는 수준이다.
- **시간대**: 서버·화면 모두 KST. 서버 시각 기준으로 R-03, R-05 를 판정한다.
- **브라우저**: 최신 Chrome/Edge 데스크톱. 모바일 최적화는 하지 않는다.
- **규모**: 회의실 3개, 사용자 소수. 성능 요구는 별도로 두지 않는다(시간표 조회 1초 이내를 체감 기준으로 함).

## 8. 범위 밖

- 실제 로그인·SSO·권한 관리, 관리자 기능(남의 예약 강제 취소, 회의실 추가·수정)
- 반복(정기) 예약, 예약 변경(시간 이동), 승인 절차
- 알림(이메일·메신저), 캘린더(Outlook/Google) 연동
- 회의실 정보(수용 인원, 장비), 참석자 지정
- 09:00~18:00 외 시간, 주말·휴일 처리, 30분 외 단위
- 모바일 앱·반응형 디자인, 다국어
- 실제 직원 데이터 연동

## 9. 개발 단계

| Phase | 목표 | 포함 기능 | 비고 |
|---|---|---|---|
| 1 (MVP) | 오늘 시간표 보기·예약·내 예약 취소 | F-01, F-02, F-03, F-04 (전부 Must) | 규칙 R-01~R-08 전부 적용 |
| 2 | 사용 편의 확대 | F-05, F-06, F-07 (Should) | Phase 1 완료 기준 통과 후 착수 |
| 3 | 부가 기능 | F-08 (Could) | 필요 시 |

Phase 1 작업 순서: ① DB 스키마·시드 → ② 조회 API → ③ 예약·취소 API(R-01~R-08) → ④ 시간표 화면 → ⑤ 예약·취소 클릭 연결 → ⑥ 완료 기준 점검.

## 10. 완료 기준

Phase 1 이 아래를 모두 통과하면 완료로 본다.

### 조회 (F-01)
- [ ] T-01 첫 화면에 회의실 3개 열 × 09:00~17:30 18행 격자가 보인다.
- [ ] T-02 예약된 칸은 예약자 이름이 보이고, 내 예약은 다른 색으로 구분된다.
- [ ] T-03 현재 시각 이전 칸은 "지난 시간"으로 구분되어 눌러도 반응하지 않는다.

### 예약 (F-02)
- [ ] T-04 빈 칸을 누르면 격자에 즉시 내 예약으로 표시되고, 새로고침해도 유지된다.
- [ ] T-05 이미 예약된 칸을 API 로 다시 예약하면 거절되고 안내 메시지가 나온다(R-01).
- [ ] T-06 범위 밖 시각(예: 08:30, 18:00, 09:15)으로 예약 요청하면 거절된다(R-02).
- [ ] T-07 지난 시각 칸 예약 요청은 거절된다(R-03).
- [ ] T-08 같은 칸에 동시 요청 두 건을 보내면 한 건만 성공한다(R-08).

### 취소 (F-03)
- [ ] T-09 내 예약 칸을 누르고 확인하면 빈 칸으로 돌아오고, 새로고침해도 유지된다.
- [ ] T-10 다른 사용자의 예약을 취소하는 요청은 거절된다(R-04).
- [ ] T-11 이미 시작된 칸의 내 예약은 취소할 수 없다(R-05).
- [ ] T-12 취소한 칸은 DB 에 `cancelled` 로 남고, 같은 칸을 다시 예약할 수 있다(R-06).

### 사용자 선택 (F-04)
- [ ] T-13 사용자 드롭다운을 바꾸면 "내 예약" 표시가 바뀐 사용자 기준으로 갱신된다.
- [ ] T-14 선택한 사용자가 새로고침 후에도 유지된다.

### 공통
- [ ] T-15 표 이름이 모두 `rr_` 로 시작하고 DB 에는 가상 데이터만 있다.
- [ ] T-16 Phase 1 화면·API 에 Should/Could 기능(날짜 이동, 내 예약 목록, 연속 예약, 제목 입력)이 없다.
- [ ] T-17 `uvicorn` 실행 후 브라우저에서 위 시나리오 T-01~T-14 를 처음부터 끝까지 수행할 수 있다.
