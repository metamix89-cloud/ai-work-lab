# PRD — 꼬르륵식품 「유통기한 임박 재고 알림판」

> 「이 화면, PRD 로는 이렇게」 2부 2편(식품 · 유통 제조). 회사 · 직원 · 품목 · 로트는 모두 교육용 가상 데이터(꼬르륵식품은 가상 회사).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 꼬르륵식품 물류 창고는 로트마다 유통기한이 다른데, 출고 담당이 가까운 선반부터 꺼내다 보니 기한이 긴 로트가 먼저 나가고 짧은 로트가 남아 폐기됐다. 유통기한 당일 로트를 '만료' 로 보고 버린 일도, 만료 로트가 출고된 일도 있었다.
- **목적:** 한 화면에서 **임박 · 만료 로트**가 바로 보이고, 출고는 **서버가 유통기한이 가장 이른 로트부터**(선입선출이 아니라 **선기한선출**) 배분하며, **폐기는 만료 로트만** 관리자가 사유와 함께 한다.
- **성공 기준:** 만료 로트 출고 0건. 기한 긴 로트가 먼저 나가는 일 0건. 임박 재고 금액이 매일 숫자로 보인다.

## 2. 사용자

- **창고 담당 · 관리자 2유형.** 로그인 없이 화면 위 **사용자 선택 상자**에서 고른다. API 는 요청자를 본문의 `user`(user_id)로 받는다. **로그인은 8 범위 밖.**
- 창고 담당: 출고. 관리자: 출고 · 폐기.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 알림판: 로트마다 품목 · 로트 · 유통기한 · 남은 일수 · 수량 · 상태(정상 · 임박 · 만료) — 남은 일수 적은 순 | Must | 1 |
| F2 | 요약: 임박 로트 수 · 만료 로트 수 · 임박 재고 금액 | Must | 1 |
| F3 | 출고: 품목 · 수량을 적으면 서버가 로트를 배분(만료 제외, 유통기한 이른 순) | Must | 1 |
| F4 | 폐기: 만료 로트를 사유와 함께(관리자만) | Must | 1 |
| F5 | API: `GET /api/users` · `GET /api/items` · `GET /api/lots` · `POST /api/ship` · `POST /api/lots/{lot_id}/dispose` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위 사용자 선택과 출고 폼, 가운데 요약 3칸, 아래 알림판 표.

- **사용자 선택:** `data-testid="user"` (`<select>`, option 의 value 는 user_id). 처음엔 첫 번째 사용자.
- **출고 폼:** 품목 `data-testid="item"`(`<select>`) · 수량 `data-testid="qty"` · 출고 `data-testid="ship"`.
- **요약:** `data-testid="sum-near"` · `sum-expired` · `sum-near-value` — 안에 숫자(금액은 천 단위 쉼표 허용).
- **알림판 줄:** `data-testid="lot"` + `data-id`(lot_id) + `data-state`(ok · near · expired). 안에 품목 이름 · 유통기한 · 남은 일수 · 수량. 상태를 한글로(정상 · 임박 · 만료). 관리자이고 만료 로트면 폐기 `data-testid="dispose"` 버튼(사유 입력 `data-testid="reason"`) — 안내일 뿐, 막는 건 서버. 수량 0 인 로트(다 나간 로트)는 표에서 뺀다.
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로. 출고가 되면 `배분: L-… 3개, L-… 2개` 처럼 로트와 수량.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 3개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`expiry.db`)를 **새로** 만든다. 출고 · 폐기 결과는 DB 에 쓴다(서버가 도는 동안 유지).

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/users.csv` | `user_id, name, role` | `user_id` 문자열 `s1` · `role` `staff`(창고 담당) 또는 `manager`(관리자) |
| `seed/items.csv` | `item_id, name, unit_price, near_days` | `item_id` 문자열 `I01` · `unit_price` 원 단위 정수 `3500` · `near_days` 임박 기준 일수 0 이상 정수 `7` |
| `seed/lots.csv` | `lot_id, item_id, produced_on, expires_on, qty` | `lot_id` 문자열 `L-2401` · 날짜 `YYYY-MM-DD` · `qty` 0 이상 정수(0 = 다 나감) |

- **테이블:** 접두어 `ex_` — `ex_users` · `ex_items` · `ex_lots` · `ex_moves(lot_id, at, by, kind, qty, note)`.
- **가상 데이터:** 사용자 3명(창고 담당 2 · 관리자 1), 품목 5개(임박 기준이 다른 것 — 3 · 7 · 30일), 로트 10개 이상(정상 · 임박 · 만료 · 유통기한 당일 · 수량 0 이 다 있게). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/users` → `[{"user_id","name","role"}]`
  - `GET /api/items` → `[{"item_id","name","unit_price","near_days"}]`
  - `GET /api/lots` → `{"lots":[{"lot_id","item_id","item_name","produced_on","expires_on","days_left","qty","state"(ok|near|expired),"unit_price"}], "summary":{"near","expired","near_value"}, "today":"YYYY-MM-DD"}` — 수량 0 인 로트는 빼고, `days_left` 오름차순 · 같으면 `lot_id` 순
  - `POST /api/ship` 본문 `{"user":"s1","item_id":"I01","qty":5}` → 200 `{"allocations":[{"lot_id","qty"}], "lots":[...위와 같은 목록...], "summary":{...}}`
  - `POST /api/lots/{lot_id}/dispose` 본문 `{"user":"m1","reason":"..."}` → 200 `{"lot": 로트 하나, "summary":{...}}`
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **남은 일수** = `expires_on` − 오늘(서버 로컬 날짜), 날짜 단위. **상태:** 남은 일수 < 0 이면 `expired`(만료), 0 ≤ 남은 일수 ≤ 품목의 `near_days` 이면 `near`(임박), 그 밖은 `ok`. **유통기한 당일(남은 0)은 임박이지 만료가 아니다.** `near_days` 와 같은 날도 임박이다. |
| R2 | **출고는 선기한선출(FEFO).** 품목의 로트 중 **만료가 아닌** 것을 `expires_on` 이른 순(같으면 `lot_id` 순)으로 배분한다. 한 로트로 모자라면 다음 로트로 이어 간다. 임박 로트도 출고된다(먼저 나가야 하니까). |
| R3 | **부족하면 전부 거부.** 만료 아닌 로트의 수량 합이 요청 수량보다 적으면 409 `재고가 부족합니다`(만료 로트 수량은 세지 않는다) 이고 아무 로트도 줄지 않는다. 부분 출고는 없다. |
| R4 | **만료 로트는 출고되지 않는다** — 수량이 남아 있어도 배분에서 뺀다. |
| R5 | **폐기는 만료 로트만, 관리자만.** 창고 담당이면 403 `관리자만 할 수 있습니다`. 만료가 아닌 로트(임박 포함)는 409 `만료된 로트만 폐기할 수 있습니다`. 폐기하면 수량이 0 이 되고 `ex_moves` 에 사유가 남는다. 수량 0 인 로트의 폐기는 409 `이미 비어 있는 로트입니다`. |
| R6 | **요약.** `near` = 상태 `near` 인 로트 수(수량 0 제외) · `expired` = 상태 `expired` 인 로트 수(수량 0 제외) · `near_value` = 임박 로트의 `unit_price × qty` 합(원 단위 정수). |
| R7 | **입력.** `qty` 는 1 이상 정수(아니면 400 `수량을 확인하세요`). 폐기 `reason` 은 앞뒤 공백 뺀 길이 1~200자(아니면 400 `사유를 입력하세요`). `user` 가 문자열로 없으면 400 `사용자를 확인하세요`. |
| R8 | **거부가 둘 이상 해당하면 '무엇을 찾아야 알 수 있나' 순서로 하나만:** 본문만 보면 아는 것(400) → 없는 사용자 · 품목 · 로트(404) → 사용자를 찾아야 아는 권한(403) → 상태 · 수량을 봐야 아는 것(409). |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 수량 · 금액은 정수.
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- '오늘' 은 서버 로컬 날짜. 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원, 입고 · 로트 등록 · 수정(로트는 CSV 로만 들어온다), 할인 판매 · 가격 변경, 거래처 주문 연결, 바코드 · 사진, 알림 · 메일, 위생 점검 · 생산 일지(앱 지도의 다른 앱), **품목 · 로트 편집 화면(데이터 편집 화면)**, 엑셀 내려받기, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 5개와 규칙 R1~R8, `/` 화면(사용자 · 출고 폼 · 요약 · 알림판 · 메시지 · 오류).
2. 그 외 없음.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '유통기한' 이 보인다.
- [ ] T2 사용자 3명 · 품목 5개 · 로트 목록이 계약대로(수량 0 제외, 남은 일수 순) · 요약 (고정 데이터에서 near 5 · expired 2 · near_value 117,000).
- [ ] T3 상태 경계: 유통기한 당일은 `near`(만료 아님), 어제는 `expired`, 남은 일수 = `near_days` 는 `near`, 그보다 하루 더 남으면 `ok` (R1).
- [ ] T4 출고 배분: 한 로트로 모자라면 유통기한 이른 로트 → 다음 로트 순으로 이어지고, 생산일이 빨라도 유통기한이 늦은 로트는 뒤로 간다 (R2).
- [ ] T5 만료 로트는 수량이 있어도 배분에서 빠지고, 만료 아닌 수량 합을 넘는 요청은 409 이고 아무 로트도 줄지 않는다 (R3 · R4).
- [ ] T6 폐기: 창고 담당은 403, 임박 로트는 409, 빈 사유는 400, 관리자가 만료 로트를 사유와 함께 → 200 이고 수량 0 · 요약 expired 가 준다 (R5 · R6).
- [ ] T7 요약 near_value = 임박 로트의 단가 × 수량 합, 출고 뒤 줄어든다 (R6).
- [ ] T8 거부 순서: 본문 없음 + 없는 로트는 400, 없는 로트는 404, 없는 사용자는 404, 창고 담당이 정상 로트를 폐기하면 403(409 아님), 수량 0 요청은 400 (R7 · R8).
- [ ] T9 화면: 만료 로트 줄은 `data-state="expired"` · 당일 로트는 `near`, 요약 숫자가 보이고, 창고 담당에게는 폐기 버튼이 없고 관리자에게는 만료 줄에만 있다. 재고를 넘는 수량을 출고하면 메시지 줄에 `재고가 부족합니다`.
