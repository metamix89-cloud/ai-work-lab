- **U3(새 대화 · 깃 있음):** 3회 모두 바이트까지 같다. 3회 모두 `git log` · `git diff` 로 바뀐 것을 보고 **`git stash push`** 로 되돌렸다(`git restore` · `git checkout` 0회). 고친 내용이 지워지지 않고 stash 에 남는다 — 보고에 `git stash pop` 으로 되살릴 수 있다고 적음. 12~15초 · 3~5턴.
- **사람이 직접 칠 때(`git_demo.py`, AI 없음):** `git init` → `git add -A` → `git commit` → (broken 으로 덮어씀) → `git diff --stat`(3 files changed, 7 insertions, 6 deletions) → `git restore .` 0.04초. 줄 끝 변환을 끈 설정에서 6/6 일치.
  - 이 PC 의 git 기본 설정(`core.autocrlf=true`)에서는 되돌린 3개 파일의 줄 끝이 CRLF 로 써져 바이트 지문은 3/6 만 같다(내용은 같고 git 도 '변경 없음' 으로 본다). 그래서 U3 실측은 `core.autocrlf false` 로 맞췄다 — 설명란에 밝힌다.
  - AI 가 새로 만든 파일(커밋에 없던 파일)은 `git restore .` 뒤에도 남는다(`git status` 에 `??`).

## 실수 · 주의

1. 채점기가 base/ · broken/ 안에서 서버를 띄워 `dash.db` 가 생겼고, 그 뒤의 U1 · U2 · U3 폴더에 같이 복사됐다(U3 은 커밋에도 들어감). 서버가 켤 때마다 새로 만드는 파일이라 결과와 무관하고 세 조건에 같지만, 원래 계획엔 없던 파일이다. U2_3 이 보고에 dash.db 수정 시각을 언급했다.
2. 처음 9회 실행이 U3_3 직전에 끝났다(출력을 못 받아 원인 모름 — pythonw 를 PowerShell `>` 로 돌리면 로그가 비어 있다). U3_3 은 `Start-Process -Wait -RedirectStandardOutput` 으로 따로 돌렸다. 조건은 같다.
3. U3 의 `git status` 에 `?? build.json` 이 보이는 것은 run_build 가 작업 폴더에 쓴 기록 파일이다(AI 가 끝난 뒤).
4. '망친 상태' 는 한 번의 AI 출력 1개다. 고친 양이 작다(3개 파일 · 더한 줄 7).
5. 커밋 메시지 "AI 시키기 전" 과 요청의 "어제 누가 고쳤는데" 는 우리가 정한 말이다. U3 의 AI 는 셋 다 "어제 고쳤다는 기록은 git 에 없다" 고 적었다.
6. 비용(API 정가): 고치기 $0.11 + 복원 15회 $1.71 = $1.82. 채점은 로컬.
