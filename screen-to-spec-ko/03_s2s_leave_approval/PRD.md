# PRD — 다온소프트 「휴가 · 출장 신청과 결재」

> 「이 화면, PRD 로는 이렇게」 3편. 회사 · 직원 · 신청 내역은 모두 교육용 가상 데이터.
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 다온소프트는 휴가 · 출장을 메신저로 팀장에게 말하고, 인사팀이 엑셀에 옮긴다. 잔여 연차를 아무도 정확히 모르고, 반려 이유가 남지 않는다.
- **목적:** 직원이 **잔여 연차를 보며 신청**하고, **팀장만 승인 · 반려**하며, 반려에는 **사유가 남는다.** 잔여 연차를 넘는 신청은 서버가 거부한다.
- **성공 기준:** 잔여 연차 이견 0건. "왜 반려됐어요?" 질문이 사라진다.

## 2. 사용자

- **직원(신청자)** 과 **팀장(결재자)** 두 역할. 로그인 없이 화면 위 **사용자 선택 상자**에서 이름을 고른다(역할은 `seed/users.csv` 의 `role`). 팀장도 자기 휴가는 신청자로 낸다(결재는 그 팀장의 팀장 — 이 편에서는 팀장의 신청은 범위 밖).

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 잔여 연차 카드: 총 · 사용(승인) · 대기(신청 중) · 잔여 | Must | 1 |
| F2 | 신청: 종류(연차 · 출장) · 시작일 · 종료일 · 사유 → 서버가 일수 계산(주말 제외)과 규칙 검사 | Must | 1 |
| F3 | 내 신청 목록: 상태(신청 · 승인 · 반려 · 취소) · 일수 · 결재자 · 반려 사유 | Must | 1 |
| F4 | 팀장 화면: 내 팀의 '신청' 상태 목록 + 승인 · 반려(사유 필수) 버튼 | Must | 1 |
| F5 | 신청자 취소: '신청' 상태에서만 | Must | 1 |
| F6 | API: `GET /api/users` · `GET /api/balance?user=` · `GET /api/requests?user=` · `GET /api/requests?approver=` · `POST /api/requests` · `POST /api/requests/{id}/approve` · `POST /api/requests/{id}/reject` · `POST /api/requests/{id}/cancel` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위에서 아래로:

- **위:** 제목 `다온소프트 휴가 · 출장`, 사용자 선택 상자(`<select data-testid="user-select">`, 옵션은 `/api/users` 의 이름). 고른 사용자의 `role` 이 `manager` 면 **결재 대기** 구역이 추가로 보인다.
- **잔여 연차 카드:** `총 15 · 사용 2 · 대기 1 · 잔여 12` — 잔여 숫자 요소 `data-testid="remaining"`.
- **신청 폼:** 종류(`data-testid="type"` select: 연차 · 출장) · 시작(`data-testid="start"`) · 종료(`data-testid="end"`) · 사유(`data-testid="reason"`) · 신청 버튼(`data-testid="submit-btn"`). 서버가 거부하면 메시지 줄(`data-testid="message"`)에 `detail` 그대로.
- **내 신청 목록:** 행마다 `data-testid="my-request"`, 속성 `data-id` · `data-status`. '신청' 상태 행에는 취소 버튼(`data-testid="cancel-btn"`).
- **결재 대기(팀장만):** 행마다 `data-testid="pending-request"`, 속성 `data-id`, 승인 버튼(`data-testid="approve-btn"`) · 반려 버튼(`data-testid="reject-btn"`, 누르면 사유 입력 `data-testid="reject-reason"`). 직원 화면에는 이 구역이 없다.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 시각 요소 이름은 완료 기준 테스트가 집는 손잡이다. 바꾸지 않는다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 2개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`leave.db`)를 **새로** 만든다. 신청 · 결재는 DB 에 쓴다(서버가 도는 동안 유지).
  - `seed/users.csv` — `user, team, role(member|manager), manager(팀장 이름, 팀장 본인은 빈칸), leave_total`
  - `seed/requests.csv` — `req_id, user, type(연차|출장), start(YYYY-MM-DD), end(YYYY-MM-DD), days, reason, status(신청|승인|반려|취소), approver, reject_reason`
- **테이블:** 접두어 `lv_` — `lv_users` · `lv_requests`. 칸은 CSV 와 같다.
- **가상 데이터:** 직원 5명(팀장 2) · 신청 4건. **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다(파일 이름 · 칸 이름 고정).
- **API**
  - `GET /api/users` → `[{"user":"박지연","team":"개발팀","role":"member","manager":"김민수","leave_total":15}, ...]`
  - `GET /api/balance?user=박지연` → `{"total":15,"used":2,"pending":1,"remaining":12}` (연차만 센다. 출장은 차감 없음)
  - `GET /api/requests?user=박지연` → 내 신청 목록(최신 먼저). `GET /api/requests?approver=김민수` → 그 팀장이 결재할 `status=신청` 목록
  - `POST /api/requests` 본문 `{"user":"박지연","type":"연차","start":"2026-11-05","end":"2026-11-09","reason":"가족 행사"}` → 201 과 만든 신청(`days` 는 서버가 계산). 거부 400(잔여 부족 · 날짜 · 빈 값) · 409(기간 겹침)
  - `POST /api/requests/{id}/approve` 본문 `{"approver":"김민수"}` → 200 과 갱신된 신청. 403(결재자 아님) · 409(이미 결정됨)
  - `POST /api/requests/{id}/reject` 본문 `{"approver":"김민수","reason":"프로젝트 마감 주간"}` → 200. 400(사유 없음) · 403 · 409
  - `POST /api/requests/{id}/cancel` 본문 `{"user":"박지연"}` → 200. 403(본인 아님) · 409('신청' 상태가 아님)
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **일수는 서버가 센다 — 주말 제외.** `start`~`end` 의 토 · 일을 뺀 날 수. 11-05(목)~11-09(월) = 3일. `end < start` 면 400 `종료일이 시작일보다 빠릅니다`. |
| R2 | **잔여 연차 = 총 − 사용(승인된 연차 일수) − 대기(신청 중 연차 일수).** 연차 신청 일수가 잔여보다 크면 400 `잔여 연차가 부족합니다`. 출장은 차감하지 않고 잔여를 검사하지 않는다. |
| R3 | **결재는 신청자의 팀장만.** `approver` 가 `users.csv` 의 `manager` 와 다르면 403 `결재 권한이 없습니다`. 본인 승인도 403. |
| R4 | **반려는 사유 필수.** `reason` 이 비면 400 `반려 사유를 입력하세요`. 사유는 신청에 남는다. |
| R5 | **결정은 한 번.** `status` 가 `신청` 이 아닌 건에 승인 · 반려 · 취소를 하면 409 `이미 처리된 신청입니다`. |
| R6 | **같은 사람의 기간 겹침 금지.** `status` 가 `신청` 또는 `승인` 인 내 신청과 날짜가 하루라도 겹치면 409 `이미 신청한 기간과 겹칩니다`. (반려 · 취소된 건은 겹침에 안 센다) |
| R7 | **취소는 본인이, '신청' 상태에서만.** 다른 사람이면 403, 이미 결정됐으면 409. |
| R8 | 결재 대기 목록은 **그 팀장의 팀원** 것만. 다른 팀 신청은 보이지 않는다. |

(실측 뒤 메모: 거부가 둘 다 해당할 때의 **순서**(잔여 부족 400 vs 기간 겹침 409)를 이 PRD 는 정하지 않았다. PRD 만 받은 B 셋 중 둘은 잔여, 하나는 겹침을 먼저 거부했고, 완료 기준이 묻지 않아 C 의 보고에도 안 나왔다. 공개본에는 빈틈을 그대로 둔다 — 3편 영상의 재료. 다음 편부터 '거부의 순서' 줄을 넣는다.)

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.**
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 날짜는 `YYYY-MM-DD`.
- 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 권한 관리, 다단계 결재(팀장 → 본부장), 대결(대리 결재), 팀장 본인의 신청 결재, 반차 · 시간 단위, 공휴일 달력(주말만 뺀다), 연차 이월 · 촉진, 알림 · 메일, 캘린더 · 월간 보기, 첨부 파일, 엑셀 내보내기, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 8개와 규칙 R1~R8, `/` 화면(잔여 카드 · 폼 · 내 목록 · 팀장 결재 대기), 오류 상태.
2. 그 외 없음.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '휴가' 가 보인다.
- [ ] T2 사용자를 박지연으로 고르면 잔여 `12` 가 보이고 내 신청 행이 고정 데이터 수만큼 있다.
- [ ] T3 11-05(목)~11-09(월) 연차 `POST` 는 201 이고 `days` 가 3 이다 (주말 제외).
- [ ] T4 잔여(12)를 넘는 연차 신청은 400 이다. 같은 기간 출장은 201 이다 (출장은 차감 없음).
- [ ] T5 팀장이 아닌 사람의 승인은 403, 팀장의 승인은 200 이고 상태가 `승인`, 잔여가 그만큼 준다.
- [ ] T6 사유 없는 반려는 400, 사유 있는 반려는 200 이고 사유가 남는다.
- [ ] T7 이미 승인된 건을 다시 승인 · 반려하면 409 다.
- [ ] T8 `신청` · `승인` 상태와 겹치는 기간은 409, 반려된 건과 겹치는 기간은 201 이다.
- [ ] T9 화면에서 팀장(김민수)에게는 결재 대기 행과 승인 버튼이 보이고, 직원(박지연)에게는 결재 대기 구역이 없다.
