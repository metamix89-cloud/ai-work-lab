# PRD — 다온소프트 「사내 소식 피드」

> 「이 화면, PRD 로는 이렇게」 12편. 회사 · 직원 · 글은 모두 교육용 가상 데이터.
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 사내 메신저 공지방이 잡담에 묻혀 중요한 공지를 못 보고, 남의 글을 지우거나 같은 글이 '더 보기' 에서 두 번 나온다는 불만이 이어졌다.
- **목적:** 직원이 짧은 글과 댓글을 쓰고, 운영자가 공지를 **맨 위에 고정**하고, 피드는 **20개씩 더 보기**로 겹치지도 빠지지도 않게 넘긴다. 삭제 · 신고는 **서버가 정한 규칙**대로.
- **성공 기준:** 남의 글 삭제 0건. '더 보기' 에서 같은 글 두 번 0건.

## 2. 사용자

- **직원 · 운영자 2유형.** 로그인 없이 화면 위 **사용자 선택 상자**에서 고른다. API 는 요청자를 본문의 `user` 또는 쿼리의 `viewer`(user_id)로 받는다. **로그인은 8 범위 밖.**
- 직원: 글 · 댓글 쓰기, 자기 글 삭제, 신고. 운영자: 그에 더해 공지 고정 · 해제, 누구 글이든 삭제.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 피드: 고정 공지(맨 위) + 일반 글 최신 순 20개, '더 보기' 로 다음 20개 | Must | 1 |
| F2 | 글 쓰기 · 댓글 쓰기 | Must | 1 |
| F3 | 삭제(본인 · 운영자) · 고정(운영자) · 신고 | Must | 1 |
| F4 | API: `GET /api/users` · `GET /api/posts` · `POST /api/posts` · `DELETE /api/posts/{post_id}` · `POST /api/posts/{post_id}/pin` · `POST /api/posts/{post_id}/reports` · `POST /api/posts/{post_id}/comments` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위 사용자 선택과 글 쓰기, 아래 피드.

- **사용자 선택:** `data-testid="user"` (`<select>`, option 의 value 는 user_id). 처음엔 첫 번째 사용자.
- **글 쓰기:** 입력 `data-testid="compose"`, 올리기 `data-testid="submit"`.
- **글:** `data-testid="post"` + `data-id`(post_id) + `data-pinned="1|0"`. 안에 작성자 · 시각 · 본문 · 댓글 수. 고정 글엔 `공지` 표시. 그 사용자가 할 수 있는 동작만 버튼으로(삭제 `data-testid="delete"`, 고정 `data-testid="pin"`, 신고 `data-testid="report"`) — 안내일 뿐, 막는 건 서버.
- **더 보기:** `data-testid="more"` — 다음 쪽이 없으면 숨긴다. 누르면 아래에 **이어 붙인다**.
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 4개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`feed.db`)를 **새로** 만든다. 쓴 글 · 삭제 · 신고는 DB 에 쓴다(서버가 도는 동안 유지).

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/users.csv` | `user_id, name, role` | `user_id` 문자열 `u1` · `role` `member` 또는 `admin` |
| `seed/posts.csv` | `post_id, author_id, body, created_at, pinned` | `post_id` 문자열 `P001` · `created_at` `2026-10-24 09:10` · `pinned` `1` 또는 `0` |
| `seed/comments.csv` | `comment_id, post_id, author_id, body, created_at` | `comment_id` 문자열 `C001` |
| `seed/reports.csv` | `post_id, reporter_id` | 한 줄 = 신고 한 건 |

- 새로 쓰는 글 · 댓글의 id 는 서버가 정한다(기존 id 와 겹치지 않게). 시각은 서버의 지금.
- **테이블:** 접두어 `fd_` — `fd_users` · `fd_posts` · `fd_comments` · `fd_reports`.
- **가상 데이터:** 사용자 5명(운영자 1), 글 45개 이상(고정 2), 댓글 몇 개, 신고 2건이 있는 글 하나. **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/users` → `[{"user_id","name","role"}]`
  - `GET /api/posts?viewer=u1[&before=<커서>]` → `{"pinned":[글...], "posts":[글 최대 20개], "next_cursor": 문자열 또는 null}`. 글 = `{"post_id","author_id","author_name","body","created_at","pinned","comment_count","hidden"}`. `before` 가 있으면 `pinned` 는 빈 목록.
  - `POST /api/posts` 본문 `{"user":"u1","body":"..."}` → 201 글
  - `DELETE /api/posts/{post_id}` 본문 `{"user":"u1"}` → 200 `{"deleted": post_id}`
  - `POST /api/posts/{post_id}/pin` 본문 `{"user":"a1","pinned":true|false}` → 200 글
  - `POST /api/posts/{post_id}/reports` 본문 `{"user":"u3"}` → 201 `{"reports": 건수, "hidden": true|false}`
  - `POST /api/posts/{post_id}/comments` 본문 `{"user":"u1","body":"..."}` → 201 `{"comment_id", ...}`
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **순서.** 고정 글은 첫 쪽 `pinned` 에만, 고정끼리 최신 순. 일반 글(고정 아님)은 `created_at` 최신 순, 같으면 `post_id` 큰 순. 삭제된 글은 어디에도 없다. |
| R2 | **더 보기는 커서로.** 한 쪽 20개. `next_cursor` 는 '이 쪽의 마지막 글' 을 가리키고, 다음 쪽은 **그 글보다 오래된 글부터** 20개. 쪽 번호(건너뛸 개수)로 나누지 않는다 — **첫 쪽을 본 뒤 새 글이 올라와도 다음 쪽에 같은 글이 다시 나오거나 빠지면 안 된다.** 마지막 쪽이면 `next_cursor` 는 null. |
| R3 | **글 · 댓글 본문.** 앞뒤 공백을 뺀 길이 1~500자. 아니면 400 `내용을 확인하세요`. |
| R4 | **삭제.** 자기 글은 직원도, 남의 글은 운영자만 — 아니면 403 `본인 글만 지울 수 있습니다`. 지운 글에 다시 동작하면 404. 지운 글의 댓글 · 신고도 함께 안 보인다. |
| R5 | **고정.** 운영자만(아니면 403 `운영자만 할 수 있습니다`). 고정은 **최대 3개** — 넷째 고정은 409 `고정은 3개까지입니다`. 이미 그 상태로 바꾸면 그대로 200. |
| R6 | **신고.** 자기 글은 신고할 수 없다(403 `자기 글은 신고할 수 없습니다`). 같은 사람이 같은 글을 두 번 신고하면 409 `이미 신고했습니다`. **서로 다른 3명**이 신고하면 그 글은 `hidden` — 작성자와 운영자에게만 보이고(`hidden: true`), 다른 사람의 피드에서는 빠진다. |
| R7 | **입력.** `user` · `viewer` 가 문자열로 없으면 400 `사용자를 확인하세요`. |
| R8 | **거부가 둘 이상 해당하면 '무엇을 찾아야 알 수 있나' 순서로 하나만:** 본문만 보면 아는 것(400) → 없는 글 · 사용자(404) → 사용자 · 글을 찾아야 아는 권한(403) → 지금 상태를 봐야 아는 것(409). |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.**
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 화면은 본문을 **글자 그대로**(HTML 로 해석하지 않고) 보여 준다.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원, 글 고치기, 좋아요 · 반응, 이미지 · 파일 첨부, 멘션 · 알림, 검색 · 해시태그, 대댓글, 신고 처리 화면(운영자 검토 · 복구), **사용자 · 글 편집 화면(데이터 편집 화면)**, 실시간 갱신(웹소켓), 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 7개와 규칙 R1~R8, `/` 화면(사용자 선택 · 글 쓰기 · 피드 · 더 보기 · 메시지 · 오류).
2. 그 외 없음.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '소식' 이 보인다.
- [ ] T2 첫 쪽: 고정 글 2개가 `pinned` 에(최신 순), 일반 글 20개가 최신 순, `next_cursor` 가 있다 (R1).
- [ ] T3 첫 쪽을 받은 뒤 새 글을 올리고 `next_cursor` 로 다음 쪽을 받으면, 겹치는 글도 빠진 글도 없다. 셋째 쪽이 마지막이면 `next_cursor` 는 null (R2).
- [ ] T4 빈 글 · 공백만 · 501자는 400, 500자는 201 이고 새 글이 첫 쪽 일반 글 맨 앞에 온다 (R3).
- [ ] T5 직원이 남의 글을 지우면 403, 자기 글은 200 이고 피드에서 빠지며, 운영자는 남의 글도 지운다. 지운 글에 댓글을 달면 404 (R4).
- [ ] T6 직원의 고정은 403, 운영자의 고정은 첫 쪽 `pinned` 에 들어가고, 넷째 고정은 409 (R5).
- [ ] T7 자기 글 신고는 403, 같은 사람의 두 번째 신고는 409, 셋째 신고로 숨겨지면 다른 직원의 피드에서 빠지고 작성자 · 운영자에게는 `hidden: true` 로 보인다 (R6).
- [ ] T8 `user` 없음 + 없는 글은 400, 없는 글은 404, 없는 사용자는 404, 직원이 이미 고정 3개인 상태에서 고정하면 403(409 아님) (R7 · R8).
- [ ] T9 화면: 고정 글이 `data-pinned="1"` 로 맨 위, '더 보기' 를 누르면 글이 40개(일반)로 늘고 겹치는 `data-id` 가 없으며, 빈 글을 올리면 메시지 줄에 `내용을 확인하세요`, `<b>굵게</b>` 를 올리면 글자 그대로 보인다.
