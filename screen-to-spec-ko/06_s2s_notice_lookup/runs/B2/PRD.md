# PRD — 푸른구청 「고시 · 공고 열람」

> 「이 화면, PRD 로는 이렇게」 6편. 구청 · 부서 · 고시 · 링크는 모두 교육용 가상 데이터(실제 법령 · 고시 · 수치가 아니다).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 푸른구청 민원실에는 "공영주차장 요금 바뀌었어요?", "음식점 위생 점검 기준이 언제부터예요?" 같은 문의가 온다. 고시 · 공고는 부서마다 다른 게시판에 있고, 직원이 만든 요약이 원문처럼 퍼진다. 폐지된 고시를 보고 안내하는 일도 생긴다.
- **목적:** 주민과 민원 담당자가 **지금 시행 중이거나 시행 예정인 고시**를 분야별로 찾고, 항목마다 **어느 부서가 언제 공고했고 언제부터인지, 원문은 어디인지**가 보이며, **요약은 요약이라고 표시**되어 원문과 섞이지 않는다.
- **성공 기준:** "그 고시 폐지됐어요" 안내 0건. 요약만 보고 잘못 안내한 민원 0건.

## 2. 사용자

- **주민 · 민원 담당자 1유형.** 로그인 없이 연다. 찾고 읽기만 한다. 고시를 올리고 고치는 건 각 부서의 다른 도구(범위 밖).

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 목록: 분야(주차 · 위생 · 건축 · 복지) 필터 + 검색어 | Must | 1 |
| F2 | 카드: 상태 배지(시행 중 · 시행 예정 D-n · 폐지) · 제목 · 부서 · 공고일 · 시행일 · 원문 링크 | Must | 1 |
| F3 | 상세: 원문 전문과 담당자 요약을 **나란히, 구분해서** | Must | 1 |
| F4 | 폐지 포함 보기: 기본은 숨김, '폐지 포함' 을 켜면 폐지 고시도 '폐지' 배지로 | Must | 1 |
| F5 | 기준일 표시: 목록 위에 `기준일 YYYY-MM-DD` — 서버가 준 값 | Must | 1 |
| F6 | API: `GET /api/categories` · `GET /api/notices` · `GET /api/notices/{id}` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위에서 아래로:

- **위:** 제목 `푸른구청 고시 · 공고 열람`, 분야 선택(`data-testid="category"`: 전체 · 주차 · 위생 · 건축 · 복지), 검색창(`data-testid="q"`) · 검색 버튼(`data-testid="search-btn"`), 폐지 포함 체크(`data-testid="include-repealed"`), 기준일(`data-testid="as-of"`, `/api/notices` 의 `as_of` 값).
- **목록:** 건수(`data-testid="count"`). 카드마다 `data-testid="notice"`, 속성 `data-id` · `data-status`(`시행 중` | `시행 예정` | `폐지`). 카드 안: 배지(`data-testid="badge"`, 시행 예정은 `시행 예정 D-3` 처럼), 제목, `부서 · 공고 YYYY-MM-DD · 시행 YYYY-MM-DD`, 원문 링크(`<a data-testid="source-link" href="...">원문</a>`).
- **상세(카드를 누르면):** 왼쪽 원문 전문(`data-testid="original"`), 오른쪽 요약(`data-testid="summary"`). 요약 칸 머리에 **`요약 — 법적 효력은 원문에 있습니다`**. 요약이 없으면 `요약 없음 — 원문을 보세요`. 원문을 잘라 요약처럼 보여 주지 않는다.
- **없음 상태:** `data-testid="no-result"` 에 `해당 고시 없음`.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 시각 요소 이름은 완료 기준 테스트가 집는 손잡이다. 바꾸지 않는다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/notices.csv`. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`notice.db`)를 **새로** 만든다.
  - `seed/notices.csv` — `notice_id, title, category(주차|위생|건축|복지), issuer(부서), published(공고일), effective_from(시행일), repealed(폐지일 또는 빈칸), source_url(원문 링크 또는 빈칸), original(원문 본문), summary(담당자 요약 또는 빈칸)`
- **테이블:** 접두어 `nt_` — `nt_notices`. 칸은 CSV 와 같다.
- **기준일:** 서버의 오늘 날짜. 모든 상태 계산과 화면의 기준일 표시는 이 값 하나를 쓴다(화면이 따로 계산하지 않는다).
- **가상 데이터:** 고시 10건(분야 4개, 시행 예정 2 · 폐지 2 · 원문 링크 없음 1 · 요약 없음 2). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/categories` → `["주차","위생","건축","복지"]`
  - `GET /api/notices?category=&q=&include_repealed=0` → `{"as_of":"2026-10-24","count":6,"items":[{"notice_id","title","category","issuer","published","effective_from","repealed","status","days_until","source_url","summary","has_summary"}]}` — `days_until` 은 시행 예정일 때만 숫자(아니면 `null`), `summary` 는 CSV 그대로(없으면 `""`).
  - `GET /api/notices/{id}` → 위 칸 + `original`. 없으면 404.
  - 거부: 알 수 없는 분야는 400 `알 수 없는 분야입니다`, `include_repealed` 가 0 · 1 이 아니면 400. 응답은 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **상태는 기준일로 셈.** `repealed` 가 있고 `<= 기준일` 이면 `폐지`. 아니면 `effective_from > 기준일` 이면 `시행 예정`(`days_until` = 날짜 차), 그 밖은 `시행 중`. |
| R2 | **폐지는 기본 숨김.** `include_repealed=0` 이면 `폐지` 는 목록에서 빠진다. `1` 이면 포함한다(상세 API 는 언제나 열린다). |
| R3 | **출처 없는 자료는 싣지 않는다.** `source_url` 이 빈 행은 목록 · 검색 · 상세 어디에도 나오지 않는다(상세는 404). |
| R4 | **요약은 요약이다.** `summary` 는 CSV 값 그대로. 비어 있으면 `""` 와 `has_summary: false` — 원문을 잘라 만들지 않는다. 화면은 요약 칸에 `요약 — 법적 효력은 원문에 있습니다` 표시. |
| R5 | **검색은 단어 모두 포함(AND)** — 제목 · 요약 · 원문에서. 분야 필터와 함께 쓰면 둘 다 만족. |
| R6 | **정렬:** 공고일 최신 먼저, 같으면 `notice_id` 순. |
| R7 | **거부가 둘 이상 해당하면** 400(입력 오류) → 404(없는 고시) 순서로 먼저 걸리는 것 하나만. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 요약 생성 · 외부 법령 API · 크롤링 · LLM 금지(이 편은 '출처 · 날짜 · 요약 구분' 이 주제).
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI. 원문 링크는 새 탭으로 열되 서버가 그 주소를 불러오지 않는다.

## 8. 범위 밖 (Won't)

- 로그인 · 권한, **고시 등록 · 수정 · 삭제 화면(데이터 편집 화면)**, 자동 요약(LLM) · 원문 크롤링 · 외부 법령 API, 알림 구독 · 메일, 첨부 파일 뷰어 · PDF, 인쇄 · 엑셀, 즐겨찾기, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 3개와 규칙 R1~R7, `/` 화면(필터 · 검색 · 카드 · 상세 원문/요약 · 폐지 포함 · 기준일 · 없음 · 오류).
2. 그 외 없음.
