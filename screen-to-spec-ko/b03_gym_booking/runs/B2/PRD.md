# PRD — 으랏차차헬스 「수업 예약 · 회원권 차감」

> 「이 화면, PRD 로는 이렇게」 2부 3편(생활 서비스 · 헬스장 · 학원 · 미용). 회사 · 회원 · 트레이너 · 수업은 모두 교육용 가상 데이터(으랏차차헬스는 가상 회사).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 으랏차차헬스 PT 수업은 10회권 · 20회권 회원이 수업 시간을 예약해서 온다. 데스크가 수첩으로 적다 보니, 잔여 2회인 회원이 5개를 예약해 두고, 안 온 수업(노쇼)을 깎을지 말지가 트레이너마다 달랐고, 정원 4명인 수업에 5명이 왔다.
- **목적:** 회원이 **남은 횟수 안에서만** 예약하고, **출석 · 노쇼는 1회 차감, 제때 취소는 차감 없음**이 자동으로 지켜지며, 정원과 노쇼 누적을 서버가 막는다.
- **성공 기준:** 잔여보다 많은 예약 0건. 정원 초과 0건. 노쇼 차감 기준에 대한 데스크 · 회원 다툼 0건.

## 2. 사용자

- **회원 · 데스크 2유형.** 로그인 없이 화면 위 **사용자 선택 상자**에서 고른다. API 는 요청자를 본문의 `user` 또는 쿼리의 `viewer`(user_id)로 받는다. **로그인은 8 범위 밖.**
- 회원: 자기 예약 · 자기 취소. 데스크: 누구 예약이든 대신 예약 · 취소, 출석 · 노쇼 처리.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 내 회원권 카드: 종류 · 잔여 횟수 · 예약 중 · 예약 가능 · 유효기간 | Must | 1 |
| F2 | 수업 목록: 시간 · 트레이너 · 정원 · 남은 자리 · 예약 버튼 | Must | 1 |
| F3 | 예약 목록: 수업 · 상태(예약 · 출석 · 노쇼 · 취소) · 그 사용자가 할 수 있는 동작(취소 · 출석 · 노쇼) | Must | 1 |
| F4 | API: `GET /api/users` · `GET /api/slots` · `GET /api/passes/{member_id}` · `GET /api/bookings` · `POST /api/bookings` · `POST /api/bookings/{booking_id}/{action}` (`action` = `cancel` · `attend` · `noshow`) | Must | 1 |

## 4. 화면

한 페이지(`/`). 위 사용자 선택, 왼쪽 회원권 카드와 수업 목록, 오른쪽 예약 목록.

- **사용자 선택:** `data-testid="user"` (`<select>`, option 의 value 는 user_id). 처음엔 첫 번째 사용자. 데스크가 고르면 **회원 선택** `data-testid="member"`(`<select>`)이 더 보인다(누구 대신 예약하나).
- **회원권 카드:** `data-testid="pass-left"`(잔여) · `pass-held`(예약 중) · `pass-avail`(예약 가능) · `pass-expires`(유효기간) — 안에 숫자 · 날짜.
- **수업 줄:** `data-testid="slot"` + `data-id`(slot_id). 안에 시간 · 트레이너 · `남은 자리 N`. 예약 `data-testid="book"`(자리가 있고 예약 가능 횟수가 1 이상일 때만 — 안내일 뿐, 막는 건 서버).
- **예약 줄:** `data-testid="booking"` + `data-id`(booking_id) + `data-status`(booked · attended · noshow · cancelled). 동작 버튼 취소 `data-testid="act-cancel"` · 출석 `act-attend` · 노쇼 `act-noshow` — 그 사용자가 그 상태에서 할 수 있는 것만.
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 4개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`gym.db`)를 **새로** 만든다. 예약 · 상태 변화는 DB 에 쓴다(서버가 도는 동안 유지).

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/users.csv` | `user_id, name, role` | `user_id` 문자열 `c1` · `role` `member`(회원) 또는 `desk`(데스크) |
| `seed/passes.csv` | `member_id, kind, total, used, expires_on` | `kind` `PT 10회권` · `total` 총 횟수 · `used` 이미 쓴 횟수(차감 합) · `expires_on` `YYYY-MM-DD` — 회원마다 한 줄 |
| `seed/slots.csv` | `slot_id, starts_at, trainer, capacity` | `slot_id` 문자열 `S-101` · `starts_at` `2026-10-25 18:00` · `capacity` 1 이상 정수 |
| `seed/bookings.csv` | `booking_id, slot_id, member_id, status` | `booking_id` 문자열 `B-1001` · `status` `booked` · `attended` · `noshow` · `cancelled` |

- 새 예약의 `booking_id` 는 서버가 정한다(기존 id 와 겹치지 않게).
- **테이블:** 접두어 `gy_` — `gy_users` · `gy_passes` · `gy_slots` · `gy_bookings` · `gy_log(booking_id, at, by, action)`.
- **가상 데이터:** 회원 5명(잔여가 넉넉한 · 잔여 2 · 0회 · 만료된 · 노쇼 3회인 회원), 데스크 1명, 수업 6개(지난 것 · 곧 시작 · 오늘 저녁 · 내일, 정원 2~4), 예약 8개 이상(네 상태 다). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/users` → `[{"user_id","name","role"}]`
  - `GET /api/slots` → `[{"slot_id","starts_at","trainer","capacity","booked","left"}]` 시작 시각 순 (`booked` = 상태 `booked` 인 예약 수, `left` = `capacity − booked`)
  - `GET /api/passes/{member_id}` → `{"member_id","kind","total","used","left","held","available","expires_on","expired"}` — `left` = `total − used` · `held` = 상태 `booked` 인 예약 수 · `available` = `left − held` · `expired` = 유효기간이 오늘보다 앞
  - `GET /api/bookings?viewer=c1` → `[{"booking_id","slot_id","starts_at","trainer","member_id","member_name","status"}]` — 회원이면 자기 것만, 데스크면 전부. 시작 시각 순
  - `POST /api/bookings` 본문 `{"user":"c1","member_id":"c1","slot_id":"S-101"}` → 201 예약 하나
  - `POST /api/bookings/{booking_id}/cancel` · `/attend` · `/noshow` 본문 `{"user":"d1"}` → 200 예약 하나
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **예약 가능 횟수 = 잔여 − 예약 중.** 예약은 `available ≥ 1` 일 때만 — 아니면 409 `예약 가능 횟수가 없습니다`. 잔여 2회에 예약 2개면 세 번째는 막힌다. |
| R2 | **유효기간.** 수업 날짜(`starts_at` 의 날짜)가 `expires_on` 보다 뒤면 409 `회원권 유효기간이 지났습니다`. 유효기간 당일 수업은 된다. |
| R3 | **정원.** 슬롯의 `booked` 가 `capacity` 에 닿으면 409 `정원이 찼습니다`. 같은 회원이 같은 슬롯에 이미 `booked` 면 409 `이미 예약한 수업입니다`. **지난 수업**(`starts_at` 이 지금보다 앞)은 409 `지난 수업입니다`. |
| R4 | **차감 시점.** 예약 때는 차감하지 않는다(예약 중으로만 센다). **출석 `attend` 와 노쇼 `noshow` 는 각각 `used` 를 1 늘린다.** 취소는 늘리지 않는다. |
| R5 | **취소 마감.** 취소는 수업 시작 **2시간 전까지** — 그 뒤는 409 `취소 마감이 지났습니다 (시작 2시간 전까지)`. 2시간 전 딱 그 시각은 된다. |
| R6 | **상태.** `booked` 에서만 `cancel` · `attend` · `noshow` 가 된다. 그 밖은 409 `지금 상태에서는 할 수 없습니다`. `attend` · `noshow` 는 수업 시작 시각이 지난 뒤에만 — 아직 안 시작했으면 409 `아직 시작하지 않은 수업입니다`. |
| R7 | **노쇼 누적.** 최근 30일(오늘 포함) 노쇼가 3회 이상인 회원은 새 예약이 409 `노쇼 3회 — 데스크에 문의하세요`. 데스크가 대신 예약해도 같다. |
| R8 | **권한.** 회원은 `member_id` 가 자기 자신인 예약만 만들고(아니면 403 `본인 예약만 할 수 있습니다`), 자기 예약만 취소한다(남의 것은 403). `attend` · `noshow` 는 데스크만(회원이면 403 `데스크만 할 수 있습니다`). `GET /api/bookings` 는 회원이면 자기 것만. |
| R9 | **입력과 거부 순서.** `user` 가 문자열로 없으면 400 `사용자를 확인하세요`. 거부가 둘 이상이면 **'무엇을 찾아야 알 수 있나'** 순서로 하나만: 본문만 보면 아는 것(400) → 없는 사용자 · 회원 · 슬롯 · 예약(404) → 사용자를 찾아야 아는 권한(403) → 시각 · 횟수 · 정원 · 상태(409). 409 끼리는 지난 수업 → 상태 → 유효기간 → 노쇼 누적 → 예약 가능 횟수 → 정원 → 중복 순. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 횟수는 정수.
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- '지금' 은 서버 로컬 시각, '오늘' 은 서버 로컬 날짜. 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원가입, 회원권 구매 · 연장 · 환불, 결제, 수업 개설 · 트레이너 배정(슬롯은 CSV 로만), 대기 순번, 문자 · 알림, 출석 QR, 통계, **회원 · 수업 편집 화면(데이터 편집 화면)**, 다크 모드.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '예약' 이 보인다.
- [ ] T2 사용자 6명 · 수업 목록(시작 순, `left` 계산) · 회원권 카드(`left` · `held` · `available`) · 예약 목록이 계약대로(회원은 자기 것만).
- [ ] T3 예약 가능 횟수: 잔여 2 · 예약 중 1인 회원은 한 번 더 예약되고(201) 그다음은 409, 잔여 0 회원은 409 (R1).
- [ ] T4 유효기간 · 지난 수업: 만료 회원은 409, 유효기간 당일 수업은 201, 지난 수업 예약은 409 (R2 · R3).
- [ ] T5 정원 · 중복: 정원 2 수업에 세 번째 예약은 409, 같은 회원이 같은 수업 두 번은 409 (R3).
- [ ] T6 차감 시점: 예약해도 `used` 그대로, 데스크의 출석은 `used` +1, 노쇼도 +1, 5시간 뒤 수업의 취소는 200 이고 `used` 그대로 · 예약 중만 준다 (R4 · R5).
- [ ] T7 취소 마감 · 상태: 1시간 뒤 수업의 취소는 409, 아직 안 시작한 수업의 출석 처리는 409, 이미 출석 처리한 예약의 취소는 409 (R5 · R6).
- [ ] T8 권한 · 거부 순서: 회원이 남의 예약을 만들면 403, 회원이 출석 처리하면 403, 본문 없음 + 없는 예약은 400, 없는 예약은 404, 회원이 남의 지난 예약을 취소하면 403(409 아님), 최근 30일 노쇼 3회 회원은 데스크가 대신 예약해도 409 (R7 · R8 · R9).
- [ ] T9 화면: 회원권 카드에 잔여 · 예약 가능 숫자가 보이고, 회원에게는 출석 · 노쇼 버튼이 없으며, 데스크로 바꾸면 지난 수업의 예약 줄에 출석 · 노쇼 버튼이 있다. 잔여 0 회원으로 예약하면 메시지 줄에 `예약 가능 횟수가 없습니다`.
