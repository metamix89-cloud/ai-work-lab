# PRD — 다온소프트 「사내 규정 검색」

> 「이 화면, PRD 로는 이렇게」 5편. 회사 · 규정 · 조항은 모두 교육용 가상 데이터(실제 어느 회사의 규정도 아니다).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 다온소프트 인사팀은 "연차 이월 돼요?", "해외 출장 숙박비 한도가 얼마예요?" 같은 질문을 메신저로 하루 열 번 받는다. 규정 문서는 공유 폴더에 PDF 로 있고, 개정 전 파일과 섞여 있어 옛 조항을 보고 답하는 일이 생긴다.
- **목적:** 직원이 **검색어로 현재 유효한 조항**을 찾고, 결과마다 **어느 규정 몇 조, 언제부터** 인지 근거가 붙으며, **개정 전 조항은 기본 결과에 나오지 않고**, **없는 규정은 '없음'** 으로 끝난다.
- **성공 기준:** 인사팀 메신저 질문 절반 감소. "그거 옛날 규정이에요" 가 사라진다.

## 2. 사용자

- **직원 1유형.** 로그인 없이 사내망에서 연다. 검색하고 읽기만 한다. 규정을 넣고 고치는 건 인사팀의 다른 도구(이 편 범위 밖).

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 검색: 검색어(공백으로 나눈 단어 **모두** 포함)로 현재 유효한 조항 찾기 | Must | 1 |
| F2 | 결과 카드: 규정 이름 · 조 번호 · 제목 · 시행일 · 본문 발췌 — 근거가 먼저 보인다 | Must | 1 |
| F3 | 원문 보기: 카드를 열면 조항 전문 | Must | 1 |
| F4 | 개정 이력: 조항에 개정 전 버전이 있으면 '개정 이력' 을 펼쳐 보기(기본은 접힘, '개정 전' 표시) | Must | 1 |
| F5 | 없음: 매칭이 없으면 결과 0 과 `해당 규정 없음` — 비슷한 조항을 대신 보여 주지 않는다 | Must | 1 |
| F6 | API: `GET /api/docs` · `GET /api/search?q=` · `GET /api/clauses/{id}` · `GET /api/clauses/{id}/history` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위에서 아래로:

- **위:** 제목 `다온소프트 사내 규정 검색`, 검색창(`data-testid="q"`) · 검색 버튼(`data-testid="search-btn"`). 아래 작은 글씨로 규정 목록(`/api/docs`)과 기준일.
- **결과:** 건수(`data-testid="count"`). 카드마다 `data-testid="result"`, 속성 `data-clause`(clause_id) · `data-doc` · `data-article`. 카드 머리에 **`규정 이름 · 제N조 · 시행 YYYY-MM-DD`** 가 제목보다 먼저, 그다음 제목과 발췌. 카드를 누르면 전문(`data-testid="full-text"`).
- **개정 이력:** 전 버전이 있는 카드에만 `개정 이력` 버튼(`data-testid="history-btn"`). 누르면 아래에 `data-testid="history-item"` 행 — `개정 전 · 시행 YYYY-MM-DD ~ YYYY-MM-DD` 와 본문. 기본은 접힘.
- **없음 상태:** `data-testid="no-result"` 에 `해당 규정 없음 — 인사팀(hr@daon.example)에 문의`. 결과 카드는 0개.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 시각 요소 이름은 완료 기준 테스트가 집는 손잡이다. 바꾸지 않는다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/clauses.csv`. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`policy.db`)를 **새로** 만든다.
  - `seed/clauses.csv` — `clause_id, doc, article, title, body, effective_from(YYYY-MM-DD), effective_to(YYYY-MM-DD 또는 빈칸)`
  - 같은 `doc` + `article` 에 행이 둘 이상이면 개정이다. `effective_to` 가 빈 행이 **현재 조항**, 채워진 행이 **개정 전** 조항.
- **테이블:** 접두어 `pl_` — `pl_clauses`. 칸은 CSV 와 같다.
- **가상 데이터:** 규정 3개(연차 · 출장 · 재택) 조항 12행(그중 개정 쌍 2개). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/docs` → `[{"doc":"연차 규정","count":5}, ...]` (현재 조항 수)
  - `GET /api/search?q=연차 이월` → `{"query":"연차 이월","count":1,"results":[{"clause_id":"L-07","doc":"연차 규정","article":"제7조","title":"연차 이월","effective_from":"2026-01-01","snippet":"…","has_history":true}]}`. 빈 검색어는 400 `검색어를 입력하세요`.
  - `GET /api/clauses/L-07` → 전문 `{"clause_id","doc","article","title","body","effective_from","effective_to","has_history"}`. 없으면 404.
  - `GET /api/clauses/L-07/history` → 개정 전 버전 목록(최신 먼저) `[{"clause_id":"L-07v1","effective_from":"2024-01-01","effective_to":"2025-12-31","body":"…"}]`. 없으면 `[]`.
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **현재 조항만 검색된다.** `effective_to` 가 비어 있는 행만 `search` 결과에 나온다. 개정 전 조항은 `history` 로만 본다. |
| R2 | **근거 없는 결과는 없다.** 결과마다 `doc` · `article` · `effective_from` 이 있고, 화면 카드 머리에 제목보다 먼저 보인다. |
| R3 | **단어 모두 포함(AND).** 검색어를 공백으로 나눠 **모든** 단어가 `title` 또는 `body` 에 들어 있는 조항만. 대소문자 · 앞뒤 공백 무시. |
| R4 | **없으면 없음.** 매칭 0 이면 `count: 0`, `results: []`. 가장 비슷한 조항을 대신 넣지 않는다. |
| R5 | **정렬.** 매칭 단어가 제목에 있는 조항 먼저, 같으면 `effective_from` 최신 먼저, 같으면 `clause_id` 순. |
| R6 | **발췌(snippet)** 는 첫 매칭 단어 앞뒤 40자, 매칭 단어는 `<mark>` 로 감싼다(HTML 은 그 태그만). |
| R7 | **거부가 둘 이상 해당하면** 400(입력 오류) → 404(없는 조항) 순서로 먼저 걸리는 것 하나만 알린다. |

(실측 뒤 메모: 화면 4 에 '기준일' 을 보이라고 해 놓고 출처(API)를 적지 않았다. 여섯 번 중 셋이 각자 API 를 만들었다 — B1 `/api/asof` · C1 `/api/today` · C3 `/api/meta`(C3 은 보고에 '없음'). 공개본에는 빈틈을 그대로 둔다 — 5편 영상의 재료.)

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 검색은 SQL `LIKE` 또는 파이썬 문자열 처리 — 외부 검색 엔진 · 임베딩 · LLM 금지(이 편은 '규칙대로 찾기' 가 주제).
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 권한, 규정 등록 · 수정 · 삭제 화면(인사팀 도구는 따로), 자연어 질문 답변(LLM) · 유사어 · 오타 교정, 동의어 사전, PDF 업로드 · 원문 파일 보기, 검색 로그 · 인기 검색어, 즐겨찾기, 알림, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 4개와 규칙 R1~R7, `/` 화면(검색 · 결과 카드 · 전문 · 개정 이력 · 없음 · 오류).
2. 그 외 없음.
