- **A 셋 다 '개정 전 조항' 이라는 개념이 없다.** 코드에 `시행 · 개정 · effective · history` 가 한 번도 안 나온다. 조항마다 한 버전뿐 — "연차는 이월하지 않는다" 와 "5일까지 이월할 수 있다" 가 같은 회사에 동시에 있을 수 있다는 걸 생각할 기회가 없었다. 규정 검색에서 가장 위험한 실수(옛 조항으로 답하기)를 막는 장치가 0.
- **A 가 스스로 정한 것:** 빈 검색어면 전체(20~21건) 반환 · 카테고리 필터(연차 · 출장 · 재택) 셋 다 · A2 · A3 '키워드' 칸을 만들어 검색에 포함 · A3 추천 검색어. 셋 다 AND 검색과 제목 우선 정렬은 스스로 했다(PRD 와 같음 — 이번엔 운이 좋았다). '없음' 화면은 셋 다 "검색 결과가 없습니다. 다른 검색어를 입력해 보세요" — 비슷한 조항을 대신 보여 주지는 않았다.
- 셋 다 "규정을 추가 · 수정하는 화면은 없습니다 — seed.py 를 고친 뒤 DB 를 지우세요" 라고 한계를 적었다. A3 는 "관리자용 등록 · 수정 화면이나 인증이 필요하면 말씀해 주세요" — 다음 일을 스스로 제안.
- **이번 PRD 의 빈틈은 '기준일'.** 화면 4 에 "규정 목록과 기준일" 을 보이라고 해 놓고 기준일의 출처(API)를 안 적었다. 여섯 번 중 셋이 각자 API 를 만들었다: B1 `/api/asof` · C1 `/api/today` · C3 `/api/meta`. B2 · B3 · C2 는 브라우저에서 오늘 날짜를 계산. 2편의 `/api/users` 와 같은 꼴 — **화면에 보이는 모든 값에 출처를 적어라.**
- **C3 는 `/api/meta` 를 추가하고도 보고에 "PRD 와 다르게 한 것: 없음".** C1 은 `/api/today` 를 같은 칸에 적었다. CLAUDE.md 의 보고 형식이 처음으로 빠뜨린 사례 — 보고 칸이 있어도 **사람(또는 코드)이 라우트 목록을 대조해야** 한다. 우리 채점기의 `extra_routes` 가 그걸 잡았다.
- B 셋 중 둘(B1 · B3)은 자기 테스트를 새로 씀. B1 "PRD 가 말하는 화면 포함 9개 테스트와는 다릅니다", B3 "httpx · pytest 는 PRD 가 허용한 패키지 밖". B1 은 history 에 없는 id 를 404 로(PRD 는 정하지 않음, R7 순서와 일관).
- 시간: 회당 70~101초. 비용은 API 정가 기준(구독 포함). 다섯 편 중 가장 빠르고 싼 편.

## 숫자의 뜻

- 검색 화면의 PRD 는 **"무엇이 결과에 나오면 안 되나"** 의 목록이다 — 개정 전 조항, 비슷하지만 다른 조항, 근거 없는 결과. 한 줄 요청은 '찾기' 는 잘 만들지만 '빼기' 는 안 만든다.
- CLAUDE.md 의 보고 칸은 검토를 **줄여 줄** 뿐 없애지 않는다. 6번 중 1번은 보고가 빠졌다.
