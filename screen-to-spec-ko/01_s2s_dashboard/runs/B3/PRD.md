# PRD — 가나다식품 「오늘의 현황판」

> 「이 화면, PRD 로는 이렇게」 1편. 회사 · 거래처 · 숫자는 모두 교육용 가상 데이터.
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 가나다식품 영업지원팀은 아침마다 주문 시스템 · 재고표 · 문의 메일함 세 곳을 열어 오늘 숫자를 확인한다. 10분이 걸리고, 사람마다 세는 법이 다르다.
- **목적:** 한 화면에서 **오늘 주문 수 · 재고 경고 품목 수 · 미처리 문의 수** 세 숫자와 **최근 7일 주문 추이 막대 1개**를 본다. 숫자의 뜻이 사람마다 달라지지 않게 계산식을 이 문서에 고정한다.
- **성공 기준:** 아침 확인 10분 → 10초. 세 숫자의 계산식에 대해 팀 안에 이견이 없다.

## 2. 사용자

- **영업지원팀 담당자 1유형.** 로그인 없이 사내망에서 주소를 열어 본다. 숫자를 보고 다른 시스템으로 이동할 뿐, 이 화면에서 무언가를 바꾸지 않는다.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 세 지표 카드: 오늘 주문 수 · 재고 경고 품목 수 · 미처리 문의 수 | Must | 1 |
| F2 | 최근 7일 주문 수 막대그래프(오늘 포함 7칸) | Must | 1 |
| F3 | 집계 시각 표시(`갱신 YYYY-MM-DD HH:MM`) | Must | 1 |
| F4 | 데이터 없음 상태(숫자 자리 `—`, 안내 문구 `데이터 없음`) | Must | 1 |
| F5 | 집계 API `GET /api/summary` (화면이 이 API 를 읽는다) | Must | 1 |
| F6 | 페이지를 다시 열면 다시 집계(캐시 없음) | Should | 1 |

## 4. 화면

한 페이지(`/`). 위에서 아래로:

- **위:** 제목 `가나다식품 오늘의 현황판`, 오른쪽에 집계 시각 `갱신 2026-10-23 09:00` (`data-testid="updated-at"`).
- **가운데:** 지표 카드 3개를 가로로. 카드마다 라벨과 큰 숫자.
  - `오늘 주문` → 숫자 요소 `data-testid="today-orders"`
  - `재고 경고` → `data-testid="stock-alerts"`
  - `미처리 문의` → `data-testid="open-inquiries"`
- **아래:** 막대그래프 1개. 막대 7개(6일 전 → 오늘), 막대마다 `data-testid="daily-bar"`, 아래에 날짜(MM-DD), 주문 0건인 날도 막대 자리(높이 0)와 날짜를 그린다.
- **데이터 없음 상태:** 세 숫자 자리에 `—`, 막대 영역에 `데이터 없음` (`data-testid="empty-notice"`). 0 으로 보이면 안 된다.
- **오류 상태:** API 가 실패하면 카드 자리에 `불러오지 못했습니다` 와 다시 시도 버튼.
- 시각 요소 이름(`data-testid`)은 완료 기준 테스트가 집는 손잡이다. 이름을 바꾸지 않는다.

## 5. 데이터

- **원본:** 프로젝트 루트의 `seed/` 폴더 CSV 3개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`dash.db`)를 **새로** 만든다(기존 DB 삭제 후 재생성).
  - `seed/orders.csv` — `order_id, ordered_at(YYYY-MM-DD HH:MM), customer, amount, status(접수|출고|취소)`
  - `seed/stock.csv` — `sku, name, qty, safety_qty`
  - `seed/inquiries.csv` — `inquiry_id, received_at(YYYY-MM-DD HH:MM), channel, status(접수|처리중|완료)`
- **테이블:** 접두어 `dash_` — `dash_orders` · `dash_stock` · `dash_inquiries`. 칸은 CSV 와 같다.
- **가상 데이터:** `seed/` 에 주문 14건 · 재고 6품목 · 문의 6건을 넣어 둔다. 숫자 검증을 위해 **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다(파일 이름 · 칸 이름 고정).
- **API 응답** `GET /api/summary`:
  ```json
  {"today_orders": 4, "stock_alerts": 2, "open_inquiries": 3,
   "daily_orders": [{"date": "2026-10-17", "count": 0}, ... 7개 ...],
   "updated_at": "2026-10-23 09:00", "empty": false}
  ```

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **오늘 주문 수** = `ordered_at` 의 날짜가 서버 로컬 '오늘'인 주문 수. **`status = 취소` 는 세지 않는다.** 어제 23:59 는 오늘이 아니다. |
| R2 | **재고 경고 품목 수** = `qty < safety_qty` 인 품목 수. **같으면 경고가 아니다.** |
| R3 | **미처리 문의 수** = `status` 가 `접수` 또는 `처리중` 인 문의 수. `완료` 는 세지 않는다. |
| R4 | **막대** = 오늘 포함 최근 7일, 날짜별 주문 수(취소 제외). **주문이 없는 날도 0 으로 칸을 둔다.** 7일보다 오래된 주문은 넣지 않는다. |
| R5 | **데이터 없음** = 세 CSV 가 모두 비어 있거나 없을 때. 숫자는 `—`, 문구 `데이터 없음`. 0 과 구분한다. |
| R6 | **집계 시각** = 서버가 집계를 끝낸 시각(`YYYY-MM-DD HH:MM`). 화면 글자는 `갱신 ` 으로 시작한다. |
| R7 | 화면은 읽기만 한다. 주문 · 재고 · 문의를 바꾸는 기능은 없다. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 차트 라이브러리 없이 `div` 또는 `svg` 로 막대를 그린다.
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만.
- 한글 UI. 숫자는 천 단위 쉼표 없이 정수.

## 8. 범위 밖 (Won't)

- 로그인 · 권한, 기간 선택 · 필터, 상세 페이지 · 드릴다운, 알림 · 이메일, 자동 새로고침, 다크 모드, 매출 금액 지표, 데이터 입력 · 수정 화면.

## 9. 개발 단계

1. **Phase 1:** `seed/` CSV → SQLite 적재, `/api/summary`, `/` 화면(카드 3 · 막대 1 · 갱신 시각), 데이터 없음 · 오류 상태.
2. 그 외 없음. 이 편은 Phase 1 로 끝난다.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '현황판' 이 보인다.
- [ ] T2 `오늘 주문` · `재고 경고` · `미처리 문의` 라벨이 있다.
- [ ] T3 오늘 주문 수가 맞다 — 취소 제외, 어제 23:50 제외 (고정 데이터에서 4).
- [ ] T4 재고 경고가 맞다 — `qty < safety_qty` 만 (고정 데이터에서 2, 같은 품목 1건은 제외).
- [ ] T5 미처리 문의가 맞다 — 접수 + 처리중 (고정 데이터에서 3).
- [ ] T6 막대가 7개다 — 주문 0건인 날 포함.
- [ ] T7 `갱신 YYYY-MM-DD HH:MM` 이 보인다.
- [ ] T8 CSV 가 비면 숫자 자리에 `—`, `데이터 없음` 문구가 보인다 (0 아님).
- [ ] T9 `/api/summary` 가 5 데이터의 응답 형식과 값을 지킨다.
