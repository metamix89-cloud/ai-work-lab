- 채점기가 이미 죽은 서버 프로세스의 출력을 읽지 않아(`stop()` 이 살아 있을 때만 읽음) B3 의 실패 이유가 비어 있었다. → `tools/debug_fixture.py`(앱을 임시 폴더로 복사 + 그 편 테스트의 고정 데이터 + uvicorn 출력)로 원인 확인. 다음 편 테스트 틀은 종료된 프로세스의 출력도 읽는다.
- B3 은 직접 띄우면 정상(`probe_app.py` 200) — 자기 seed 로는 문제가 안 보인다. 실패는 **바꿔 끼운 데이터**에서만 났다. '데이터를 바꿔 끼울 수 있어야 한다' 는 PRD 5 의 문장을 테스트가 실제로 검사한 첫 사례.

## 숫자의 뜻

- 데이터 계약은 칸 이름만으로는 반쪽이다. **형식(문자열 · 숫자 · 날짜 모양)과 예시 한 줄**까지 적어야 한다. 안 적으면 셋이 셋 다 다르게 만들고, 그중 하나는 남의 데이터를 받는 순간 죽는다.
- 상태 흐름 화면의 PRD 는 '단계를 옮기는 API 하나 + 단계마다 필요한 것' 으로 적는다. 한 줄 요청은 단계를 동작(배정 · 답변)에 묶어서, 흐름이 맞는지 따로 검사할 수 없었다.
