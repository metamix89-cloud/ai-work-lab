# PRD — 가나다식품 「세금계산서 발행」

> 「이 화면, PRD 로는 이렇게」 8편. 회사 · 거래처 · 사업자번호 · 금액은 모두 교육용 가상 데이터. 국세청 전송이 없는 **사내 발행 대장** 연습 화면이다(실제 전자세금계산서가 아니다).
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 가나다식품 회계팀은 거래처에 보내는 세금계산서를 엑셀로 쓴다. 품목 줄마다 세액을 반올림해 더하는 사람과 합계에 한 번 매기는 사람이 달라 1원씩 어긋난다. 틀린 계산서를 그 자리에서 고쳐 써서, 거래처가 받은 것과 대장의 것이 다르다.
- **목적:** 금액은 **서버가 한 가지 규칙으로** 계산하고, 필수 항목이 빠지면 발행되지 않으며, 발행된 계산서는 **고치지 않고 새 번호로 수정 발행**한다. 월 합계는 유효한 계산서만 센다.
- **성공 기준:** 1원 차이 문의 0건. 거래처 보관본과 대장이 어긋난 계산서 0건.

## 2. 사용자

- **회계팀 담당자 1유형.** 로그인 없이 사내망에서 연다(권한은 범위 밖).

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 작성: 거래처 선택 · 작성일 · 품목 줄(품목명 · 수량 · 단가) 여러 줄 · 미리보기 · 발행 | Must | 1 |
| F2 | 미리보기: 서버가 계산한 공급가 · 세액 · 합계(저장하지 않음) | Must | 1 |
| F3 | 발행 대장: 이번 달 계산서 목록 + 월 합계(공급가 · 세액 · 합계) | Must | 1 |
| F4 | 상세: 품목 줄 · 상태 · 수정 관계(무엇을 고친 것인지 / 무엇으로 고쳐졌는지) | Must | 1 |
| F5 | 수정 발행: 원본은 '수정됨', 새 번호의 계산서가 생긴다 | Must | 1 |
| F6 | 취소: 상태만 '취소', 지우지 않는다 | Must | 1 |
| F7 | API: `GET /api/customers` · `POST /api/invoices/preview` · `POST /api/invoices` · `GET /api/invoices` · `GET /api/invoices/{no}` · `POST /api/invoices/{no}/amend` · `POST /api/invoices/{no}/cancel` | Must | 1 |

## 4. 화면

한 페이지(`/`). 왼쪽 작성, 오른쪽 대장.

- **작성:** 거래처 선택(`data-testid="customer"`, 옵션 값은 사업자번호), 작성일(`data-testid="issued"`), 품목 줄마다 `data-testid="line"` 안에 품목명(`data-testid="item"`) · 수량(`data-testid="qty"`) · 단가(`data-testid="price"`), 줄 추가(`data-testid="add-line"`), 미리보기 숫자 `data-testid="pv-supply"` · `pv-tax` · `pv-total`(서버 `preview` 값), 발행 버튼(`data-testid="issue-btn"`).
- **대장:** 이번 달 목록 행 `data-testid="invoice-row"`, 속성 `data-no`(발행 번호) · `data-status`(`발행` | `수정됨` | `취소`). 월 합계 `data-testid="month-supply"` · `month-tax` · `month-total` — 숫자는 천 단위 쉼표 허용.
- **상세(행을 누르면):** 품목 줄 · 금액 · 상태 · `이 계산서를 고친 것: INV-…` 또는 `고쳐진 계산서: INV-…`. 발행 상태일 때만 수정 발행(`data-testid="amend-btn"`) · 취소(`data-testid="cancel-btn"`).
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 3개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`invoice.db`)를 **새로** 만든다.

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/customers.csv` | `biz_no, name, ceo` | `biz_no` 문자열 `101-81-11111`(숫자 3-2-5, 하이픈 포함) |
| `seed/invoices.csv` | `invoice_no, issued, biz_no, supply, tax, total, status, amends, amended_by` | `invoice_no` 문자열 `INV-20261024-001` · `issued` `YYYY-MM-DD` · 금액은 원 단위 정수 · `status` `발행`/`수정됨`/`취소` · `amends`/`amended_by` 는 발행 번호 또는 빈칸 |
| `seed/invoice_lines.csv` | `invoice_no, line, item, qty, unit_price` | `line` 1부터 정수 · `qty` 1 이상 정수 · `unit_price` 0 이상 정수(원) |

- **테이블:** 접두어 `tx_` — `tx_customers` · `tx_invoices` · `tx_lines`. 칸은 CSV 와 같다.
- **가상 데이터:** 거래처 3곳, 오늘 날짜 계산서 3건(발행 2 · 취소 1). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API** — 모든 금액은 원 단위 정수.
  - `GET /api/customers` → `[{"biz_no":"101-81-11111","name":"행복마트","ceo":"김행복"}, ...]`
  - `POST /api/invoices/preview` 본문 `{"biz_no","issued","lines":[{"item","qty","unit_price"}]}` → `{"supply","tax","total","lines":[{"item","qty","unit_price","line_supply"}]}` (저장하지 않음)
  - `POST /api/invoices` 같은 본문 → 201 과 계산서 `{"invoice_no","issued","biz_no","customer","supply","tax","total","status","amends","amended_by","lines":[...]}`
  - `GET /api/invoices?month=YYYY-MM`(기본 이번 달) → `{"month","count","totals":{"supply","tax","total"},"items":[계산서(lines 없이)]}` — 발행 번호 순.
  - `GET /api/invoices/{no}` → 계산서(lines 포함). 없으면 404.
  - `POST /api/invoices/{no}/amend` 본문 `{"issued","lines"}` → 201 과 새 계산서(거래처는 원본과 같음, `amends` = 원본 번호).
  - `POST /api/invoices/{no}/cancel` → 200 과 계산서.
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **금액은 서버가 센다.** 줄 공급가 = 수량 × 단가. 공급가 = 줄 공급가의 합. **세액 = 공급가 합계 × 10%, 원 미만 버림 — 줄마다 세액을 따로 매겨 더하지 않는다.** 합계 = 공급가 + 세액. 요청에 금액이 들어 있어도 무시하고 다시 센다. |
| R2 | **필수 항목.** 등록된 거래처의 `biz_no`, `issued`(YYYY-MM-DD), 품목 1줄 이상, 줄마다 품목명 · 수량(1 이상 정수) · 단가(0 이상 정수). 하나라도 어기면 400 `필수 항목을 확인하세요`(어느 칸인지 덧붙여도 된다). |
| R3 | **발행 번호** = `INV-` + 작성일(YYYYMMDD) + `-` + 그날 세 자리 일련번호(001부터). 이미 있는 번호(seed 포함) 다음 번호를 쓴다. 번호는 다시 쓰지 않는다(취소 · 수정된 번호도 건너뛴다). |
| R4 | **발행된 계산서는 고치지 않는다.** 수정은 `amend` 로만 — 새 번호의 계산서를 만들고, 원본은 `수정됨` + `amended_by` = 새 번호, 새 것은 `amends` = 원본 번호. 원본의 품목 줄 · 금액은 그대로 남는다. |
| R5 | **발행 상태만 고치거나 취소한다.** `수정됨` · `취소` 인 계산서에 `amend` · `cancel` 은 409 `발행 상태가 아닙니다`. |
| R6 | **월 합계는 `발행` 상태만.** `수정됨` · `취소` 는 목록에는 보이지만 합계에서 뺀다. |
| R7 | **거부가 둘 이상 해당하면** 400(입력 오류) → 404(없는 계산서) → 409(상태 위반) 순서로 먼저 걸리는 것 하나만. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.** 금액 계산에 부동소수점을 쓰지 않는다(정수 연산: 세액 = 공급가 × 10 // 100).
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 권한, 국세청 전송 · 전자서명, **거래처 · 품목 마스터 편집 화면(데이터 편집 화면)**, 영세율 · 면세 · 다른 세율, PDF · 인쇄 · 메일 발송, 품목 마스터 자동완성, 계산서 삭제, 엑셀, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 7개와 규칙 R1~R7, `/` 화면(작성 · 미리보기 · 대장 · 월 합계 · 상세 · 수정 발행 · 취소 · 메시지 · 오류).
2. 그 외 없음.

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '세금계산서' 가 보인다.
- [ ] T2 줄 공급가 1,005원짜리 품목 3줄 → 세액 301원(합계 3,015 에 10%, 원 미만 버림) · 합계 3,316. 줄마다 세액을 매기면 300 이나 303, 합계를 반올림하면 302 가 된다 (R1).
- [ ] T3 요청에 엉터리 금액(supply · tax · total)을 넣어도 서버가 다시 센다. 미리보기와 발행 금액이 같다 (R1).
- [ ] T4 발행 번호가 seed 다음부터 이어진다 — 오늘 004 · 005 · 006 (R3).
- [ ] T5 모르는 거래처 · 품목 없음 · 수량 0 · 수량 1.5 · 음수 단가는 400, 계산서가 생기지 않는다 (R2).
- [ ] T6 수정 발행 — 새 번호, 원본 `수정됨` + `amended_by`, 원본 품목 줄은 그대로, 같은 원본을 또 고치면 409. 없는 번호는 잘못된 본문이면 400 · 올바른 본문이면 404 (R4 · R5 · R7).
- [ ] T7 취소 — 상태 `취소`, 취소된 것을 고치거나 다시 취소하면 409 (R5).
- [ ] T8 월 합계가 `발행` 상태만 더한다 (R6).
- [ ] T9 화면: 대장 행 7개, 수정된 원본 행 `data-status="수정됨"`, `month-total` 이 API 합계와 같다.
