# PRD — 가나다식품 「경영 현황 대시보드」

> 「이 화면, PRD 로는 이렇게」 13편(1부 마지막). 1편 「오늘의 현황판」 의 지표 정의를 **기간 · 여러 표 · 역할**로 넓힌다.
> 회사 · 거래처 · 숫자는 모두 교육용 가상 데이터. 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 1편 현황판은 '오늘' 숫자 셋이었다. 대표는 "지난주 매출은?", 영업팀은 "거래처별로는?", 물류팀은 "재고 경고만" 을 묻는다. 엑셀로 뽑을 때마다 매출을 주문일 기준으로 셌다 출고일 기준으로 셌다 하고, 기간 끝날의 주문이 빠지기도 했다.
- **목적:** 한 화면에서 **기간을 골라** 지표 다섯 개 · 일별 주문 막대 · 거래처별 매출 상위 5를 본다. **역할마다 볼 수 있는 지표가 다르고**, 안 보이는 지표는 **응답에도 나가지 않는다**. 계산식은 이 문서에 고정한다(1편과 같은 지표는 1편과 같은 식).
- **성공 기준:** 같은 기간 · 같은 지표에 대해 팀마다 숫자가 다른 일 0건.

## 2. 사용자

- **대표 · 영업팀 · 물류팀 3유형.** 로그인 없이 화면 위 **사용자 선택 상자**에서 고른다. API 는 요청자를 쿼리의 `viewer`(user_id)로 받는다. **로그인은 8 범위 밖.**
- 화면은 읽기만 한다. 아무것도 바꾸지 않는다.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 기간 선택(시작일 · 종료일) — 처음엔 최근 7일(오늘 포함) | Must | 1 |
| F2 | 지표 카드 5개: 주문 수 · 매출 · 취소율 · 재고 경고 · 미처리 문의 — 역할이 볼 수 있는 것만 | Must | 1 |
| F3 | 일별 주문 막대(기간의 날마다 한 칸, 0 인 날 포함) · 거래처별 매출 상위 5 표(대표만) | Must | 1 |
| F4 | API: `GET /api/users` · `GET /api/dashboard?viewer=&from=&to=` | Must | 1 |

## 4. 화면

한 페이지(`/`). 위 사용자 선택과 기간, 가운데 카드, 아래 막대와 표.

- **사용자 선택:** `data-testid="user"` (`<select>`, option 의 value 는 user_id). 처음엔 첫 번째 사용자.
- **기간:** 시작일 `data-testid="from"` · 종료일 `data-testid="to"`(`<input type="date">`), 적용 `data-testid="apply"`.
- **카드:** `data-testid="m-orders"` · `m-revenue` · `m-cancel-rate` · `m-stock-alerts` · `m-open-inquiries` — 안에 숫자. **역할이 못 보는 카드는 그리지 않는다**(빈 카드 · 자물쇠 표시도 없이). 값이 없으면(취소율 분모 0) `—`.
- **막대:** 날마다 `data-testid="daily-bar"`. **거래처 표:** 줄마다 `data-testid="top-customer"`(대표만).
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 4개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`biz.db`)를 **새로** 만든다.

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/users.csv` | `user_id, name, role` | `role` `exec`(대표) · `sales`(영업팀) · `logistics`(물류팀) |
| `seed/orders.csv` | `order_id, ordered_at, customer, amount, status` | `ordered_at` `2026-10-23 23:50` · `amount` 원 단위 정수 · `status` `접수` · `출고` · `취소` |
| `seed/stock.csv` | `sku, name, qty, safety_qty` | 정수 |
| `seed/inquiries.csv` | `inquiry_id, received_at, channel, status` | `status` `접수` · `처리중` · `완료` |

- **테이블:** 접두어 `biz_` — `biz_users` · `biz_orders` · `biz_stock` · `biz_inquiries`.
- **가상 데이터:** 사용자 3명(역할마다 1), 최근 열흘 남짓의 주문 12건 이상(세 상태 다 있게), 재고 6품목, 문의 6건. **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다.
- **API**
  - `GET /api/users` → `[{"user_id","name","role"}]`
  - `GET /api/dashboard?viewer=u1&from=2026-10-18&to=2026-10-24` →
    ```json
    {"period": {"from": "2026-10-18", "to": "2026-10-24"},
     "metrics": {"orders": 8, "revenue": 600000, "cancel_rate": 27.3, "stock_alerts": 2, "open_inquiries": 3},
     "daily": [{"date": "2026-10-18", "count": 1}, ...기간의 날 수만큼...],
     "top_customers": [{"customer": "마루푸드", "revenue": 200000}, ...최대 5...],
     "updated_at": "2026-10-24 09:00"}
    ```
    역할이 못 보는 지표는 `metrics` 에 **키가 없다**(null 도 아니다). `top_customers` 도 대표가 아니면 키가 없다.
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **기간.** `from` · `to` 는 `YYYY-MM-DD`, **둘 다 포함**(종료일 23:59 주문도 들어간다). 둘 다 없으면 최근 7일(오늘 포함). 하나만 있거나, 형식이 틀리거나, `from > to` 이거나, 31일을 넘으면 400 `기간을 확인하세요`. |
| R2 | **주문 수** = 기간 안 주문 중 `취소` 가 아닌 것(1편 R1 과 같은 식). |
| R3 | **매출** = 기간 안 주문 중 **`출고` 인 것만**의 `amount` 합. 접수는 아직 매출이 아니다. |
| R4 | **취소율** = 기간 안 `취소` 건수 ÷ 기간 안 전체 주문 건수(취소 포함) × 100, **소수 첫째 자리 반올림**(27.27 → 27.3). 전체가 0 이면 `null`(화면 `—`) — 0 과 다르다. |
| R5 | **재고 경고** = `qty < safety_qty` 인 품목 수(1편 R2 — 같으면 경고 아님). 기간과 상관없는 '지금' 값. |
| R6 | **미처리 문의** = **기간 안에 들어온** 문의 중 `접수` · `처리중` 인 것. |
| R7 | **일별 막대** = 기간의 날마다 한 칸(주문 0 인 날도), 주문 수 식은 R2. **거래처 상위 5** = 매출 식(R3)으로 거래처별 합, 큰 순, 같으면 거래처 이름 순, 최대 5. |
| R8 | **역할별로 보이는 것.** 대표: 전부. 영업팀: 주문 수 · 매출 · 취소율 · 미처리 문의 · 막대. 물류팀: 주문 수 · 재고 경고 · 막대. 못 보는 것은 **응답에 키가 없다**. |
| R9 | **입력과 거부 순서.** `viewer` 가 없으면 400 `사용자를 확인하세요`. 거부가 둘 이상이면 본문 · 쿼리만 보면 아는 것(400) → 없는 사용자(404) 순서로 하나만. |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 · 차트 라이브러리 없음) + SQLite.** 금액은 정수 원.
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- '오늘' 은 서버 로컬 날짜. 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원, 데이터 입력 · 수정, 엑셀 · PDF 내려받기, 드릴다운 · 상세 페이지, 목표 대비 · 전년 대비, 원가 · 이익 지표, 알림, 자동 새로고침, **사용자 · 권한 편집 화면**, 다크 모드.

## 9. 개발 단계

1. **Phase 1:** `seed/` → SQLite, API 2개와 규칙 R1~R9, `/` 화면(사용자 · 기간 · 카드 · 막대 · 표 · 메시지 · 오류).
2. 그 외 없음.

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 가 완료 기준이다. 아래 9개가 모두 통과해야 끝난다.

- [ ] T1 `/` 가 200 으로 열리고 '현황' 이 보인다.
- [ ] T2 대표 · 기본 기간: 응답 형식, 지표 다섯 키, 막대 7칸(0 인 날 포함), 사용자 3명.
- [ ] T3 주문 수 · 매출 — 취소 제외, 매출은 출고만(접수 제외) (R2 · R3).
- [ ] T4 취소율 반올림(27.3) · 거래처 상위 5 순서 (R4 · R7).
- [ ] T5 기간 경계 — 종료일 23:50 은 들어가고, 시작일 전날 23:59 · 종료일 다음 날은 빠진다 (R1).
- [ ] T6 기간 오류(시작 > 종료 · 32일 · 형식 · 하나만)는 400, 없는 사용자는 404, `viewer` 없음 + 형식 오류는 400 (R1 · R9).
- [ ] T7 역할: 물류팀 응답에 매출 · 취소율 · 미처리 문의 · 거래처 키가 없고 매출 숫자도 응답 어디에도 없다, 영업팀에 재고 경고 · 거래처 키가 없다 (R8).
- [ ] T8 주문이 없는 기간: 주문 수 0 · 매출 0 · 취소율 null, 막대는 날 수만큼 0. 미처리 문의는 기간 안에 들어온 것만 (R4 · R6 · R7).
- [ ] T9 화면: 대표에게 매출 카드(600,000)가 보이고, 물류팀으로 바꾸면 매출 카드가 없다. 주문 없는 기간을 적용하면 취소율이 `—`, 시작 > 종료를 적용하면 메시지 줄에 `기간을 확인하세요`.
