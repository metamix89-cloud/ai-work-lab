## 탐침 — 결과물끼리 같은 요청 (`probe_cases.py` + `probe_qc.json`)

| 보낸 것 | B1 · B2 · B3 · C1 · C2 · C3 · 정답 앱 |
|---|---|
| 신고자 = 담당자인 건을 본인이 검증 | 403 '본인 조치는…' — **일곱 다 같은 문구**(R7 에 담당자 검사가 먼저 적혀 있음) |
| 원인 분석에서 자기를 담당자로 → 그 사람이 조치 등록 | 200 · 200 — 일곱 다 허용(PRD 가 '분석자 = 담당자' 를 막지 않음) |
| 작업자 신고자가 검증 | 403 '품질팀만' — 일곱 다 |
| 같은 로트 다른 증상 · 로트 수량과 같은 수량 | 201 — 일곱 다 |

- **B · C 여섯이 탐침 전부에서 정답 앱과 같은 답.** 13편(1부) 에 이어 두 편 연속 — R9 거부 순서를 '무엇을 찾아야 아나' 로 적고, R7 에 403 문구를 세 가지로 나눠 적은 효과.
- 남은 틈: **분석한 사람이 자기를 담당자로 정하는 것**은 막지 않았다(일곱 다 허용). 실무에선 원인 분석자 = 조치 담당자가 흔해 규칙으로 둘지 회사가 정할 일. PRD 에 '같은 사람이어도 된다' 고 적어 두는 편이 낫다.

## C 의 '직접 정한 것' (네 번째 편)

- C2: **"담당자가 아직 없는 신고 상태 건에 조치 등록은 403 이 아니라 409"** — 담당자가 비어 '담당자만' 검사를 할 수 없어서. 정답 앱은 403 — PRD R9 의 순서(403 → 409)를 글자 그대로 따르면 403, 뜻으로 읽으면 409. 테스트는 그 자리를 묻지 않았다(T5 는 검증 대기 건으로 409 를 묻는다).
- C1: 담당자와 신고자가 같은 사람이면 '본인 조치…' 를 먼저. 새 id 는 겹치면 번호를 올림. C3: 성공 메시지 '신고했습니다' 를 화면에 추가(PRD 에 없음 — 보고함).
- **C1 · C3 둘 다 "테스트가 끝난 뒤 seed/ 가 비어 있었다"** — C3 "제 셸이 seed/ 안에 있어서 복구가 막힌 것으로 보입니다". 9편 C2 · C3 과 같은 윈도우 폴더 잠금(빌더가 cwd 를 seed 로 옮겨 놓고 테스트를 돌림). 채점 때는 재현되지 않음(`restore_seed` 재시도 10회). 빌더가 스스로 복구했다.

## 숫자의 뜻

- **검증의 '제3자' 는 두 사람을 다 빼야 한다** — 담당자(A 1/3 이 막음)와 신고자(A 0/3). 한 줄 요청은 "검증" 을 '품질팀이 확인' 으로만 읽는다.
- **기한은 단위까지** — 시간인지 날짜인지, 당일은 넘김인지. 안 적으면 시간 단위 SLA 를 스스로 만든다(3/3).
- 업종 편에서도 PRD 10칸 틀은 그대로 통했다 — 2부는 '어느 업종이든 같은 칸, 다른 규칙' 을 보여 주는 편.
