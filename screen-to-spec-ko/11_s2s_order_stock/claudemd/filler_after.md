## 프런트엔드
- 시맨틱 태그를 먼저 쓴다(`button` · `table` · `main` · `nav`).
- 버튼과 입력에는 접근성 이름(`aria-label` 또는 `label`)을 단다.
- 색만으로 상태를 구분하지 않는다. 글자도 함께 쓴다.
- 인라인 스타일을 줄이고 클래스로 묶는다.
- 색과 간격은 CSS 변수로 모은다.
- 전역 변수를 줄이고 함수로 묶는다.
- `var` 대신 `const` 와 `let` 을 쓴다.
- 비교는 `===` 로 한다.
- 비동기 호출은 `async` · `await` 로 쓰고 실패를 처리한다.
- 네트워크가 끝나기 전에는 버튼을 다시 누를 수 없게 한다.
- `innerHTML` 에 사용자 값을 그대로 넣지 않는다.
- 작은 화면에서도 가로로 넘치지 않게 한다.
## 데이터베이스
- 스키마는 한곳에 모은다.
- 외래 키에는 제약을 건다.
- 자주 찾는 칸에는 인덱스를 건다.
- 한 번의 요청에서 쿼리를 반복문으로 돌리지 않는다.
- 커넥션은 쓰고 나면 닫는다.
- 시간은 한 가지 형식으로 저장한다.
## 성능
- 재 보기 전에 최적화하지 않는다.
- 필요한 칸만 읽는다.
- 긴 목록을 한 번에 그리지 않는다.
- 같은 계산을 반복문 안에서 되풀이하지 않는다.
## 테스트
- 새 함수에는 단위 테스트를 추가한다.
- 테스트 이름은 무엇을 확인하는지 문장으로 짓는다.
- 테스트 하나는 한 가지만 확인한다.
- 준비 · 실행 · 확인 순서로 쓴다.
- 테스트끼리 순서에 기대지 않는다.
- 경계값과 실패하는 경우도 시험한다.
- 버그를 고칠 때는 먼저 그 버그를 재현하는 테스트를 쓴다.
- 시간 · 난수에 기대는 테스트는 고정한다.
- 시험용 데이터는 테스트 가까이에 둔다.
## 문서
- `README.md` 에 설치 · 실행 · 시험 명령을 적는다.
- 명령은 복사해서 바로 돌아가게 쓴다.
- 환경 변수가 있으면 이름과 기본값을 적는다.
- 동작이 바뀌면 문서도 같은 변경에서 고친다.
- 문서에 낡은 스크린샷을 남기지 않는다.
- 설계에서 고민한 결정은 이유를 짧게 남긴다.
## 의존성
- 새 패키지를 넣기 전에 표준 라이브러리로 되는지 본다.
- 버전을 고정한다.
- 쓰지 않게 된 패키지는 지운다.
- 라이선스를 확인한다.
## Git
- 커밋 메시지는 `feat:` · `fix:` · `docs:` · `refactor:` · `test:` 로 시작한다.
- 제목은 50자 안쪽, 명령문으로 쓴다.
- 본문에는 왜 바꿨는지 적는다.
- 커밋 하나에 변경 하나만 담는다.
- 커밋하기 전에 차이를 다시 읽는다.
- 빌드 산출물 · 로컬 설정 · 데이터베이스 파일을 커밋하지 않는다.
- 비밀값이 커밋되면 값을 바꾸고 이력에서 지운다.
- 공유 브랜치에 강제로 푸시하지 않는다.
- 브랜치 이름은 `feature/` · `fix/` 로 시작한다.
- 이력을 깔끔하게 하려고 남의 커밋을 고치지 않는다.
## 코드 리뷰
- 변경은 리뷰할 수 있는 크기로 나눈다.
- 스타일 지적은 사람이 아니라 코드에 대해 적는다.
- 고칠 것과 제안을 구분해서 적는다.
- 리뷰에서 나온 질문은 코드나 문서로 답한다.
## 유지 보수
- 지나가다 본 작은 오타는 고치되 변경을 섞지 않는다.
- 쓰지 않는 코드는 남겨 두지 않고 지운다.
- 경고를 무시하지 않는다.
- 설정값은 한곳에 모은다.
