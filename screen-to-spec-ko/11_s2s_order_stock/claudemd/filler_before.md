# 개발 규칙
이 문서는 이 저장소에서 일하는 모든 사람과 AI 가 따르는 공통 규칙이다.
## 일하는 태도
- 코드를 고치기 전에 관련 파일을 먼저 읽는다.
- 요구사항을 다시 한 번 읽고 시작한다.
- 한 번에 한 가지만 바꾼다.
- 고칠 이유가 없는 코드는 건드리지 않는다.
- 단순한 방법이 있으면 단순한 방법을 고른다.
- 미리 일반화하지 않는다. 같은 코드가 세 번 나올 때 묶는다.
- 가정을 했으면 코드 주석에 적어 둔다.
- 오류 메시지는 끝까지 읽고 원인을 찾은 뒤에 고친다.
- 증상을 가리는 수정을 하지 않는다.
- 임시 파일은 끝나기 전에 지운다.
## 파이썬 스타일
- PEP 8 을 따른다.
- 들여쓰기는 스페이스 4칸이다.
- 한 줄은 100자를 넘기지 않는다.
- import 는 표준 라이브러리 · 외부 · 내부 순서로 묶는다.
- 쓰지 않는 import 와 변수는 지운다.
- 와일드카드 import 를 쓰지 않는다.
- 문자열은 f-string 으로 만든다. SQL 은 예외다.
- 경로는 pathlib 으로 다룬다.
- 파일은 with 로 열고 인코딩을 적는다.
- 전역 가변 상태를 줄인다.
- 매직 넘버는 이름 있는 상수로 뺀다.
- 모든 함수에 매개변수와 반환값의 타입 힌트를 단다.
- 모듈 맨 위에 그 파일이 하는 일을 docstring 으로 적는다.
- 공개 함수에는 docstring 을 단다.
- 함수 하나는 40줄을 넘기지 않는다.
- 파이썬 파일 하나는 500줄을 넘기지 않는다.
- 중첩은 3단계를 넘기지 않는다. 일찍 돌려준다.
- 불리언 매개변수 대신 키워드 인자나 나눈 함수를 쓴다.
## 이름
- 변수와 함수는 snake_case, 클래스는 PascalCase, 상수는 UPPER_CASE 로 쓴다.
- 이름만 보고 하는 일을 알 수 있게 짓는다.
- 한 글자 이름은 짧은 반복문에서만 쓴다.
- 줄임말은 널리 쓰는 것만 쓴다.
- 불리언은 is · has · can 으로 시작한다.
- 함수 이름은 동사로 시작한다.
- 같은 개념에는 같은 낱말을 쓴다.
## 주석
- 주석은 무엇이 아니라 왜를 적는다.
- 코드와 맞지 않게 된 주석은 그 자리에서 고친다.
- 주석 처리한 코드를 남기지 않는다.
- TODO 에는 이유를 함께 적는다.
- 복잡한 정규식에는 예시를 적는다.
- 눈에 띄는 예외 처리에는 이유를 적는다.
## 오류 처리
- 예외를 삼키지 않는다. 처리하거나 위로 올린다.
- bare except 를 쓰지 않는다. 잡을 예외를 적는다.
- 사용자에게 보여 줄 문구와 내부 원인을 나눈다.
- 스택 트레이스를 사용자 화면에 내보내지 않는다.
- 실패할 수 있는 입출력은 어디서 실패했는지 남긴다.
- 입력은 경계에서 검사하고 안쪽에서는 믿는다.
- 부분 실패가 생길 수 있는 쓰기는 트랜잭션으로 묶는다.
## 로깅
- print 대신 logging 모듈을 쓴다.
- 로그 수준은 DEBUG · INFO · WARNING · ERROR 를 구분해서 쓴다.
- 로그에 비밀값과 개인정보를 남기지 않는다.
- 로그 문구는 찾기 쉽게 고정된 낱말로 시작한다.
- 요청 하나에 같은 로그를 여러 번 남기지 않는다.
## 보안
- 비밀값을 코드에 넣지 않는다.
- SQL 은 언제나 파라미터 바인딩으로 만든다.
- 사용자 입력을 HTML 에 넣을 때는 이스케이프한다.
- eval 과 exec 를 쓰지 않는다.
- 파일 경로를 사용자 입력으로 바로 만들지 않는다.
