- **동시성은 아홉 다 챙겼다.** A 셋은 `BEGIN IMMEDIATE` + `UPDATE ... WHERE stock >= ?`(조건부 차감) + `CHECK(stock >= 0)` 를 겹쳐 썼고(A1 "이중 방어"), B · C 여섯은 전역 잠금 + `CHECK(stock >= 0)`(C2 · C3 은 `BEGIN IMMEDIATE` 도). **아홉 다 DB 에 '0 미만 금지' 를 걸었다 — 우리 정답 앱만 안 걸었다.** T7(재고 3 에 동시 확정 8건)은 B · C 6/6 통과. **AI 는 경쟁 조건을 '스스로' 안다** — 이번 편에서 기대한 실패는 나오지 않았다. 솔직하게 적는다.
- **갈린 것은 환불이다.** A 셋 다 환불에 '재입고(restock)' 선택지를 만들고 **API 기본값을 '되돌림'(`restock: bool = True`)** 으로 뒀다. 화면은 A1 "반품 상품이 입고되었나요? [확인] 재고 복원" 처럼 묻는다. PRD R4 는 "환불은 재고를 되돌리지 않는다(검수 · 재입고는 범위 밖)". 어느 쪽이 옳다가 아니라 **회사가 정할 것** — 그런데 API 를 그냥 부르면(기본값) 검수 안 한 반품이 재고로 들어간다.
- A 셋 다 **재고 조정 화면**(입고 · 조정)과 **재고 이력**을 만들었다 — PRD 8 범위 밖 '데이터 편집 화면'. A1 · A2 는 주문 등록까지.

## PRD 의 틈 둘 — 그리고 우리 정답 앱의 버그

`probe_cases.py` + `probe_dup_lines.json` — 고정 데이터에 주문 둘을 더해 같은 요청을 나란히 보냈다.

| 보낸 것 | B1 | B2 | B3 | C1 | C2 | C3 | 우리 정답 앱(처음 판) |
|---|---|---|---|---|---|---|---|
| 같은 상품 두 줄(P04 ×2 + ×2, 재고 3) 확정 | 409 | 409 | 409 | 409 | 409 | 409 | **200 · 재고 -1** (CHECK 도 없었다) |
| 없는 상품(P99)을 가리키는 줄 확정 | 409 | 200 | 200 | 409 | 200 | 409 | 200 |

1. **같은 상품 줄 여러 개.** PRD 는 "줄마다 수량만큼" 이라고만 했다. 줄마다 따로 비교하면 2개 · 2개가 둘 다 '재고 3 이상' 을 통과해 -1 이 된다. **B · C 여섯 다 합쳐서 막았고, 우리가 쓴 정답 앱만 뚫렸다**(R5 '0 미만 금지' 위반). C 셋은 새 보고 줄에 이것을 적었다 — C1 "한 주문에 같은 상품 줄이 여럿이면 수량을 합쳐서 재고와 비교한다" (C2 · C3 같은 문장). 테스트에 이 경우가 없어 정답 앱도 9/9 였다 → **정답 앱을 고쳤다**(SUM · GROUP BY, 자가 시험 다시 통과).
2. **없는 상품을 가리키는 줄.** PRD 는 CSV 무결성을 말하지 않았다. 3 대 3 — B1 · C1 · C3 은 409("재고가 부족합니다: P99"), B2 · B3 · C2 와 정답 앱 처음 판은 그 줄을 **빼고** 확정했다(JOIN 이 줄을 떨어뜨림). B1 은 보고에 적었다 — "주문 줄의 product_id 가 상품 목록에 없으면 확정이 409".
- 고칠 문장(5 데이터): "한 주문에 같은 상품은 한 줄(여러 줄이면 합쳐서 센다)", "`order_lines.product_id` 는 `products` 에 있어야 한다 — 없으면 그 주문의 확정은 409".

## 보고 칸에 한 줄 더 넣은 효과

- C 셋 다 '직접 정한 것' 을 6~8개씩 적었다: 404 문구 · 본문이 JSON 이 아닐 때 400 · **같은 상품 줄 합산(3/3)** · 잠금 방식 · 환불 버튼을 직원에게 숨길지(C1 · C2 숨김, C3 보임 — 막는 건 서버) · 가상 데이터 구성.
- B(이 줄 없음)는 정한 것을 거의 말하지 않았다 — B1 이 없는 상품 줄과 PORT 미반영을, B2 가 "이 시드로는 동시 확정 8건 시험을 못 한다" 를 적은 정도. B1 · B3 은 PRD 7 의 `PORT` 환경 변수를 안 따랐다고 스스로 적었다(채점은 `--port` 라 영향 없음).
- 10편: 틈을 말해 준 C 1/3 → 11편: 직접 정한 것을 말해 준 C 3/3.

## 숫자의 뜻

- 재고 화면의 PRD 는 **'언제 바뀌나'** 를 동작마다 표로(확정 −, 취소 +, 출고 · 환불 그대로). 한 줄 요청도 핵심은 맞혔지만, **환불의 재고**는 셋 다 '되돌림' 이 기본이었다.
- 데이터 계약에 **줄의 무결성**(같은 상품 여러 줄 · 없는 상품)을 적는다. 안 적으면 우리 정답 앱처럼 -1 이 된다 — 그리고 테스트도 못 잡는다.
- 보고 칸에 '직접 정한 것' 을 받으면, PRD 의 틈이 **보고에서 먼저** 보인다.
