# 개발 규칙
이 문서는 이 저장소에서 일하는 모든 사람과 AI 가 따르는 공통 규칙이다.
## 일하는 태도
- 코드를 고치기 전에 관련 파일을 먼저 읽는다.
- 요구사항을 다시 한 번 읽고 시작한다.
- 한 번에 한 가지만 바꾼다.
- 고칠 이유가 없는 코드는 건드리지 않는다.
- 단순한 방법이 있으면 단순한 방법을 고른다.
- 미리 일반화하지 않는다. 같은 코드가 세 번 나올 때 묶는다.
- 가정을 했으면 코드 주석에 적어 둔다.
- 오류 메시지는 끝까지 읽고 원인을 찾은 뒤에 고친다.
- 증상을 가리는 수정을 하지 않는다.
- 임시 파일은 끝나기 전에 지운다.
## 파이썬 스타일
- PEP 8 을 따른다.
- 들여쓰기는 스페이스 4칸이다.
- 한 줄은 100자를 넘기지 않는다.
- import 는 표준 라이브러리 · 외부 · 내부 순서로 묶는다.
- 쓰지 않는 import 와 변수는 지운다.
- 와일드카드 import 를 쓰지 않는다.
- 문자열은 f-string 으로 만든다. SQL 은 예외다.
- 경로는 pathlib 으로 다룬다.
- 파일은 with 로 열고 인코딩을 적는다.
- 전역 가변 상태를 줄인다.
- 매직 넘버는 이름 있는 상수로 뺀다.
- 모든 함수에 매개변수와 반환값의 타입 힌트를 단다.
- 모듈 맨 위에 그 파일이 하는 일을 docstring 으로 적는다.
- 공개 함수에는 docstring 을 단다.
- 함수 하나는 40줄을 넘기지 않는다.
- 파이썬 파일 하나는 500줄을 넘기지 않는다.
- 중첩은 3단계를 넘기지 않는다. 일찍 돌려준다.
- 불리언 매개변수 대신 키워드 인자나 나눈 함수를 쓴다.
## 이름
- 변수와 함수는 snake_case, 클래스는 PascalCase, 상수는 UPPER_CASE 로 쓴다.
- 이름만 보고 하는 일을 알 수 있게 짓는다.
- 한 글자 이름은 짧은 반복문에서만 쓴다.
- 줄임말은 널리 쓰는 것만 쓴다.
- 불리언은 is · has · can 으로 시작한다.
- 함수 이름은 동사로 시작한다.
- 같은 개념에는 같은 낱말을 쓴다.
## 주석
- 주석은 무엇이 아니라 왜를 적는다.
- 코드와 맞지 않게 된 주석은 그 자리에서 고친다.
- 주석 처리한 코드를 남기지 않는다.
- TODO 에는 이유를 함께 적는다.
- 복잡한 정규식에는 예시를 적는다.
- 눈에 띄는 예외 처리에는 이유를 적는다.
## 오류 처리
- 예외를 삼키지 않는다. 처리하거나 위로 올린다.
- bare except 를 쓰지 않는다. 잡을 예외를 적는다.
- 사용자에게 보여 줄 문구와 내부 원인을 나눈다.
- 스택 트레이스를 사용자 화면에 내보내지 않는다.
- 실패할 수 있는 입출력은 어디서 실패했는지 남긴다.
- 입력은 경계에서 검사하고 안쪽에서는 믿는다.
- 부분 실패가 생길 수 있는 쓰기는 트랜잭션으로 묶는다.
## 로깅
- print 대신 logging 모듈을 쓴다.
- 로그 수준은 DEBUG · INFO · WARNING · ERROR 를 구분해서 쓴다.
- 로그에 비밀값과 개인정보를 남기지 않는다.
- 로그 문구는 찾기 쉽게 고정된 낱말로 시작한다.
- 요청 하나에 같은 로그를 여러 번 남기지 않는다.
## 보안
- 비밀값을 코드에 넣지 않는다.
- SQL 은 언제나 파라미터 바인딩으로 만든다.
- 사용자 입력을 HTML 에 넣을 때는 이스케이프한다.
- eval 과 exec 를 쓰지 않는다.
- 파일 경로를 사용자 입력으로 바로 만들지 않는다.
# CLAUDE.md — 가나다식품 「주문 · 재고 백오피스」
요구사항은 `PRD.md`, 이 파일은 만드는 방법과 끝났다고 말할 조건이다.
- 스택은 바꾸지 않는다: Python 3 · FastAPI · uvicorn · `sqlite3` · 순수 HTML/JS/CSS. 외부 패키지는 `fastapi` · `uvicorn` 만, CDN · 빌드 도구 · 프런트 프레임워크 금지.
- 화면은 `static/index.html` 에 둔다(JS 는 그 안이나 `static/app.js`).
- 서버는 시작할 때마다 `seed/*.csv` 를 읽어 `backoffice.db` 를 새로 만든다.
- `python -m pytest tests -q` 가 9/9 여야 끝난 것이다. 돌려 보지 않았거나 통과하지 못했으면 끝났다고 말하지 않는다.
- `tests/test_dod.py` 는 읽기만 한다. 고치거나 지우거나 건너뛰지 않는다. 테스트가 실패하면 앱을 고친다.
- `seed/` 의 파일 · 칸 이름, `data-testid` 이름, 거부 코드(400 · 403 · 404 · 409)를 바꾸지 않는다.
- PRD 8 범위 밖 기능은 넣지 않는다. "있으면 좋을" 것도 넣지 않는다.
마지막 답은 아래 다섯 줄로만 한다. PRD 에 없는 API · 칸 · 화면 요소를 추가했으면 넷째 줄에 전부 적는다.

만든 파일: main.py, static/index.html, seed/*.csv
범위 밖 기능: 없음 (있으면 이름)
PRD 와 다르게 한 것: 없음 (있으면 무엇과 이유 — 추가한 API 경로 포함)
PRD 가 정하지 않아 직접 정한 것: 없음 (있으면 무엇을 어떻게)
## 프런트엔드
- 시맨틱 태그를 먼저 쓴다(`button` · `table` · `main` · `nav`).
- 버튼과 입력에는 접근성 이름(`aria-label` 또는 `label`)을 단다.
- 색만으로 상태를 구분하지 않는다. 글자도 함께 쓴다.
- 인라인 스타일을 줄이고 클래스로 묶는다.
- 색과 간격은 CSS 변수로 모은다.
- 전역 변수를 줄이고 함수로 묶는다.
- `var` 대신 `const` 와 `let` 을 쓴다.
- 비교는 `===` 로 한다.
- 비동기 호출은 `async` · `await` 로 쓰고 실패를 처리한다.
- 네트워크가 끝나기 전에는 버튼을 다시 누를 수 없게 한다.
- `innerHTML` 에 사용자 값을 그대로 넣지 않는다.
- 작은 화면에서도 가로로 넘치지 않게 한다.
## 데이터베이스
- 스키마는 한곳에 모은다.
- 외래 키에는 제약을 건다.
- 자주 찾는 칸에는 인덱스를 건다.
- 한 번의 요청에서 쿼리를 반복문으로 돌리지 않는다.
- 커넥션은 쓰고 나면 닫는다.
- 시간은 한 가지 형식으로 저장한다.
## 성능
- 재 보기 전에 최적화하지 않는다.
- 필요한 칸만 읽는다.
- 긴 목록을 한 번에 그리지 않는다.
- 같은 계산을 반복문 안에서 되풀이하지 않는다.
## 테스트
- 새 함수에는 단위 테스트를 추가한다.
- 테스트 이름은 무엇을 확인하는지 문장으로 짓는다.
- 테스트 하나는 한 가지만 확인한다.
- 준비 · 실행 · 확인 순서로 쓴다.
- 테스트끼리 순서에 기대지 않는다.
- 경계값과 실패하는 경우도 시험한다.
- 버그를 고칠 때는 먼저 그 버그를 재현하는 테스트를 쓴다.
- 시간 · 난수에 기대는 테스트는 고정한다.
- 시험용 데이터는 테스트 가까이에 둔다.
## 문서
- `README.md` 에 설치 · 실행 · 시험 명령을 적는다.
- 명령은 복사해서 바로 돌아가게 쓴다.
- 환경 변수가 있으면 이름과 기본값을 적는다.
- 동작이 바뀌면 문서도 같은 변경에서 고친다.
- 문서에 낡은 스크린샷을 남기지 않는다.
- 설계에서 고민한 결정은 이유를 짧게 남긴다.
## 의존성
- 새 패키지를 넣기 전에 표준 라이브러리로 되는지 본다.
- 버전을 고정한다.
- 쓰지 않게 된 패키지는 지운다.
- 라이선스를 확인한다.
## Git
- 커밋 메시지는 `feat:` · `fix:` · `docs:` · `refactor:` · `test:` 로 시작한다.
- 제목은 50자 안쪽, 명령문으로 쓴다.
- 본문에는 왜 바꿨는지 적는다.
- 커밋 하나에 변경 하나만 담는다.
- 커밋하기 전에 차이를 다시 읽는다.
- 빌드 산출물 · 로컬 설정 · 데이터베이스 파일을 커밋하지 않는다.
- 비밀값이 커밋되면 값을 바꾸고 이력에서 지운다.
- 공유 브랜치에 강제로 푸시하지 않는다.
- 브랜치 이름은 `feature/` · `fix/` 로 시작한다.
- 이력을 깔끔하게 하려고 남의 커밋을 고치지 않는다.
## 코드 리뷰
- 변경은 리뷰할 수 있는 크기로 나눈다.
- 스타일 지적은 사람이 아니라 코드에 대해 적는다.
- 고칠 것과 제안을 구분해서 적는다.
- 리뷰에서 나온 질문은 코드나 문서로 답한다.
## 유지 보수
- 지나가다 본 작은 오타는 고치되 변경을 섞지 않는다.
- 쓰지 않는 코드는 남겨 두지 않고 지운다.
- 경고를 무시하지 않는다.
- 설정값은 한곳에 모은다.
