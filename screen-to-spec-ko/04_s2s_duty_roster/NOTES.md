## 실수 · 주의

- 재채점 뒤 results.json 의 `tests_modified` 가 C 에서도 True — 빌더가 고친 게 아니라 **우리가 채점기를 고쳐서** 빌드 때 받은 사본과 달라진 것. C 셋은 테스트를 건드리지 않았다(C2 보고: "테스트는 고치지 않고 앱을 맞춤").

- 채점기 `find_swap` 의 모호함(위). 자가 시험(정답 · 함정 앱)으로는 안 잡혔다 — 함정 앱은 그 경로를 안 지나니까. **AI 빌더가 채점기 검토자 노릇을 했다.** 보고 칸이 없었으면(B) 그냥 지나갔을 것.
- B 가 남긴 서버 때문에 C 의 기본 포트가 막힘 → `run_build.py` 의 `kill_servers` 가 빌드 끝마다 돌지만 **B 의 pytest 가 띄운 uvicorn 은 cwd 가 작업 폴더라 잡혔어야 하는데** PID 14536 은 남았다(wmic 의 CommandLine 에 폴더 이름이 없는 `-m uvicorn main:app` 이라 매칭 실패). → 조건 사이에 `kill_servers.py`(포트 기준)를 돌리도록 run_build 에 추가.

## 숫자의 뜻

- 알고리즘 규칙은 **글로 쓸 수 있다** — R1~R5 다섯 줄. PRD 를 받은 여섯 번 모두 되추적으로 다섯 줄을 다 지켰다. 한 줄 요청은 셋 다 '대체로 공평' 에서 멈췄고, 못 지킬 때 규칙을 **몰래 푸는** 길을 스스로 택했다.
- '못 만들면 422' 한 줄이 "후보가 없으면 연속 금지만 풀어 준다" 를 막는다. 알고리즘 PRD 에서 가장 중요한 줄은 **실패 조건**이다.
