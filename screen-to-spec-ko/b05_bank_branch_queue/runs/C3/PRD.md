# PRD — 두둑은행 넉넉지점 「방문 예약 · 대기 현황판」

> 「이 화면, PRD 로는 이렇게」 2부 5편(금융 지점). 은행 · 지점 · 고객 · 직원은 모두 교육용 가상 데이터(두둑은행은 가상 회사).
> 아래 규칙은 전부 **이 지점의 규칙**이다. 실제 법규 · 금융 규정의 수치가 아니다.
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준).

## 1. 개요

- **배경:** 넉넉지점은 방문 예약 고객과 현장 번호표 고객이 한 줄에 섞여 있다. 예약하고 온 고객이 현장 고객 뒤에 서서 항의하고, 호출해도 안 오는 고객 때문에 창구가 멈추고, 지점 모니터에 고객 이름이 그대로 떠서 옆 사람이 다 읽었다.
- **목적:** 예약 우선 · 보류 · 업무별 창구 규칙을 서버가 지키고, **모두가 보는 대기 화면과 그 응답에는 가린 이름과 번호만** 나간다.
- **성공 기준:** 대기 화면 응답에 이름 전체 · 전화번호 · 계좌번호 · 업무 종류 0건. 다른 창구 고객 상세 열람 0건.

## 2. 사용자

- **고객(누구나) · 창구 직원 · 지점장.** 로그인 없이, 직원 화면 위 **사용자 선택 상자**에서 고른다. API 는 요청자를 본문의 `user` 또는 쿼리의 `viewer`(user_id)로 받는다. **로그인은 8 범위 밖.**
- 고객: 번호표 뽑기 · 예약(API) 과 대기 화면 보기.
- 창구 직원: **자기 창구**의 대기 줄(가린 이름)을 보고 다음 번호를 호출하고, **자기 창구가 호출한 고객**의 상세만 본다.
- 지점장: 현황 숫자만 본다. **고객 상세는 못 본다.** 호출도 못 한다.

### 보여 줄 것 · 숨길 것 (이 편의 핵심 — 화면과 **응답** 모두)

| 어디 | 보여 준다 | 숨긴다 |
|---|---|---|
| 대기 화면 `/board` · `GET /api/board` (누구나) | 번호 · 가린 이름 · 호출 창구 번호 | 이름 전체 · 전화번호 · 계좌번호 · **업무 종류** |
| 번호표 응답 `POST /api/tickets` | ticket_id · 번호 · 상태 | 이름 · 전화번호 · 계좌번호 |
| 창구 대기 줄 `queue` (자기 창구 직원) | ticket_id · 번호 · 가린 이름 · 업무 · 우선 여부 | 이름 전체 · 전화번호 · 계좌번호 |
| 고객 상세 (그 고객을 호출한 창구의 직원) | 이름 전체 · 전화번호 · 계좌 **끝 4자리** · 업무 | 계좌번호 전체 |
| 지점장 현황 | 숫자 · 창구별 호출 번호 | 고객 이름(가린 것도) · 전화번호 · 계좌번호 |

- 계좌번호 전체는 **어떤 응답에도** 나가지 않는다. DB 에만 있다.
- 가리기는 **서버가** 한다. 화면(JS)에서 가리면 응답에는 이름이 그대로 실리므로 안 된다.

## 4. 화면

페이지 둘: `/board`(대기 화면, 누구나) · `/`(직원 · 지점장).

**`/board`**
- 호출 중: `data-testid="serving"` — 안에 번호 · 가린 이름 · 창구 번호. 대기 중: `data-testid="waiting"` — 안에 번호 · 가린 이름. 5초마다 다시 읽어도 되고 안 읽어도 된다(테스트는 열 때 한 번 본다).
- 데이터 출처는 `GET /api/board` 하나.

**`/`**
- **사용자 선택:** `data-testid="user"` (`<select>`, option 의 value 는 user_id, 출처 `GET /api/users`). 처음엔 첫 번째 사용자.
- **창구 직원이면:** 대기 줄 `data-testid="ticket"` + `data-id`(ticket_id)(출처 `queue`) · 호출 버튼 `data-testid="next"` · 호출한 고객 상세 `data-testid="detail-name"` · `detail-phone` · `detail-account`(출처 `GET /api/tickets/{id}`, 호출 직후 자동으로 불러온다) · 완료 버튼 `data-testid="complete"`.
- **지점장이면:** 현황 상자 `data-testid="summary"` (출처 `summary`). 대기 줄 · 호출 · 완료 · 상세가 **없다.**
- **메시지 줄:** `data-testid="message"` — 서버가 거부하면 `detail` 그대로.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 문구를 테스트하는 요소는 그 문구가 **손잡이 요소 안에** 있어야 한다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 3개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`bank.db`)를 **새로** 만든다. 번호표 · 호출 · 상태 변경은 DB 에 쓴다(서버가 도는 동안 유지).

| 파일 | 칸 | 형식과 예시 |
|---|---|---|
| `seed/users.csv` | `user_id, name, role, counter_id` | `t1` · `한창구` · `role` 은 `teller`(창구 직원) 또는 `manager`(지점장) · `counter_id` 는 직원이면 `C1`, 지점장이면 빈칸 |
| `seed/counters.csv` | `counter_id, name, service` | `C1` · `창구 1` · `service` 는 `deposit`(예금) · `loan`(대출) · `fx`(외환) 중 하나. 넉넉지점은 C1 · C2 예금, C3 대출, C4 외환 |
| `seed/tickets.csv` | `ticket_id, number, name, phone, account, service, reserved_at, arrived_at, status, counter_id, called_at` | `K-01` · 정수 `101` · `김민수` · `010-0000-0001` · `110-222-333001` · `deposit` · 예약이 아니면 `reserved_at` 빈칸 · 시각은 `YYYY-MM-DD HH:MM` · `status` 는 아래 다섯 중 하나 · 호출 전이면 `counter_id` · `called_at` 빈칸 |

- **상태:** `reserved`(예약, 아직 안 옴) → `waiting`(대기) → `called`(호출 중) → `done`(완료) 또는 `held`(보류).
- **테이블:** 접두어 `bk_` — `bk_users` · `bk_counters` · `bk_tickets`.
- **가상 데이터:** 직원 4명 · 지점장 1명, 창구 4개, 번호표 8개 이상(예약 · 현장 · 대기 · 완료 섞어서). **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다. 전화번호는 `010-0000-` 으로 시작하는 가짜 번호만.
- **가린 이름 `masked_name`:** 서버가 만든다. 두 글자는 첫 글자 + `*`(이수 → `이*`), 세 글자는 가운데만(김민수 → `김*수`), 네 글자 이상은 첫 글자와 끝 글자만 남긴다(남궁민수 → `남**수`).
- **시각:** 동작 API 는 본문의 `at`(`YYYY-MM-DD HH:MM`)을 '지금' 으로 쓴다. 없으면 서버 시각.
- **API**
  - `GET /api/users` → `[{"user_id","name","role","counter_id"}]`
  - `GET /api/board` → `{"serving":[{"number","masked_name","counter_id"}],"waiting":[{"number","masked_name"}]}` — `called` 와 `waiting` 만(번호 오름차순). `reserved` · `done` · `held` 는 나오지 않는다. 칸은 이것뿐이다.
  - `POST /api/tickets` 본문 `{"name","phone","account","service","reserved_at"(선택),"at"(선택)}` → 201 `{"ticket_id","number","status"}`. `reserved_at` 이 없으면 현장 번호표: `status` `waiting` · `arrived_at` = 지금. 있으면 예약: `status` `reserved`. `number` 는 지금까지의 최댓값 + 1.
  - `POST /api/tickets/{ticket_id}/checkin` 본문 `{"at"}` → 200 `{"ticket_id","number","status":"waiting","priority":true|false}`
  - `GET /api/counters/{counter_id}/queue?viewer=t1` → 부를 순서대로 `[{"ticket_id","number","masked_name","service","priority"}]`
  - `POST /api/counters/{counter_id}/next` 본문 `{"user","at"}` → 200 `{"called":{"ticket_id","number","masked_name","counter_id"} 또는 null,"held":앞 고객의 ticket_id 또는 null}`
  - `POST /api/tickets/{ticket_id}/complete` 본문 `{"user","at"}` → 200 `{"ticket_id","status":"done"}`
  - `GET /api/tickets/{ticket_id}?viewer=t1` → 200 `{"ticket_id","number","name","phone","account_last4","service","status","counter_id"}`
  - `GET /api/manager/summary?viewer=m1` → 200 `{"waiting":{"deposit":n,"loan":n,"fx":n},"held":n,"done":n,"counters":[{"counter_id","service","number"(호출 중 번호 또는 null)}]}`
  - 거부 응답은 모두 `{"detail": "사유"}`.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **예약 우선.** 예약 시각 **앞뒤 10분 안**(10분 포함)에 도착하면 `priority` true. 10:00 예약 → 09:50 도착 우선 · 10:10 도착 우선 · 09:49 도착 일반 · 10:11 도착 일반. 일반이 되면 도착 시각대로 줄을 선다. |
| R2 | **부르는 순서.** 같은 업무 안에서 `priority` true 가 먼저(그 안에서 도착 순), 그다음 일반(도착 순). 도착이 같으면 번호 순. 현장 번호표는 언제나 일반. |
| R3 | **업무별 창구.** 창구는 자기 `service` 의 고객만 부른다. C1 · C2 는 예금 줄 하나를 같이 쓴다. 대출 고객은 C3 만, 외환 고객은 C4 만. 업무는 이 셋뿐이다(서버의 규칙, 아니면 400). |
| R4 | **보류.** 창구에 호출 중인 고객이 있을 때 `next` 를 누르면: 호출 뒤 **3분 미만이면** 409 `호출 뒤 3분이 지나야 다음 번호를 부를 수 있습니다`. **3분이 되면** 앞 고객은 `held`(대기 화면에서 사라짐), 다음 번호를 호출한다. 10:00 호출 → 10:02 `next` 409 · 10:03 `next` 앞 고객 보류. 줄이 비어 있으면 `called` null(앞 고객 보류는 그대로). 보류 고객의 복귀는 8 범위 밖. |
| R5 | **완료.** 호출 중(`called`)인 고객을 `complete` 하면 `done`. 그 뒤 `next` 는 3분을 기다리지 않는다. 자기 창구가 이미 완료 · 보류한 건을 다시 `complete` 하면 409 `호출 중인 고객이 아닙니다`. |
| R6 | **번호표 입력.** `name` 빈칸이면 400 `이름을 확인하세요`. `phone` 이 `01X-XXXX-XXXX` 꼴(`^01\d-\d{3,4}-\d{4}$`)이 아니면 400 `전화번호 형식을 확인하세요`. `account` 빈칸이면 400 `계좌번호를 확인하세요`. `service` 가 셋 중 하나가 아니면 400 `업무 종류를 확인하세요`. |
| R7 | **도착 처리.** `reserved` 상태가 아니면 409 `예약 상태가 아닙니다`(현장 번호표 · 이미 도착한 예약). |
| R8 | **권한 — 누가 누구의 것을.** `queue` · `next` 는 **그 창구의 직원만**: 다른 창구 직원 · 지점장은 403 `자기 창구만 할 수 있습니다`. `complete` · 고객 상세는 **그 고객을 호출한 창구의 직원만**(호출 전 고객은 어느 창구의 고객도 아니다): 그 밖은 403 `자기 창구 고객이 아닙니다`. 지점장도 고객 상세는 403. `summary` 는 지점장만: 그 밖은 403 `지점장만 볼 수 있습니다`. |
| R9 | **입력과 거부 순서.** `user`(또는 `viewer`)가 문자열로 없으면 400 `사용자를 확인하세요`. 거부가 둘 이상이면 **'무엇을 찾아야 알 수 있나'** 순서로 하나만: 본문만 보면 아는 것(400) → 없는 사용자 · 창구 · 번호표(404) → 권한(403) → 상태(409). |

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.**
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것. **`main.py` 안에서 다른 파일을 import 하거나 파일을 열면 프로젝트 루트 기준 절대 경로로**(테스트는 다른 폴더에서 서버를 띄운다).
- '지금' 은 본문의 `at`, 없으면 서버 로컬 시각. 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만. 한글 UI.

## 8. 범위 밖 (Won't)

- 로그인 · 회원가입, 실제 금융 거래 · 계좌 조회 · 대출 심사, 문자 · 알림, 보류 고객 복귀 · 재호출, 예약 변경 · 취소 · 예약 화면(예약은 API 만), 민원 접수, 내부 점검표, 교육 기록, 통계 그래프, **고객 · 직원 · 창구 편집 화면(데이터 편집 화면)**, 다크 모드.
