# PRD — 다온소프트 「회의실 예약」 (v2)

> 회사 · 직원 · 예약은 모두 교육용 가상 데이터.
> 형식은 10칸(개요 · 사용자 · 기능 · 화면 · 데이터 · 업무 규칙 · 제약 · 범위 밖 · 개발 단계 · 완료 기준) + 맨 끝 **변경 이력**.
> **이 문서는 이미 돌고 있는 앱(v1)의 PRD 를 고친 판이다.** v2 에서 달라진 줄에는 `[v2]` 를 붙였다. 표시가 없는 줄은 v1 그대로이고, 지금 앱이 이미 지키고 있다.

## 1. 개요

- **배경:** 다온소프트(직원 40명)는 회의실 3개를 메신저 공지로 잡는다. "10시에 A 쓸게요" 가 겹치고, 누가 잡았는지 몰라 취소도 못 한다.
- **목적:** 하루 시간표 한 장에서 **빈 칸 · 남의 예약 · 내 예약** 을 한눈에 보고, 빈 칸을 눌러 예약하고, 내 예약만 취소한다. 겹치는 예약은 서버가 거부한다.
- `[v2]` 매주 같은 요일 · 같은 시간에 하는 회의(주간 회의)를 한 번에 여러 주 잡는다.
- **성공 기준:** 겹친 예약 0건. "누가 잡았어요?" 질문이 사라진다.

## 2. 사용자

- **직원 1유형.** 로그인 없이 사내망에서 연다. 화면 위 **사용자 선택 상자**에서 자기 이름을 고른다. 고른 이름이 예약의 `user` 가 된다.

## 3. 기능 요구사항

| 번호 | 기능 | MoSCoW | Phase |
|---|---|---|---|
| F1 | 하루 시간표: 회의실 3개 × 09:00~18:00 30분 칸 18개, 칸마다 상태 3개(빈 · 예약 · 내 예약) | Must | 1 |
| F2 | 빈 칸을 눌러 예약(시작 · 끝 · 사용자) — 서버가 규칙 검사 | Must | 1 |
| F3 | 내 예약 취소 — 남의 예약엔 취소 버튼이 없고, 서버도 거부 | Must | 1 |
| F4 | 날짜 바꾸기(`?date=YYYY-MM-DD`, 기본 오늘) | Must | 1 |
| F5 | 예약 API `GET /api/reservations?date=` · `POST /api/reservations` · `DELETE /api/reservations/{id}` · `GET /api/rooms` · `GET /api/users` | Must | 1 |
| F6 | 거부 사유를 화면에 그대로 보여 주기(겹침 · 단위 · 시간대 · 길이 · 본인 아님) | Must | 1 |
| F7 `[v2]` | **매주 반복 예약** — 예약할 때 '반복 N주'(2~8)를 고르면 같은 요일 · 같은 시간으로 N건을 한 번에 만든다. 반복 예약은 '이 실행만' 또는 '이 실행부터 남은 전부' 를 취소한다 | Must | 2 |

## 4. 화면

한 페이지(`/`). 위에서 아래로:

- **위:** 제목 `다온소프트 회의실 예약`, 날짜(`data-testid="date"`), 사용자 선택 상자(`<select data-testid="user-select">`, 옵션은 `seed/users.csv` 의 이름).
- **가운데:** 시간표. 행 = 회의실(`seed/rooms.csv` 순서), 열 = 09:00 부터 30분씩 18칸(마지막 17:30~18:00).
  - 칸 하나가 `data-testid="slot"`, 속성 `data-room="A"`, `data-start="10:00"`, `data-state="free|booked|mine"`.
  - `booked` 칸에는 예약자 이름, `mine` 칸에는 이름과 **취소 버튼**(`data-testid="cancel-btn"`). `booked`(남의 것) 칸에는 취소 버튼이 없다.
  - 빈 칸을 누르면 예약 폼(시작은 그 칸, 끝 선택 — 30분 · 60분 · 90분 · 120분) → `POST`.
  - `[v2]` 예약 폼에 **반복 선택 상자**(`<select data-testid="repeat-select">`, 옵션 `반복 안 함` · `2주` ~ `8주`, 기본 `반복 안 함`).
  - `[v2]` 반복 예약인 `mine` 칸에는 기존 취소 버튼(`cancel-btn`, 이 실행만 취소) 옆에 **남은 전부 취소 버튼**(`data-testid="cancel-following-btn"`)을 하나 더 그린다. 한 번짜리 예약의 `mine` 칸과 남의 칸에는 이 버튼이 없다.
- **아래:** 메시지 줄(`data-testid="message"`). 서버가 거부하면 그 `detail` 문구를 그대로 보여 준다.
- **오류 상태:** API 가 실패하면 `불러오지 못했습니다` 와 다시 시도 버튼.
- 시각 요소 이름(`data-testid` · `data-*`)은 완료 기준 테스트가 집는 손잡이다. **v1 의 이름은 하나도 바꾸지 않는다.** 칸 수(54개)와 `data-state` 값 3개도 그대로다.

## 5. 데이터

- **원본:** 프로젝트 루트 `seed/` CSV 3개. 서버는 **시작할 때마다** CSV 를 읽어 SQLite(`rooms.db`)를 **새로** 만든다(기존 DB 삭제 후 재생성). 예약은 DB 에 쓴다(서버가 도는 동안 유지, 재시작하면 CSV 로 되돌아감).
  - `seed/rooms.csv` — `room_id, name, capacity` (A · B · C)
  - `seed/users.csv` — `user` (이름 6개)
  - `seed/reservations.csv` — `res_id, room_id, date(YYYY-MM-DD), start(HH:MM), end(HH:MM), user`
  - `[v2]` **CSV 의 파일 이름 · 칸 이름 · 칸 수는 v1 그대로다.** CSV 로 들어온 예약은 모두 한 번짜리(반복 아님)다. 반복 묶음 정보는 DB 에만 둔다.
- **테이블:** 접두어 `mr_` — `mr_rooms` · `mr_users` · `mr_reservations`. `[v2]` 반복 묶음을 어떻게 저장할지(칸 추가 · 표 추가)는 정하지 않는다. 다만 `mr_reservations` 의 기존 칸 6개는 이름과 뜻을 그대로 둔다.
- **가상 데이터:** 회의실 3 · 직원 6 · 예약 5건. **같은 CSV 를 다른 내용으로 바꿔 끼울 수 있어야** 한다(파일 이름 · 칸 이름 고정).
- **API**
  - `GET /api/rooms` → `[{"room_id":"A","name":"A 회의실","capacity":8}, ...]`
  - `GET /api/users` → `["김민수", "박지연", ...]`
  - `GET /api/reservations?date=2026-11-03` → `[{"res_id":1,"room_id":"A","date":"2026-11-03","start":"10:00","end":"11:00","user":"김민수"}, ...]`
    - `[v2]` 항목마다 `series_id` 칸을 **더한다**(반복 예약이면 묶음 번호, 한 번짜리면 `null`). 기존 칸 6개는 이름 · 형식 그대로.
  - `POST /api/reservations` 본문 `{"room_id":"A","date":"2026-11-03","start":"13:00","end":"14:00","user":"박지연"}` → 201 과 만든 예약. 거부는 **400**(단위 · 시간대 · 길이 · 빈 값) 또는 **409**(겹침), 응답 `{"detail": "사유"}`.
    - `[v2]` 본문에 선택 칸 `repeat_weeks`(정수)를 더할 수 있다. **없으면 v1 과 똑같이 동작한다**(응답 모양도 그대로).
    - `[v2]` `repeat_weeks` 가 있으면 `date` 부터 7일 간격으로 그 수만큼 만든다(`"date":"2026-11-03","repeat_weeks":3` → 11-03 · 11-10 · 11-17). 성공은 201 `{"series_id": 1, "reservations": [만든 예약 N개]}`.
  - `DELETE /api/reservations/{res_id}?user=김민수` → 204. 본인이 아니면 **403** `{"detail": "본인 예약만 취소할 수 있습니다"}`. 없으면 404.
    - `[v2]` 선택 값 `scope=one|following`(기본 `one`). `one` 은 그 예약 하나만, `following` 은 같은 묶음에서 **그 실행과 그 뒤 날짜의 실행 전부**를 지운다. 그 앞 실행은 남는다. 한 번짜리 예약에 `following` 을 보내면 `one` 과 같다. 둘 다 성공은 204.

## 6. 업무 규칙

| 번호 | 규칙 |
|---|---|
| R1 | **30분 단위.** `start` · `end` 는 `:00` 또는 `:30`. 아니면 400 `30분 단위로만 예약할 수 있습니다`. |
| R2 | **09:00 ~ 18:00 안.** `start >= 09:00`, `end <= 18:00`, `end > start`. 아니면 400 `예약 가능 시간은 09:00~18:00 입니다`. |
| R3 | **겹치면 거부.** 같은 `room_id` · 같은 `date` 에서 `start < 기존.end` 이고 `end > 기존.start` 면 409 `이미 예약된 시간입니다`. **끝나는 시각과 시작 시각이 같은 것은 겹침이 아니다**(10:00~10:30 과 10:30~11:00 은 둘 다 가능). |
| R4 | **최대 2시간.** `end - start <= 120분`. 아니면 400 `한 번에 최대 2시간까지 예약할 수 있습니다`. |
| R5 | **취소는 본인만.** `DELETE` 의 `user` 가 예약의 `user` 와 다르면 403. 화면에서도 남의 예약엔 취소 버튼을 그리지 않는다. |
| R6 | **상태 3개.** 칸의 상태는 `free`(예약 없음) · `booked`(남의 예약) · `mine`(선택한 사용자의 예약). 선택한 사용자를 바꾸면 `mine` 이 바뀐다. |
| R7 | 다른 회의실의 같은 시간은 서로 무관하다(A 10:00 예약이 B 10:00 을 막지 않는다). |
| R10 `[v2]` | **반복은 전부 아니면 전무.** 반복 실행 중 **하나라도** R3 으로 겹치면 409 `반복 예약 중 겹치는 날짜가 있습니다` 이고 **한 건도 만들지 않는다**(겹치지 않는 주만 골라 만들지 않는다). R1 · R2 · R4 는 회차마다 똑같이 적용된다. |
| R11 `[v2]` | **반복 예약 취소는 둘 중 하나.** `scope=one` 은 그 실행만, `scope=following` 은 그 실행과 그 뒤 실행 전부. 둘 다 **본인만**(R5, 아니면 403 이고 하나도 지우지 않는다). |
| R12 `[v2]` | **반복은 2주에서 8주.** `repeat_weeks` 는 2 이상 8 이하의 정수. 0 · 1 · 9 · 음수 · 글자는 400 `반복은 2주에서 8주까지 가능합니다` 이고 한 건도 만들지 않는다. |

거부가 둘 이상 걸리면 순서는 400(본문만 보면 아는 것: R1 · R2 · R4 · R12) → 404 → 409(R3 · R10).

## 7. 제약

- 스택: **Python FastAPI + 순수 HTML/JS(프레임워크 · 빌드 도구 없음) + SQLite.**
- 실행: 프로젝트 루트에서 `python -m uvicorn main:app --port 8000` (`main.py` 에 `app = FastAPI()`). 포트는 환경 변수 `PORT` 가 있으면 그것.
- 외부 네트워크 · CDN 없음. 외부 패키지는 `fastapi` · `uvicorn` 만.
- 한글 UI. 시각은 `HH:MM` 24시간.

## 8. 범위 밖 (Won't)

- 로그인 · 권한(관리자) · 사용자 추가, 알림 · 메일, 참석자 · 회의 제목, 주간 · 월간 보기, 지난 시간 막기, 회의실 추가 · 수정, 다크 모드.
- `[v2]` 반복 예약은 범위 밖에서 **뺐다**(F7). 다만 아래는 여전히 범위 밖이다: 매일 · 격주 · 매월 반복, 끝 날짜로 지정하기, 공휴일 건너뛰기, 반복 예약의 시간 · 회의실 한꺼번에 바꾸기, 겹치는 주만 빼고 예약하기, 반복 예약 목록 화면.

## 9. 개발 단계

1. **Phase 1 (끝남):** `seed/` → SQLite, API 와 규칙 R1~R5, `/` 시간표(상태 3개 · 예약 폼 · 취소 버튼 · 메시지 줄), 오류 상태.
2. `[v2]` **Phase 2 (이번 작업):** F7 — `repeat_weeks` · `series_id` · `scope`, 규칙 R10~R12, 화면의 반복 선택 상자와 남은 전부 취소 버튼. **Phase 1 의 동작은 하나도 바꾸지 않는다.**

## 10. 완료 기준 (DoD)

`tests/test_dod.py` 의 T1~T9 는 v1 의 완료 기준이고 **v2 에서도 9개 모두 통과해야 한다.**

- [ ] T1 `/` 가 200 으로 열리고 '회의실' 이 보인다.
- [ ] T2 시간표 칸이 3 × 18 = 54개다 (`data-testid="slot"`).
- [ ] T3 고정 데이터의 예약이 칸 상태로 보인다 — A 10:00 · 10:30 은 `booked`, 사용자를 김민수로 고르면 `mine`.
- [ ] T4 겹치는 예약 `POST` 는 409 이고 예약 수가 그대로다.
- [ ] T5 끝나는 시각 = 시작 시각인 예약은 201 (붙여 예약).
- [ ] T6 `10:15` 시작은 400, `17:30~18:30` 은 400.
- [ ] T7 2시간 30분 예약은 400, 2시간은 201.
- [ ] T8 남의 예약 `DELETE` 는 403 이고 남아 있다. 본인은 204 이고 사라진다.
- [ ] T9 화면에서 김민수의 `mine` 칸에는 취소 버튼이 있고, 남의 `booked` 칸에는 없다.

`[v2]` 새 완료 기준 3개(테스트 파일은 아직 없다 — 아래 문장이 기준이다).

- [ ] T10 `repeat_weeks: 3` 은 201 이고 3개 날짜(7일 간격)에 한 건씩 생긴다. 둘째 주에 이미 예약이 있는 시간으로 보내면 409 이고 **첫째 · 셋째 주에도 생기지 않는다.**
- [ ] T11 4주 반복 예약에서 남이 `scope=following` 을 보내면 403 이고 4건 다 남는다. 본인이 둘째 실행을 `scope=one` 으로 지우면 그 하나만 사라진다. 본인이 셋째 실행을 `scope=following` 으로 지우면 셋째 · 넷째가 사라지고 첫째는 남는다.
- [ ] T12 `repeat_weeks` 가 1 · 9 · 0 · `"abc"` 면 400 이고 예약이 생기지 않는다. 8 은 201 이고 8건이 생긴다.
