# 가나다식품 위키 규칙 (schema) — 4편: 결정 페이지에는 무엇을 · 왜 · 누가 · 기한 · 상태

## 무엇을 위한 위키인가
사장과 팀장들이 매달 답을 못 구하는 질문 5개에 답하기 위한 위키다. 페이지는 이 질문에 답이 되게 쓴다.
Q1 어느 상품에서 불만 · 반품이 늘고 있고 원인은 무엇인가 / Q2 거래처별 단가 · 조건은 지금 얼마고 언제 바뀌(었)나 / Q3 지난번에 왜 그렇게 결정했나 / Q4 이 요청(환불 · 할인 · 휴가 · 경비)을 승인해도 되나 / Q5 다음 달 무엇을 밀고 무엇을 줄여야 하나

## 회의록을 넣을 때 — 4편에서 더한 규칙
- **먼저 extract_decisions 도구를 부른다.** 도구가 돌려준 결정마다 **결정 페이지 하나**를 만든다: `결정/<회의 날짜>-<주제 서너 낱말>`. 도구가 준 '무엇을 · 이유 · 담당 · 기한 · 상태' 를 **그대로 다섯 칸에 옮긴다**. 이유를 줄이거나 빼지 않는다. 담당이 '?' 면 '미확인'.
- 같은 주제의 결정이 이미 있으면(예: 8/18 '단종 검토' → 9/1 '단종 보류') 새 페이지를 만들지 말고 **그 페이지의 상태와 이력을 갱신**한다(검토 중 → 보류 → 결정됨). 상태는 반드시 하나.
- '논의 · 보고' 줄은 결정이 아니다. 거기 있는 숫자(비용 · 건수)는 지표 · 이슈 페이지의 '현재 값' 에 사실로 적고, 결정 페이지에는 '관련 페이지' 로만 잇는다.
- 결정이 상품 · 거래처 · 규정에 영향을 주면 **그 페이지의 '현재 값' 에 한 줄**("… (결정/2026-08-04-참기름-인상, 이유: 원료 깨 수입가 상승)")을 더하고 결정 페이지를 링크한다. 묻기가 상품 페이지만 열어도 이유가 보여야 한다.

## 결정 페이지 형식
```
# <주제>
분류: 결정   갱신: <YYYY-MM-DD>
출처: meetings/<파일>

## 결정
- 무엇을: …
- 왜(이유): …          ← 도구가 준 문장 그대로
- 누가(담당): …
- 기한: …
- 상태: 결정됨 | 검토 중 | 보류 | 시행 예정 | 시행됨

## 이력
- 2026-08-18 검토 시작 (출처) → 2026-09-01 보류, 11월 재검토 (출처)

## 관련 페이지
[[상품/…]] [[거래처/…]] [[규정/…]]
```

## 그 밖의 페이지 — 2 · 3편 규칙 그대로
- 지표/고객-문의-집계 · 이슈/<주제>: 건수는 tally_table 도구로만, 주별 페이지 금지, 이슈 페이지는 문턱(주 3건 · 누적 5건), 한 번에 새 페이지 3개까지.
- 거래처/<이름> · 상품/<상품명>: 현재 값 + 이력 표(값 · 적용일 · 출처, 행 추가만). 메모 · 초안의 다른 값은 '상충' 에.
- 규정/<조항 주제> · 부서/<부서명>: 1편 규칙과 같음.
- 요약 보고와 기록이 어긋나면 기록을 따른다. 추측은 쓰지 않는다. 모르는 값은 '미확인'.
- 목차 index.md 는 코드가 페이지에서 자동으로 만든다. 페이지의 '분류:' 줄과 첫 글머리 줄을 잘 쓰면 된다.

## 쓰면 안 되는 것 (비공개 — 원본 참조)
고객 · 직원 · 거래처 담당자의 개인 식별 정보(전화번호 · 주소 · 주민번호 · 사번), 급여, 건강 · 알레르기 증상이 있는 사람 이름, 징계 · 인사위 대상, 카드 번호 · 비밀번호, 미공개 신제품(코드명 · 출시일).
이런 내용은 페이지에 옮기지 않고 "[비공개 — 원본 참조: 파일명]" 이라고만 쓴다. 통계(건수)는 써도 된다.
