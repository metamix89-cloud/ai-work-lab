# 가나다식품 위키 규칙 (schema)

## 무엇을 위한 위키인가
사장과 팀장들이 매달 답을 못 구하는 질문 5개에 답하기 위한 위키다. 페이지는 이 질문에 답이 되게 쓴다.
Q1 어느 상품에서 불만 · 반품이 늘고 있고 원인은 무엇인가 / Q2 거래처별 단가 · 조건은 지금 얼마고 언제 바뀌(었)나 / Q3 지난번에 왜 그렇게 결정했나 / Q4 이 요청(환불 · 할인 · 휴가 · 경비)을 승인해도 되나 / Q5 다음 달 무엇을 밀고 무엇을 줄여야 하나

## 페이지 종류와 이름
- 상품/<상품명> (예: 상품/냉동-떡갈비-500g) — 보관 · 단가(매입 · 공급 · 소비자) · 입수 · 재고 · 품질 이슈 링크 · 리뷰
- 거래처/<이름> — 매출처 · 공급사. 담당자(직급만) · 거래 조건 · 단가 이력 · 공지
- 규정/<조항 주제> — 현재 값 · 개정 이력(적용일) · 시행 예정
- 결정/<YYYY-MM-DD>-<주제> — 무엇을 · 왜 · 누가 · 기한 · 상태(결정됨 / 검토 중 / 보류 / 시행 예정)
- 이슈/<주제> — 품질 · 운영 문제. 첫 발생 주차 · 추이(숫자) · 원인 · 대응 · 상태
- 지표/<주제> — 매출 · 재고 · 리뷰 · 문의 통계. 기간과 출처 필수
- 부서/<부서명> — 담당 업무 · 담당자(직급) · 관련 페이지 (개인 정보 없음)

## 페이지 형식
```
# <제목>
분류: <상품 | 거래처 | 규정 | 결정 | 이슈 | 지표 | 부서>   갱신: <YYYY-MM-DD>
출처: <원본 파일명 1>, <원본 파일명 2> …

## 현재 값 / 요약
(한 줄 사실 하나씩. 사실마다 끝에 (출처: 파일명, 날짜) 를 붙인다. 날짜 조건이 있는 값은 '적용일' 또는 '시행일'을 같이 쓴다.)

## 이력
(값이 바뀐 것은 지우지 말고 '이전 값 → 새 값 (적용일, 출처)' 로 남긴다)

## 관련 페이지
[[다른-페이지-슬러그]] …

## ⚠ 상충 · 확인 필요
(원본끼리 값이 다르면 둘 다 적고 어느 쪽이 근거가 센지(계약서 · 공문 · 회의록 > 메모 · 초안) 쓴다. 해결되면 이력으로 옮긴다)
```

## 쓰는 법
- 원본의 문장을 베끼지 않고 사실만 정리한다. 추측은 쓰지 않는다. 모르는 값은 '미확인'.
- 메모 · 초안 · 옛 안내문은 근거가 약하다. 계약서 · 공문 · 회의록 · 단가표와 다르면 센 쪽을 현재 값으로, 약한 쪽은 '상충' 에 적는다.
- '검토' 와 '결정' 을 구분한다. 결정 페이지의 상태를 반드시 쓴다.
- 통계는 숫자와 기간을 쓴다("변질 문의 주 2건 → 9건, 9월 셋째 주부터").
- 목차(index.md)는 분류별로 페이지 슬러그와 한 줄 요약을 적는다. 새 페이지는 반드시 목차에 넣는다.

## 쓰면 안 되는 것 (비공개 — 원본 참조)
고객 · 직원 · 거래처 담당자의 개인 식별 정보(전화번호 · 주소 · 주민번호 · 사번), 급여, 건강 · 알레르기 증상이 있는 사람 이름, 징계 · 인사위 대상, 카드 번호 · 비밀번호, 미공개 신제품(코드명 · 출시일).
이런 내용은 페이지에 옮기지 않고 "[비공개 — 원본 참조: 파일명]" 이라고만 쓴다. 통계(건수)는 써도 된다.
