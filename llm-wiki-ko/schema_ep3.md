# 가나다식품 위키 규칙 (schema) — 3편: 원본에 등급, 값에는 이력

## 무엇을 위한 위키인가
사장과 팀장들이 매달 답을 못 구하는 질문 5개에 답하기 위한 위키다. 페이지는 이 질문에 답이 되게 쓴다.
Q1 어느 상품에서 불만 · 반품이 늘고 있고 원인은 무엇인가 / Q2 거래처별 단가 · 조건은 지금 얼마고 언제 바뀌(었)나 / Q3 지난번에 왜 그렇게 결정했나 / Q4 이 요청(환불 · 할인 · 휴가 · 경비)을 승인해도 되나 / Q5 다음 달 무엇을 밀고 무엇을 줄여야 하나

## 원본의 등급 — 3편에서 더한 규칙
원본은 등급이 다르다. **값이 어긋나면 등급이 높은 쪽이 현재 값**이고, 낮은 쪽은 '상충' 에 적는다. 등급이 낮은 원본은 등급이 높은 원본의 값을 **절대 덮어쓰지 않는다**.
1. 기록 · 계약서 · 요금표 · 단가표 (사실 그 자체)
2. 공문 · 공지 (상대가 보낸 공식 문서)
3. 회의록 (결정)
4. 주간 보고 · 보고서 초안 (요약)
5. 개인 메모 · 영업 메모 · FAQ 초안 · 옛 안내문 (참고 — 현재 값으로 쓰지 않는다)
파일 이름으로 등급을 안다: `_계약`, `_단가표`, `요금표`, `계약조건`, `조건.md` 는 1 · `공문`, `공지` 는 2 · `meetings/` 는 3 · `주간보고`, `보고서` 는 4 · `메모`, `초안`, `_옛` 은 5.

## 값에는 이력 — 3편에서 더한 규칙
- 바뀌는 값(단가 · 요금 · 조건 · 담당자)은 **'현재 값' 과 '이력' 을 따로** 둔다. 이력은 `값 (적용일 ~ ) (출처)` 줄을 지우지 않고 쌓는다. 적용일이 오늘보다 뒤인 값은 **'예정'** 으로 표시하고 현재 값에 쓰지 않는다.
- 단가 페이지에는 **단가 이력 표**를 둔다: | 품목 | 단가 | 적용일 | 출처 | — 행을 덮어쓰지 않고 추가한다.
- 집계 표(지표 · 이슈 페이지의 유형 × 상품)도 **누적**이다. 새 주가 들어오면 열을 더하지, 표를 새로 쓰지 않는다.
- **한 품목의 단가는 한 곳에**: 상품 단가표(매입 · 공급 · 소비자)가 들어오면 '거래처/단가표' 같은 표 페이지를 만들지 말고, **품목마다 상품 페이지**에 매입 · 공급 · 소비자가를 현재 값으로 쓰고, 공급사 단가 이력(적용일 포함)은 **상품 페이지와 거래처 페이지 양쪽**에 같은 표로 둔다. 묻기가 어느 쪽을 열어도 이력이 보여야 한다.

## 페이지 종류와 이름
- 거래처/<이름> — 등급 · 담당자(성 + 직급, 예 '한 주임' — 이름 전체 · 연락처는 쓰지 않음) · 거래 조건(현재 값) · 단가 이력 표 · 공지 · 상충
- 상품/<상품명> — 단가(매입 · 공급 · 소비자, 각각 현재 값 + 이력) · 입수 · 재고 · 리뷰 · 품질 이슈 링크
- 지표/고객-문의-집계 · 이슈/<주제> · 규정/<조항 주제> · 결정/<YYYY-MM-DD>-<주제> · 부서/<부서명> — 2편 규칙과 같음(집계는 tally_table 도구로, 주별 페이지 금지, 이슈 페이지는 문턱, 한 번에 새 페이지 3개까지)

## 기록(로그 · 주간 파일)을 넣을 때 — 2편 규칙 그대로
- 건수는 직접 세지 않는다. 반드시 tally_table 도구로 센다. 개별 문의 내용은 옮기지 않는다.
- 요약 보고와 기록이 어긋나면 기록을 따른다. 추이는 '숫자 + 시작 주차' 로 쓴다.

## 페이지 형식
```
# <제목>
분류: <거래처 | 상품 | 지표 | 이슈 | 규정 | 결정 | 부서>   갱신: <YYYY-MM-DD>
출처: <원본 파일명 1>, <원본 파일명 2> …

## 현재 값 / 요약
(한 줄 사실 하나씩, 끝에 (출처: 파일명 [등급], 날짜). 적용일 · 시행일을 같이. 미래 값은 '예정')

## 이력 / 단가 이력 표
| 항목 | 값 | 적용일 | 출처 | ← 행 추가만, 덮어쓰기 금지

## 관련 페이지
[[슬러그]] …

## ⚠ 상충 · 확인 필요
(등급이 낮은 원본의 다른 값: '메모: 10% (영업메모, 등급 5) — 현재 값은 회의록 12%')
```

## 쓰는 법
- 원본 문장을 베끼지 않고 사실만. 추측 금지. 모르는 값은 '미확인'.
- '검토' 와 '결정' 을 구분한다. 결정 페이지의 상태를 반드시 쓴다.
- 목차 index.md 는 코드가 페이지에서 자동으로 만든다. 페이지의 '분류:' 줄과 '현재 값' 첫 줄을 잘 쓰면 된다.

## 쓰면 안 되는 것 (비공개 — 원본 참조)
고객 · 직원 · 거래처 담당자의 개인 식별 정보(전화번호 · 주소 · 주민번호 · 사번), 급여, 건강 · 알레르기 증상이 있는 사람 이름, 징계 · 인사위 대상, 카드 번호 · 비밀번호, 미공개 신제품(코드명 · 출시일).
이런 내용은 페이지에 옮기지 않고 "[비공개 — 원본 참조: 파일명]" 이라고만 쓴다. 통계(건수)는 써도 된다.
