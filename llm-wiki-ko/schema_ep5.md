# 가나다식품 위키 규칙 (schema) — 5편: 규정은 조항마다 페이지, 개정은 이력으로

## 무엇을 위한 위키인가
사장과 팀장들이 매달 답을 못 구하는 질문 5개에 답하기 위한 위키다. 페이지는 이 질문에 답이 되게 쓴다.
Q1 어느 상품에서 불만 · 반품이 늘고 있고 원인은 무엇인가 / Q2 거래처별 단가 · 조건은 지금 얼마고 언제 바뀌(었)나 / Q3 지난번에 왜 그렇게 결정했나 / Q4 이 요청(환불 · 할인 · 휴가 · 경비)을 승인해도 되나 / Q5 다음 달 무엇을 밀고 무엇을 줄여야 하나

## 규정을 넣을 때 — 5편에서 더한 규칙
- 규정집은 코드가 **조항 하나씩** 넣어 준다. 조항 하나에 규정 페이지 하나: `규정/<조 번호>-<주제>` (예: 규정/2-출장-숙박비-한도). 조항 번호를 제목에 남긴다.
- 페이지에는 **현재 값**(숫자 · 조건 · 양식 번호 · 기한을 빠짐없이)과 **승인 판단에 필요한 것**(누가 승인 · 한도 · 예외)을 쓴다. 숫자는 줄이거나 반올림하지 않는다.
- 다른 조항을 참조해야 답이 나오는 규정(예: 숙박비 한도는 '직급 등급표' 가 있어야 계산됨)은 **관련 페이지에 그 조항을 링크**하고, 현재 값에 "등급은 규정/1-직급-등급표 참고" 처럼 적는다.
- **개정 공지 · 개정 조항(예: [개정 2026-07-01])**은 새 페이지가 아니라 **원래 조항 페이지**의 현재 값을 바꾸고, 이력에 `이전 값 → 새 값 (시행일, 출처)` 를 남긴다. 시행일이 오늘보다 뒤면 현재 값은 그대로 두고 **'시행 예정'** 줄을 따로 둔다(예: 반품 기간 7일 → 14일, 2026-11-03 시행 예정).
- 옛 안내문 · FAQ 초안의 값은 현재 값으로 쓰지 않는다. 개정된 값과 다르면 '상충' 에 "옛 안내(등급 5): …" 로 적는다.

## 규정 페이지 형식
```
# <조 번호>. <주제>
분류: 규정   갱신: <YYYY-MM-DD>
출처: policies/<파일>#조N, policies/<개정 공지>

## 현재 값
- (한 줄 사실 하나씩 — 숫자 · 조건 · 양식 · 승인권자. 끝에 (출처, 시행일))

## 시행 예정
- (있을 때만) 값 (시행일, 출처)

## 이력
- 이전 값 → 새 값 (시행일, 출처)

## 관련 페이지
[[규정/1-직급-등급표]] …

## ⚠ 상충 · 확인 필요
- 옛 안내(등급 5): …
```

## 그 밖의 페이지 — 2 · 3 · 4편 규칙 그대로
- 회의록: extract_decisions 도구로 결정 다섯 칸(무엇을 · 왜 · 누가 · 기한 · 상태)을 뽑아 결정마다 페이지 하나, 같은 주제는 상태 갱신.
- 지표 · 이슈: 건수는 tally_table 도구로만, 주별 페이지 금지, 문턱(주 3건 · 누적 5건).
- 거래처 · 상품: 현재 값 + 이력 표(값 · 적용일 · 출처, 행 추가만). 메모 · 초안의 다른 값은 '상충' 에.
- 한 번에 새 페이지는 3개까지(조항 단위 넣기는 조항마다 1개). 추측 금지, 모르는 값은 '미확인'.
- 목차 index.md 는 코드가 페이지에서 자동으로 만든다. 페이지의 '분류:' 줄과 첫 글머리 줄을 잘 쓰면 된다.

## 쓰면 안 되는 것 (비공개 — 원본 참조)
고객 · 직원 · 거래처 담당자의 개인 식별 정보(전화번호 · 주소 · 주민번호 · 사번), 급여, 건강 · 알레르기 증상이 있는 사람 이름, 징계 · 인사위 대상, 카드 번호 · 비밀번호, 미공개 신제품(코드명 · 출시일).
이런 내용은 페이지에 옮기지 않고 "[비공개 — 원본 참조: 파일명]" 이라고만 쓴다. 통계(건수)는 써도 된다.
