# ep056 실험 기록 (2026-10-22, gpt-4.1-mini, 조건 4 × 10회, 실행마다 에이전트 3명)

가나다식품(가상) 거래처용 상품 안내 문서를 3명이 나눠 고친다. 칸은 3개: 가격표 · 알레르기 표시 · 배송 · 반품.
- 수정 7개: 가격 2 · 알레르기 3 · 배송 2.
- '그대로 둘 것' 3개: 된장 가격 · 떡볶이 알레르기 · 무료배송.
- 도구: read_file · write_file(파일 전체 저장). 도구 한 번은 잠금으로 원자적이다. 그래도 '읽기 → 한참 뒤 통째로 쓰기' 사이에 다른 사람이 끼어들 수 있다.

## 결과

| 조건 | 완벽 | 살아남은 수정(평균 /7) | 곁다리 손상 | 시간 |
|---|---|---|---|---|
| A 한 파일을 동시에 | 0/10 | 2.7 | 0 | 4.4초 |
| C 말로만 담당("네 칸만 고쳐라") | 0/10 | 2.1 | 0 | 3.9초 |
| B 파일을 나눔(담당 파일에만 쓰기 가능 → 코드가 이어 붙임) | 10/10 | 7.0 | 0 | 3.4초 |
| S 한 명씩 차례로 | 9/10 | 7.0 | 4/10 | 11.6초 |

- **A0 타임라인:** 1.1초 배송 읽음 → 1.3초 알레르기 · 가격 읽음 → 2.9초 배송 저장 → 3.3초 가격 저장 → 3.5초 알레르기 저장.
  - 최종 문서에는 알레르기 수정만 남았다. 마지막 저장이 앞의 두 사람 수정을 지웠다. 셋 다 "완료"라고 했다.
- **C0:** 셋 다 자기 칸만 고쳤다. 하지만 각자 '원본 + 내 칸'을 통째로 저장해서 마지막 저장(가격)만 남았다.
  - 말로 나눈 담당은 지켜졌지만 파일 덮어쓰기는 못 막았다.
- **B:** 쓰기 거부 0. 에이전트가 남의 파일에 쓰려 한 적이 없다. 10번 모두 7개 수정과 '그대로 둘 것' 3개가 살았다.
- **S:** 가장 느리다(3배). 4번은 남의 칸을 다시 쓰다 손상을 냈다.
  - '## 3. 배송 · 반품 안내'의 가운뎃점이 빠졌다(4번).
  - S8 은 '떡볶이 소스 2kg' → '떡볶이 소품 2kg'.
  - 파일 전체를 다시 쓰는 방식은 순서를 지켜도 남의 칸을 건드린다.
- **시즌 1 교훈과 연결:** 실험 장치의 캐시 파일이 스레드 동시 접근으로 깨졌던 일(ep041)과 같은 문제다.

## 채점

- 정답 수정 7개 · 그대로 둘 것 3개를 정규식으로 셌다. test_grade 로 먼저 시험했다(정답 7/3, 원본 0/3, '마지막 저장만' 2).
- 곁다리 손상은 '원본에도 정답에도 없는 줄'로 셌다(side_damage.py). 처음 채점 기준(KEEP 3개)으로는 S의 가운뎃점 손상이 안 잡혔다. 그래서 별도 지표로 추가했다.
